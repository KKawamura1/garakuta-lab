# 起きたときに読むもの

**このファイルは、予定で起こされたセッションが最初に読む。**
文脈を持っていない（まっさらな）セッションでも、これだけで動けるように書いてある。

## なぜこの形か（2026-08-22）

作者：「特に深夜など、いつ止まっても制限が消え次第復帰できるようにしといてほしい」

それまでの予約は **`send_later` の一発きり＋このセッションに紐づけ** だった。
- 発火時にトークン上限に当たっていたら、**その1回は消えて二度と再開しない**（`run_once_at` は発火後に自分を無効化する）
- セッションが死んでいたら、紐づけ先が無い

**毎時の Routine（`trig_014bSZYerpiZVPhGoVaeUZmW`）＋このセッションへの紐づけ**に替えた。
1回落ちても**次の1時間後が拾う。**上限が消えた直後の回から自然に復帰する。

**なぜ「発火ごとに新しいセッション」にしなかったか。**一度そう作ったら警告が返った：

> this trigger stores no MCP connectors, so the sessions it fires will run without
> connector (mcp__<server>__*) tools

**新しいセッションは MCP のツールを持たない。** プレイ記録は GitHub Actions 経由で
D1 から引いているので、**その形の起床では新着が読めない。**作った直後に消した。

紐づけの残る弱点：**このセッション自体が復旧不能になったら、発火の行き先が無い。**
上限で落ちるのは復旧するが、セッションの死は復旧しない。
兆候は「コミットも通知も止まる」こと。そのときは作者が一言送れば新しいセッションで再開できる。
**だから状態は文脈ではなくリポジトリに置く**（このファイルがそれ）。

## 起きたら、この順で

### 1. まず向きを合わせる

```bash
git fetch origin && git status --short && TZ=Asia/Tokyo date '+%F %H:%M JST'
```

**ツリーが巻き戻っていることがある**（コンテナ再起動）。その場合は
`git reset --hard origin/claude/repository-inventory-yvut4e` で戻す。押してあるので失われない。

**別のセッションが同時に動いていることがある。** 未コミットの変更が自分の覚えに無いなら、
それは他のセッションのものかもしれない。**消さない。**触らずに、その回は何もせず終わる。

### 2. 夜も書いてよい（2026-08-22、作者の指示で変更）

一度は「23:30〜07:30 JST は何も書かずに終わる」と決めたが、作者に取り消された：

> 「夜間でもガンガン書いていいですよ。LLMの性質上、書いた方があなたの性能も上がるはずです。」

**夜に止めるのは、新しいプレイ記録が増えないからであって、書いてはいけないからではない。**
記録が増えない時間帯は、**作者の手を借りずにできることへ回す**：
測り直し、調律、検査の追加、そして**書くこと**（考えは書くと固まる）。

- **通知だけは夜に飛ばさない。**起こす理由が無い（`docs/OPERATIONS.md` の表）
- コミットも書き物も自由。朝に読めるように、結論を先に書く

### 3. 新しいプレイ記録を取り込む

```
mcp__github__actions_run_trigger: export-playtests.yml / limit=10 / echo_to_log=true
→ actions_list(list_workflow_jobs, run_id) → get_job_logs(job_id, return_content, tail_lines=60)
```

**ログは1行に潰れて返る。**`tail_lines` を増やすと大きすぎて弾かれ、ファイルに落ちる。
落ちたファイルは python で `json.loads('"'+行+'"')` して二重に解いてから読む
（`analysis/` に置いた手順ではなく、これが実際に通る形）。

読むのは `answers_json`。`trialStage:0` が1本目（メモだけ）、`1` が2本目（強制選択）。

### 4. 判定は、事前登録どおりに当てる

`agents/HYPOTHESIS_TESTING.md` の 0.7（判定規則）と 0.9（気づかれない差は結果である）。
**数字を見てから条件を緩めない。** 迷ったところは、迷った跡ごと書く。

### 5. 通知するのは、作者の行動が要るときだけ

`docs/OPERATIONS.md` の表を見る。**途中経過では飛ばさない。**

### 6. 何も無ければ、何も書かずに終わる

新着が無い回は、**コミットも通知もしない。**次の発火が勝手に来る。

## MCP が使えない回に当たったら

`mcp__github__*` が無い状態で起こされることがある（上の警告のとおり）。そのときは：

- **新着は読めない。**読めないことを、読めたふりで埋めない
- リポジトリの中だけでできる作業（調律・検査・書き物）に切り替えるか、何もせず終える
- 作者の手が要るなら通知する。GitHub の画面から `Export D1 playtests` は手で回せる

**恒久策の候補（作者の判断が要る）：** 書き出しを GitHub Actions の定期実行にして、
結果をリポジトリへコミットする。そうすれば MCP なしでも読める。
ただし**このリポジトリは公開で、自由記述の回答がそのまま公開物になる。**
いまも `analysis/ROUND*.md` で引用はしているが、生の記録を丸ごと置くのは別の話なので、
**勝手にやらない。**

## 予約について

- **繰り返しの Routine が常に立っている**ので、`send_later` で取り直す必要は無い
- `.claude/next-wakeup` は stop hook が読む。**繰り返しの Routine の次回時刻を書いておく**
- 一発きりの `send_later` を使うのは、**繰り返しの合間に急いで戻りたいときだけ**
