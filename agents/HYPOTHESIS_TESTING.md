# P は仮説であって、守るべきルールではない

**2026-08-22、作者の指摘を受けて書き直した設計。**

> いまやっていることは、面白いゲームを作ることではなく、面白いゲームを作るための仮説検証をすることです。
> そのために、いまのルールが正しいかもきちんと仮説検証してください。Pは仮説であって、守るべきルールではありません。
> Pが成り立つゲームが面白いか（Precisionを上げるテスト）だけでなく、
> Pが成り立たないゲームがつまらないか（Recallを上げるテスト）も必要でしょう。

## 私が何を間違えていたか

天井（P12-b）が満たせないと分かったとき、私がやったのは
**(a) ゲームを作り直す (b) 閾値を上げてよいか訊く** の二つだった。どちらも「Pは守るもの」という前提に立っている。

正しい反応は **「参照点 RELAY 0.1（作者評価5・企画の記録）が天井を落とした。それは天井仮説への反証である」** だった。
**仮説が反証されたのに、仮説を守ってゲームの側を曲げていた。**

そして、いまのところ**どのPも「必要である」とは一度も示せていない。**
Pを満たすゲームしか作っていないので、当然そうなる。

## 1. いま持っている証拠

| 条件 | 満たした版 → 結果（Precision） | 破った版 → 結果（Recall） | いま言えること |
|---|---|---|---|
| **T1 詰みを作らない** | RELAY 0.1（再5→1）、LAWS（再4,3,3,2） | ARC 0.1（勝ち筋ゼロ24%）→ 再1 | 弱い支持。ただしARCは他も違う |
| **T2 勝てる並びが5〜15%** | RELAY 0.1（再5が最高記録） | **PHASE 0.1（59〜100%）→ 再4,3,3,3** | **反証寄り。**破った版が、通した版（CYCLE 0.2＝再1,1）より高い |
| **T3 並び順が効く** | RELAY / LAWS 全部 | **無し** | **未検証。**破った版を一度も作っていない |
| **T5 外した代償** | RELAY 0.1 | 無し | **未検証** |
| **天井（P12-b）** | **無し**（通した版が一つも無い） | RELAY 0.1（71%）→ 再5、LAWS（26〜44%）→ 再4,3,3,2 | **反証寄り。**天井が近い版が最高評価を出している |
| **GATE v2 全体** | CYCLE 0.2 → **再1,1**「何しても勝てそう」 | — | **反証。**通した版が最低評価 |

**読み方：** 通した版が最低点（CYCLE 0.2）、破った版が高得点（PHASE 0.1）という組が既にある。
**関門は、少なくとも現状の形では、面白さを予測できていない。**

### ただし、この表は結論には使えない

**過去の比較は一つも ceteris paribus でない。** PHASE と RELAY は T2 以外に、法則の有無・UIの予告・敵の数値がすべて違う。
どの差が効いたのかを分離できない。**だから上の表は「仮説」であって「証拠」ではない。**

もう一つ：**絶対評価は遊んだ回数とともに単調に下がる**（RELAY: 5→4→3→3→2→1）。
版をまたいだ絶対値の比較は、順序効果と交絡している。**今までの比較は全部これを踏んでいる。**

## 2. これからの形：対にして出す

### 設計

1. **1ランを3戦に短縮する**（いまは6戦）。所要時間が半分になり、同じ時間で**2ラン＝1対**が回る。
2. 対の2本は、**登録した条件のうち1つだけが違う。** 他は機械で揃える。
3. **順序はランダム。どちらがどちらかは伏せる。**
4. 終わったら**強制選択**：「どちらが面白かったか」「どちらをもう一回やりたいか」＋理由。
   **絶対評価（1〜5）は主要指標に使わない。** 単調減衰と交絡するため。
   対にすれば順序効果は相殺でき、**同じ日の同じ気分の中での比較**になる。

### なぜ強制選択か

絶対評価は「今日は3」としか言えないが、対比較は「AよりB」と言える。
**減衰していく量でも、同時に比べれば差は見える。**

### 破る側も、ちゃんと遊べるものにする

Recallテストの版は「条件を破っただけ」で、**壊れたゲームではない。**
壊れたものがつまらないのは当たり前で、それでは仮説の検証にならない。
破る条件以外はすべて通す。

## 3. 時間の配分

| | やること | なぜそちら側か |
|---|---|---|
| **Claude** | 対の生成（1条件だけ違う組を探す） | 計算。調律機は9倍速くなった |
| **Claude** | **操作チェック**：エージェントに両方を遊ばせ、狙った条件だけが実際に違うことを確認 | **人間に出す前に、操作が効いていることを機械で確かめる** |
| **Claude** | 機構側の変数（探索量・型の転移・決着巡回・並べ替え回数）を測る | エージェントで測れる |
| **作者** | **結果変数だけ**：どちらが面白かったか、どちらをもう一度やりたいか、理由 | **人間にしか出せない量はこれだけ** |

**エージェントは面白さを報告できない。** だから人間の時間は結果変数だけに使い、
それ以外は全部こちらで潰す。作者の1ランあたりの情報量を上げることが、この設計の目的である。

## 4. 最初の3対（優先順）

### 対1：T3「並び順が効く」

**これが企画の出発点そのもの**（「並びはきつめに、部品選択はゆるめに」）なのに、**一度も破って試していない。**

- **A（T3を満たす）**：順序に依存する法則（継電＝連なり、先陣＝その巡回の1番目）
- **B（T3を破る）**：順序に依存しない法則（共鳴＝作動数、均衡＝系統が揃っているか）

**法則の組み替えだけで操作できる**ので、他は完全に揃う。最もきれいな対。

- 仮説が正しいなら：**Aが選ばれる**
- 反証されるなら：**差が出ない**か、Bが選ばれる。そのときは「並び順が効くこと」は面白さの条件ではない

### 対2：T2「勝てる並びが5〜15%」

- **A**：勝てる並び 7%（帯の中）
- **B**：勝てる並び 35%（帯の外・緩い）
- 敵HPだけで操作できる。**PHASE 0.1 の記録は反証寄りなので、ここは本気で怪しい。**

### 対3：天井（P12-b）

- **A**：無傷の到達率が遠い
- **B**：近い
- **継続の条件なので、1対では判定できない可能性が高い**（継続は複数ランに現れる量）。
  面白さの条件（対1・対2）を先に潰してから。

## 5. 何が起きたら仮説を捨てるか（先に書く）

- **対1で差が出ない** → T3 を「面白さの必要条件」から外す。生成条件から削る
- **対2でBが選ばれる** → T2 の帯を捨てる。「正解が少ないこと」は面白さの条件ではなかったことになる
- **対3で差が出ない** → 天井を捨てる。**今日一日を止めていた条件が消える**
- **どの対でも差が出ない** → 面白さは私が測っている軸の上に無い。軸を探すところからやり直す

**差が出なかったことも結果である。** 出るまで対を作り替えるのは、事前登録の趣旨に反する。
