# おかしな機関 / ODD ENGINE 0.1

## 位置づけ

これは通常の「一要因を切り分ける小さな実験」ではない。作者自身が繰り返し遊びたいゲームを、設計者が本気で一度作ってみるための独立作である。既存のECHO、HAUL、法則機関の改修版ではない。

## 私が面白いと思う理由

私がゲームで一番強く面白いと思うのは、強い部品を引いた瞬間よりも、**一度は弱い・変な部品だと思ったものの意味が、別の部品や並びによって反転する瞬間**である。

このゲームでは、次の流れを一つのランの中に作ることへ賭ける。

1. 最初は、4つの寄せ集めをどう動かすか分からない。
2. 区画ごとに「衝撃」「守り」「信号」「熱」という異なる問いが出る。
3. ランダムな部品を見て、いまの機関ならどこへ入れるかを考える。
4. 命令を送ると、部品が左から反応し、予想外の連鎖が起きる。
5. 実行ログを読んで、次の区画では同じ部品を別の順番・命令で使う。
6. 最後に、単なる勝敗ではなく「この機関はこういう経緯でこの形になった」と振り返れる。

これは、既存ログで一度だけ観測された「弱いと思ったレンズを、2枚目と異常核によって再評価し、構成全体を崩して勝った」体験を、特定部品の必須レシピにせず、より小さな共通文法として再現しようとする賭けでもある。

## 維持するもの

- iPhoneでタップ中心
- 1ラン数分〜十数分
- ランダムseedと、同じseedでの再挑戦
- 途中の感情マーカーと任意メモ
- 終了アンケート、D1保存、GitHub Actions export
- 構築が中心で、戦闘中の操作技術を主役にしない

## 大きく変えたもの

- 部品の価値を、単体の強さではなく「命令」「左からの順序」「直前の出力」との関係で決める。
- 抽象的な部品数の目標ではなく、毎区画の異なる問いへ答える。
- 危険メーターだけを押すのではなく、火種と機関という具体的なものを守る。
- 結果を合計値だけでなく、部品ごとの反応列として表示する。

## 面白さへの予想

### 本当に面白くなる場合

- 「この部品を先頭へ置けば、さっきの熱が衝撃になる」と、プレイヤーが直前の結果を次の手へ変換する。
- 最初から最終構成が決まらず、報酬で既存部品の価値が変わる。
- 機関が強くなったとき、数字だけでなく反応の連鎖が長くなり、作者性のある圧倒感が出る。
- 失敗しても、次に試す命令・並び・部品が一つ具体的に残る。

### つまらない場合

- 予測欄を見て一番大きい数値の命令を押すだけになる。
- 部品の説明が多く、ログを読んでも因果が理解できない。
- 並べ替え回数が、考えるためではなく全通りを試すために使われる。
- どの部品を引いても、命令を変えれば同じように通れてしまう。
- 勝利した時点で、次の問いではなく「もう十分」が残る。

## 最初の対話で見たいこと

作者には、点数より次を教えてほしい。

- どの部品の意味が途中で変わったか
- どの区画で、命令を送る前に本気で迷ったか
- 実行ログで「なるほど」と思った連鎖があったか
- そのランの後、同じseedをもう一度やりたいか、新しいseedをやりたいか
- つまらなかった場合、どの時点で判断が消えたか

この文書の役割は、最初から成功を証明することではない。私がなぜこの構造へ賭けたかを明らかにし、作者の「面白い／つまらない」と具体的な出来事を接続することである。
