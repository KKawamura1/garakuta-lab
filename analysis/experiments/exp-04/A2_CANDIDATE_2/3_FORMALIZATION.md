# 診断用の暫定形式化

この文書はR1を変更しない。Gate Cの曖昧さを実証する安価な診断に限り、明記済みの
意味論を実行可能にしたもの。未記載部分の選択を、計算ゲートの正式解釈として主張しない。

## 状態

戦闘状態は少なくとも次を持つ。

- player `hp`, `energy`
- `enemyHp`, 6要素以下の `enemyAttacks`, 現在`turn`
- 3行動それぞれの変異（なし / 反動 / 余波 / 継ぎ火）
- 直前の反動で次の手動ターンだけ禁止される行動
- 次ターン開始時に1回解決する余波
- 一枠だけ保留される継ぎ火の発生元
- 手動行動列とイベントtrace

## 暫定遷移

R1の処理順をそのまま実装した。診断器では、energy消費は行動の入力コストであり倍率対象外、
倍率は発電量・攻撃量・防御量へ適用し、正の値を `Math.round` で整数化する。余波は解決済みの
手動効果量の50%を予約し、入力コストを再消費せず、新しい変異を発火させない。

継ぎ火保留中に異なる手動行動を選ぶと、その行動の効果へ1.5倍を適用して保留を消費する。
同じ行動なら保留を維持する。反動禁止は直後の手動ターンだけ有効。

今回の判定分岐証人は「防御+余波」だけを使う。反動・継ぎ火の重複や倍率合成順には依存しない。

## Gate Cの二解釈

全合法手動列（最大6ターン）を列挙し、勝利終端だけを比較する。

- `turns-first`: ターン数最小 → 終了HP最大 → 終了energy最大
- `hp-first`: 終了HP最大 → ターン数最小 → 終了energy最大

診断コードは、取得前後の最適手動列集合に共通列がなければ「変化」とする保守的定義を使う。
ただし代表証拠では各集合が一要素のため、集合比較規則を変えても目的関数による分岐は残る。

## 独立性

- `gate-c-ambiguity.mjs`: 汎用の `graft-core.mjs` で小規模範囲を列挙
- `witness-oracle.mjs`: 定数と遷移を別記した証人専用列挙。coreをimportしない

双方が、最短優先では不変、残HP優先では変化、という同じ結果を返す。
