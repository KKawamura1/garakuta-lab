# 実装前の反証レビュー

## 結論

高価な探索へ進めない。Gate C の「最適行動列が変わる」は、戦闘の最適化目的と
同率解の扱いを定めていない。これはHOWではなくGateの真偽を変える判定定義である。

## 先に確認した問い

| 観点 | 確認結果 |
|---|---|
| 変異が対象に関係なく固定装着される構造か | Gate Eが意図する反証だが、Gate C停止後のseed探索は未実行 |
| 単なる常時倍率で行動順が変わらないか | Gate Cが見るが、「最適」の目的関数不足で判定不能 |
| 自動発動・禁止・継ぎ火の順序 | R1の明記分は実装可能。9装着fixtureと開始時余波勝利を暫定実装で検査 |
| Gateが恒真・恒偽か | Gate Cは少なくとも目的関数ごとには恒真・恒偽でない。ただし目的関数選択で同一例の真偽が変わる |
| 未知の将来情報が必要か | 今回のGate C証人は単一の次戦だけで成立し、将来情報に依存しない |

## 問題となる記述

R1 Gate C:

> 各取得時、少なくとも一方の提示変異について、取得前と取得後で次戦の最適行動列が変わる。

定義されていない項目は次の二つ。

1. 勝利方策間で何を最適化するか（撃破ターン、戦闘終了HP、energy、次戦への状態など）
2. 同率最適列が複数あるとき、集合が一部変わればよいか、共通列がなくなる必要があるか

HPは戦闘間で持ち越すため、最短撃破と残HP最大化のどちらもゲーム意味上合理的である。

## 判定が変わる具体例

- 開始: player HP 8、energy 3
- 敵: HP 8、攻撃列 `[2, 8, 2, 8, 2, 8]`
- 取得: 防御へ余波を装着
- 最大6ターン

| 解釈 | 取得前の一意な最適列 | 取得後の一意な最適列 | Gate C |
|---|---|---|---|
| 最短撃破→残HP→energy | 攻撃→攻撃（2T、HP6） | 攻撃→攻撃（2T、HP6） | FAIL |
| 残HP→最短撃破→energy | 攻撃→攻撃（HP6） | 防御→防御→発電→防御→攻撃→攻撃（HP7） | PASS |

どちらも一意な最適列なので、この証人の分岐は同率解のタイブレークに依存しない。
`witness-oracle.mjs` は `graft-core.mjs` をimportせず、同じ値を独立列挙する。

## 最小限必要な意思決定

探索再開前に、少なくとも次をR1へ追記する必要がある。

1. 「最適」を比較する完全な優先順位（例: 終了HP、ターン数、energyの辞書順）
2. 取得前後の変化を、最適列集合についてどう判定するか
   - 集合が非同一なら変化
   - 共通する最適列がなければ変化
   - 事前固定した一意タイブレーク列が異なれば変化

この決定なしに候補生成規則を固定すると、結果を見た後で目的関数を選べてしまう。
