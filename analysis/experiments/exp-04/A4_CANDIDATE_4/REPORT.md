# EXP-04 Candidate 4 — 反証レビュー結果

## 1. 結論

計算ゲートは **判定不能（妥当な事前停止）**。高価な評価器実装・候補探索は開始していない。

R1は「HPは戦闘間で持ち越す」とだけ規定し、energyおよび戦闘内の一時状態を戦闘間で持ち越すか初期化するかを規定していない。この選択はGate B〜Fの到達可能性・勝利方策・最適列・完走経路を変えるため、探索HOWではなくゲーム意味論である。候補側で推測するとR2 §4違反になる。

## 2. 実装前の反証レビュー

### 2.1 判定を変える未定義点（停止理由）

問題となるR1の記述：

- 基本行動は「発電：energyを2得る」「攻撃／防御：energyを1使う」
- 「HPは戦闘間で持ち越す」
- ラン構成は4戦

energyの戦闘間処理は記述されていない。少なくとも次の二解釈が自然に成立する。

1. **保持**：戦闘終了時のenergyを次戦へ持ち越す。HPだけでなくプレイヤー状態を連続させる。
2. **リセット**：各戦energy=0で開始する。「HPは持ち越す」と明記されたことから、HPだけを例外的に保持する。

`preflight.mjs` は HP=7、敵HP=5、敵初撃7という最小境界を列挙する。開始energy=1なら攻撃で即勝利、energy=0なら発電中に死亡する。実行結果は `carry_energy_1=WIN`, `reset_energy_0=LOSS` である。

この差は次を反転し得る。

- Gate B: 次戦の勝利方策の存在
- Gate C: 取得前後の最適行動列
- Gate D: 無制限最適方策および固定方策の4戦完走
- Gate E: 到達可能な文脈と有用な装着先
- Gate F: 各提示候補後の完走可能な継続経路

したがって同じ敵seed・報酬seedでも、保持ならPASS、リセットならFAILになり得る。

### 2.2 併せて固定が必要な同種の境界

energyの決定と同時に、戦闘終了時に残る `反動の使用不能`、`余波の予約`、`継ぎ火の保留` を次戦へ持ち越すかも明記が必要である。特に余波攻撃の持越しは次戦ターン開始時勝利を作り、Gate B/Fを直接変える。

### 2.3 その他の形式化上の裁量

以下は停止原因ではないが、意味論決定後に評価器のHOWとして事前固定する必要がある。

- Gate Cの「最適」は、勝利可否の後に残HP、ターン数等のどれを目的関数・tie-breakとするか
- Gate Dの5方策の完全な決定規則、および報酬・装着選択は最適化を許すか
- Gate Eの「有用」を、次戦勝利、完走可能性、最適値改善、実使用のどれで判定するか
- 「最小seed」の順序と敵候補生成規則

これらはコード内で事前登録できる余地があるが、戦闘間状態の保持／初期化はプレイヤーが遊ぶ規則そのものなので候補側では決めない。

## 3. 必要な最小意思決定

次の1点をR1へ追加すれば再開できる。

> 各戦開始時、energy、反動の使用不能、余波の予約、継ぎ火の保留を、それぞれ前戦から保持するか、所定値へ初期化するか。

推奨は、**HPのみ保持し、各戦開始時energy=0、一時状態はすべて空へ初期化**。戦闘単位の予告と6ターン上限を独立に評価でき、前戦最終手が見えない将来罠になるのを避ける。ただしこれは仕様提案であり、本候補の判定には採用していない。
