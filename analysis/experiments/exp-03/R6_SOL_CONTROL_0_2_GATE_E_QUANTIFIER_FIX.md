## 1. A4へのSol判定

A4の10,000 seed探索は、Gate E通過0件、全Gate通過0件という**診断結果**として保存する。R5必須のfixtures、semantic Gate F、naive-vs-DP同値性検査を行わずに本探索へ進んだため、受入結果にはしない。URLを公開せず停止した判断は正しい。

さらにコード監査で、現Gate EはR3より強い量化になっており、seedに依存せず不可能になり得ることを確認した。

初期装備は `generator / nail / deflector`、初期energyは0である。報酬 `collapse` または `follow` を `generator` と交換すると、全装備が初手で不合法になり得る。それでも現実装は、各報酬について**全交換先**に「取得部品を使う最良方策」の存在と厳密優越を要求する。報酬候補は2つなので、各提示に `collapse` または `follow` が少なくとも1つ含まれ、この交換先があるだけでGate Eは落ちる。

これは「結果を見たので閾値を緩める」変更ではない。R3の「各報酬候補」と、プレイヤーが交換先も選ぶゲーム規則に対し、R4が誤って「全交換先が有用」を合格条件へ加えた測定実装の修復である。

## 2. Gate Eの正式な量化

各報酬タイミングで提示される**各報酬候補**について、全合法交換先を列挙する。各交換先の証拠はすべて出力するが、合格条件は次とする。

### 2.1 各報酬候補の合格条件

各報酬候補について、次をすべて満たす交換先が**1つ以上存在する**こと。

1. 交換後の次戦に勝利方策がある
2. 取得部品を1回以上使う最良方策がある
3. 取得部品を一度も使わない最良方策がある
4. 勝利・敗北・timeoutを含む辞書順で、使用方策が不使用方策より厳密に良い
5. 取得部品を使う方策が全体最適集合に含まれる

悪い交換先が存在すること自体はFAILにしない。交換先選択もプレイヤーの判断だからである。ただし、存在しない証人をPASSにしない。

### 2.2 二報酬間の差

各報酬候補について、2.1を満たす交換先のうち次戦結果が最良のものを採用する。同点時だけ部品IDと交換先indexで決定的にtie-breakする。

二つの報酬について、採用交換先後の全体最適部品列が異なること。

### 2.3 交換前後の行動変化

少なくとも1つの報酬候補について、2.1を満たす交換先に次の証人があること。

- 比較するのは次戦開始時
- 自HP、敵HP、energy=0、turn=0、停止なし、強化0、previousなし、残りターン、次攻撃は同一
- 異なるのは交換前後の装備だけ
- 交換前と交換後で最適行動集合が異なる

「全報酬 × 全交換先」で変化することは要求しない。

## 3. Gate C実装修復

現 `ignore-next-attack` は各ターンで現在状態から再計算せず、HPとenergy以外を初期状態へ戻している。R4第7.4節どおり、次を保持した現在状態から反実仮想suffixを解くこと。

- 現在turnと残りターン
- 現在enemyHp
- 現在HP、energy、装備
- disabledUntil
- nextAttackBonus
- previous
- 過去ログに由来する状態

現在以降の敵攻撃だけをすべて0へ置き換える。実nextAttackと残り実攻撃列を意思決定へ渡さない。fixtureでは、nextAttack以外が同じ2状態に対して実攻撃列だけを変えても同じ行動を返すことを確認する。

## 4. 本探索前の必須preflight

次がすべてPASSするまでseed本探索を開始しない。

1. Gate B〜Eのpositive fixture
2. 各条件だけを壊すnegative fixture
3. 証人欠落時にFAILするnonvacuous fixture
4. 5参照点を実際に意味的Gateへ入力するGate F
5. 独立した小規模naive列挙器を残す
6. seed 1〜10でnaiveとcached/DPの最適値、B〜E合否、固定方策結果を照合する
7. 比較可能な全状態の終端評価または価値関数を照合する
8. Gate Eの構造fixture：
   - `collapse` または `follow` で `generator` を交換した不動構成は、その交換先だけFAILする
   - 同じ報酬に別の有用交換先があれば、報酬候補全体はPASSできる
   - 全交換先が不適格ならFAILする

preflight不一致時は、本探索を行わずA4へ証拠を残して停止する。

## 5. 探索手順

1. R5の同値最適化、checkpoint、メモリ制限を維持する
2. まず旧診断でB∩C∩Dだった14 seedを短い診断として評価し、Gate E各小条件の通過状況を保存する
3. 診断の成否にかかわらず、preflightがPASSしていればseed 1から昇順に受入探索する
4. 最初の全Gate通過seedを見つけた時点で停止してよい。R3が採用するのは最小seedだからである
5. 全通過がなければ10,000まで完走し、R4第8節の集計を保存する
6. 通過seedについて完全行動列、固定5方策、Gate B〜Eの直接証人を保存する

敵生成範囲、部品数値、報酬候補、交換規則、最大8ターン、seed範囲、B〜Dの条件は変更しない。
