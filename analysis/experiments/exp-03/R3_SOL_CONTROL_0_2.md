## 1. CONTROL 0.1の判定

**CONTROL 0.1という具体版は棄却する。ただし「戦闘中の短い選択」仮説は未検証とする。**

人間結果は楽しさ1、再プレイ1であり、具体版としては明確に失敗した。

しかし採用seedの敵攻撃は4 / 0 / 1で、第2戦は攻撃0だった。機械上の最適列も、発電・蓄積をまとめてから攻撃を連打する固定手順だった。R1のGateは「2種類以上使う」「ランダム方策より難しい」を見たが、仮説の中心である次を見ていなかった。

- 敵予告によって最適行動が変わる
- 防御が最適になる
- 発電と攻撃を途中で切り替え直す
- 報酬取得物が実際の最適行動に必要になる

よって、人間へ出した問題が仮説を実装していなかった。CONTROL 0.2は数値改善ではなく、測定手段の修復である。

## 2. 問い

敵の次攻撃に応じて、発電・攻撃・防御を途中で切り替える必要が実際にある戦闘なら、戦闘中の選択は固定手順ではなく意味のある判断になるか。

## 5. 直接ゲート

### Gate A：計算とログ一致

CONTROL 0.1の計算検査に加えて、各ターンについて次を照合する。

- 選択前の自HP、敵HP、エネルギー、停止、強化、次攻撃
- 選択部品
- 部品効果
- 遮蔽
- 実際の敵攻撃
- 選択後の自HP、敵HP、エネルギー、停止、強化
- 勝敗とターン終了

画面表示、内部計算、保存イベントの3者が一致する。

### Gate B：予告感応性

各採用戦闘に、少なくとも1つ、次の反実仮想状態を作る。

- 自HP、敵HP、エネルギー、装備、停止、強化、残りターンは同一
- 次攻撃だけ0と7以上に変える
- 最適行動集合が異なる

偏向板を装備している戦闘では、少なくとも1状態で：

- 次攻撃7以上では偏向板が唯一の最適行動
- 次攻撃0では偏向板が最適行動ではない

「最適」は、まず勝利、次に終了HP、次に少ないターンの辞書順で判定する。

### Gate C：固定マクロ拒否

次の方策を明示的に実行する。

1. 発電・蓄積系だけを可能な限り使い、その後は攻撃系だけを使う
2. 発電と釘打ち砲を交互に使う
3. 次攻撃に関係なく、同じ状態なら同じ部品を選ぶ
4. 偏向板を一度も使わない
5. 合法な最大ダメージ部品を常に使う

いずれの方策も、全3戦を突破できず、かつ最適方策と同じ最終HPを得られないこと。

少なくとも1戦の最適方策は、行動カテゴリとして、

> 蓄積系 → 攻撃または防御 → 蓄積系

の再訪を含む。最初に全部溜めて後半に全部攻撃する列は不合格。

### Gate D：防御と代償

- 第1戦では、最大終了HPを得る全勝利方策が偏向板を1回以上使う
- 一方、偏向板を使いすぎるとターン切れまたは終了HP悪化になる合法列がある
- 高攻撃をすべて防ぐ方策と、一部を受けて早く倒す方策の両方が勝てる
- 両方の終了HPまたは決着ターンが異なる

これにより「防御一択」ではなく、どの攻撃を受け入れるかを作る。

### Gate E：報酬の行動変化

各報酬候補について：

- どちらを選んでも次戦に勝利方策がある
- 取得部品を実際に1回以上使う最適方策がある
- 取得部品を一度も使わない最良方策より、勝敗・終了HP・ターンの辞書順で厳密に良い
- 二つの報酬後で最適行動列の部品列が異なる
- 交換前と交換後で、少なくとも1つの同型状態における最適行動が変わる

### Gate F：参照点

上記ゲートへ先に次をかけ、すべて落ちることを確認する。

- 攻撃が全ターン0
- 攻撃が全ターン1
- 発電後に攻撃連打だけで最適になる敵
- 防御だけしていれば負けない敵
- どちらの報酬でも取得部品を使わない方が最適な局面

参照点が1つでも通ったら、本番seed探索を行わない。

## 9. Luna試用の合否

これはゲームの面白さとは別に判定する。以下のいずれかが起きたら、次回から実装担当をTerraへ置き換える。

- 必須検査を未実施のままURLを渡す
- 無断で仕様・閾値を変更する
- 標準UI・ログを落とす
- 結果票から作者原文または主要行動を落とす
- 合格主張と証拠が矛盾する
- 公開後に作者が公開条件の不足を2件以上発見する

正しく停止した場合や、正しい実験が面白さ1だった場合はLunaの工程失敗に数えない。
