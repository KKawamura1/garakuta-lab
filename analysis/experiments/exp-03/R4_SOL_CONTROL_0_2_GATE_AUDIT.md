## 6. Gate修復要件

### Gate A

今回は計算と計算内イベントの一致だけを `A-calc` として検査する。画面・内部計算・永続保存イベントの完全Gate Aは未実施と明記し、PASSへ繰り上げない。

### Gate B

各戦闘について証人を出力する。

- nextAttack以外が同一の状態全文
- nextAttack=0とnextAttack>=7の全合法行動と評価
- 両方の最適行動集合
- 最適集合が異なる証拠
- 偏向板装備時、7以上で偏向板が唯一最適、0で偏向板が非最適である証拠

### Gate C

R3の5固定方策すべてを、HP持越しと戦闘間報酬を含む3戦キャンペーンとして実行する。報酬規則とnextAttack無視方策は第7節に従う。

各方策について次を出力する。

- 報酬候補、取得報酬、交換元
- 3戦の完全行動列
- HP推移
- 各戦の勝敗・終了HP・ターン
- 合計ターン
- 無制限最適方策との差
- 蓄積→攻撃または防御→蓄積の再訪証拠

### Gate D

第1戦について直接検査し、証人列を出力する。

- 勝利方策の最大終了HP
- そのHPを得る全方策が偏向板を使う
- 偏向板過剰使用によりtimeout、敗北、または終了HP悪化になる合法列
- 7以上の攻撃をすべて偏向板で受ける勝利列
- 7以上の攻撃を少なくとも一度防がず、実ダメージを受けて早く倒す勝利列
- 両者の終了HPと決着ターン

### Gate E

各報酬候補と各合法交換先について次を検査する。

- 取得部品を使う最良方策
- 取得部品を一度も使わない最良方策
- 勝利・敗北・timeoutを含む辞書順比較
- 取得部品を使う方策が全体最適集合に含まれる
- 二報酬間で最適部品列が異なる
- 交換前後の同型状態と双方の最適行動集合
- 報酬を使わないと勝てない場合も「使用方策が厳密に優れる」と判定する

### Gate F

5つの悪い参照点を意味的なGateへ実入力し、どのGateのどの条件で落ちたかを出力する。生成範囲外という理由だけで棄却しない。

### fixtures

各条件について次を用意する。

- 条件を満たすpositive fixture
- その条件だけを壊すnegative fixture
- negativeが実際にFAILする検査
- 証人が存在しない場合にPASSできないnonvacuous検査

## 7. Gate C未定義動作へのSol判断

### 7.1 固定方策の報酬選択

A4の選択肢1を採用する。

各固定戦闘方策について、実際に提示される報酬候補と合法な交換先をすべて列挙し、その固定方策にとって3戦キャンペーン結果が最良になる経路を採用する。

固定するのは戦闘内の行動方策だけである。報酬選択は各固定方策へ最も有利なbest-caseとし、報酬選択の下手さを理由に固定マクロを棄却しない。

### 7.2 キャンペーン評価順

報酬経路および無制限最適方策の比較には次の辞書順を使う。

1. 撃破した戦闘数が多い
2. 同数なら、キャンペーン停止時点の自HPが高い
3. 同じなら、そこまでの合計ターン数が少ない
4. 完全同点の場合だけ、部品IDと交換先indexの辞書順で決定的にtie-breakする

4は再現性だけに使い、ゲーム上の優劣へ含めない。

無制限最適方策も、戦闘内行動、報酬候補、交換先を同じ評価順で最適化する。

### 7.3 Gate C合格条件

5固定方策それぞれについて、最も有利な報酬・交換経路を与えても次の両方を満たすこと。

- 3戦すべてを突破できない
- 無制限最適キャンペーンよりキャンペーン評価が厳密に悪い

1つでも3戦突破したらGate CはFAILとする。

### 7.4 nextAttack無視方策

seedごとに最適化した状態→行動表は使用しない。ターン番号から攻撃列を暗記できるためである。

各実ターンで次の手順により決定する。

1. 自HP、敵HP、energy、装備、停止、強化、残りターンは実状態を使う
2. 現在以降の敵攻撃列をすべて0にした反実仮想戦闘を作る
3. 反実仮想戦闘を「勝利、終了HP、少ないターン」の辞書順で最適化する
4. 最適列の先頭行動を実戦で選ぶ
5. 実際の敵攻撃は本来の攻撃列で解決する
6. 次ターンに実状態から再計算する

最適行動が複数なら次の固定順でtie-breakする。

`generator, nail, collapse, deflector, capacitor, follow`

この方策の意思決定へ実nextAttackまたは残りの実攻撃列を渡さない。過去の攻撃で変化した現在HPの参照は許可する。

fixtureでは、実攻撃列だけを変えても、nextAttackを除く入力状態が同一なら同じ行動を返すことを確認する。
