## 2. R8 の採用仕様と食い違うところ

**黙って片方へ寄せていない。両方の式をコードに残し、Stage 定義が `ladderMode` で
どちらを名乗るかを宣言する。**

### 2.1 有効パック数

| | 式 | Stage 0〜3 |
|---|---|---|
| R8 §4.2 | `1 + ceil(sequence / 2)` | 1, 2, 2, 3 |
| R9 §3（採用） | `sequence + 1` | 1, 2, 3, 4 |

`activePackCountForSequence(sequence, mode)` が両方を持つ。Stage 4 以降を
R8 の回転（`rotation`）へ戻す余地を残してある。

**影響**: Stage 3 の有効パックが3から4へ増える。R6 §14 の「一遠征で見える
局所ルール量を増やしすぎない」に対しては、core / full の二段で相殺した
（Stage 3 の新 pack は入口7技能だけ）。

### 2.2 過去パックの扱い

R8 §4.3 は「過去パックは単純累積させない」と書いている。R9 §3.1 は
チュートリアル中の累積を第一候補にしている。**初期4 Stage だけ累積を採った。**
理由は R9 §3.1 が挙げた4点（前の技能がまだ使える／新しい人物が古い pack を
別目的で使う／新 pack は以前の価値を一つだけ変える／全部理解しなくても進める）。

`auditCampaignManifestLadder` は `ladderMode === "tutorial"` の Stage に対して
**逆の検査**をする（前 Stage の pack と仲間が消えていないこと）。

### 2.3 Stage 3 の pack

R8 §5.4 は Stage 3 を B（連撃と刻印）にしていた。R9 §3 は
「Stage 3 は E＋W＋T＋C を第一候補」とし、§11 で未決定と書いている。
**C（手当てと余剰）を採った。** 理由は R9 §9.4「回復を遅くしすぎるリスク」——
HP 持ち越しがある以上、回復の意味を Stage 3 までに見せる必要がある。

**影響**: `pack_barrage` は Campaign Stage 0〜3 から外れ、Free / Endless から
だけ引ける。技能は残っているので、Stage 4 の候補として使える。

### 2.4 編成の自由度

R8 は「8人から5人を選ぶ」を前提にしていた。R9 §2.1 の加入順を実装すると、
初回の Stage 0〜3 では**誰が来るかを content が決める**。R9 §8 に従い、
一度クリアした Stage を遊び直すときだけ5人・自由編成に戻す。

## 3. 序盤の敗北をどう作ったか

R9 §2.1 は「最初の戦闘で敗北し、時間が巻き戻る。戦闘予測を見ながら編成を変え、
予測どおりに勝利する」と書いている。

**演出で敗北を差し込んでいない。** 決定的 engine を実際に走らせている。

- 敵: `gray_marksman`（後列を狙う）＋ `gray_guard`（前列を狙い、最初に防壁）
- 既定配置: レオン front_left / ユウリ front_right → **8 round で決着せず敗北**
- 一手変える: どちらかを後列へ下げる → **7 round で勝利**

`ecology/story.test.mjs` が、既定配置で本当に負けること、3通りの修正で本当に
勝つことを、毎回シミュレーションして確かめている。**この一戦は遠征に数えない**
（活動資金も持ち越しHPも動かさない）。

問いは一つに絞ってある: 「後列を狙う敵がいるとき、前列に固まると二人とも同じ圧を受ける」。

## 4. 新しい content

### 4.1 導入 pack の接続面（R9 §4.1, §9.2）

| ID | pack | 読む出来事 | 渡す先 |
|---|---|---|---|
| `whetted_by_pain` 痛みで研ぐ | edge | 被弾 | 自分の集中（守り役が刃の pack へ入る口） |
| `first_blood` 先手の一閃 | edge | 戦闘開始 | 自分の集中 |
| `shield_handoff` 受けの受け渡し | wall | 受け止め | 最も傷ついた味方の防壁 |
| `patient_step` 溜めの次手 | tempo | 準備完了 | 自分の行動権（RP を払う） |
| `held_breath` 余りを溜める | tempo | 余った行動権 | 自分の集中 |
| `shield_the_wounded` 傷へ盾を | care | （主行動） | 最も傷ついた味方の防壁 |
| `steady_hands` 慣れた手つき | care | 回復 | 自分の集中 |

`shield_the_wounded` は **HP を戻さない**。v1 schema では active に有限コストを
書けないので、heal を持つ active は round を稼ぐだけで撃ち放題になる
（`analysis/ecology-anti-stall-audit.mjs`）。care の主行動は「傷を戻す」ではなく
「これ以上の傷を止める」側に置いた。

### 4.2 横断pack `pack_relay`「余波と受け渡し」（R9 §5）

R9 §5 が挙げた6つの発生源を一つずつ読み、どれも「その役割の中で完結しない出口」へ渡す。

| ID | 読む出来事 | 渡す先 |
|---|---|---|
| `spill_forward` 余波を回す | 過剰ダメージ | 最も弱った敵へ追撃 |
| `blocked_into_step` 受けを順番へ | 受け止め | 前列最速の味方へ行動権 |
| `mercy_into_guard` 手当てを備えへ | 回復 | 回復した相手へ受け構え |
| `stride_into_reach` 歩みを間合いへ | 移動 | 最前の敵へ隙 |
| `readied_relay` 支度を渡す | 準備完了 | 最も遅い味方へ反応権 |
| `wake_of_the_fallen` 倒したあと | 撃破 | 最も傷ついた味方へ防壁 |
| `wake_reader` 余波を読む（常設） | 過剰ダメージ | 自分の集中 |
| `hand_off` 引き継ぐ / `overreach` 無理を通す | （主行動） | 発生源を作る / 条件付きの強打 |

R9 §5.1 の条件で守っているもの: 発生源6種類、人物ID・skill ID を条件にしない、
どれも単独で価値がある、A＋B の固定レシピを要求しない、**待機だけでは何も増えない**
（すべて RP1 を払い、round か chain で止まる）。

**Campaign Stage 0〜3 には入れていない。** R9 §10 が「このGateを通過する前に
生成装備や大量の高次packを追加しない」と書いているため、作者評価までは
Free / Endless の random manifest からだけ引ける。Stage 4 の候補である。
