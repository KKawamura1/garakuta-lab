## 0. 結論

R1で事前登録した構造条件は、純粋関数の決定的戦闘エンジンで成立した。

- 第一小隊には、群れを倒す三つの質的に異なる指令がある。
- 第一小隊は三指令のどれでも遠砲要塞を突破できない。
- 遠砲要塞には、正面から装甲を破る重砲と、前衛を無視する狙撃の二解がある。
- 重砲小隊と狙撃小隊は群れを突破できない。
- 二正面では、第一小隊と第二小隊を同時に保持し、正しく割り当てる必要がある。

これは面白さの証明ではない。しかし「旧戦略を弱体化せず専門性として残し、別原理の新戦略を追加し、両方を同時に必要とする」という企画の最小構造は、曖昧な説明ではなく実行可能な規則になった。

## 3. 数値境界の修正

紙上の初稿では防塞機HPを10としていたが、参照実装では12へ変更し、R1も同じ値へ修正した。

HP10では、貫通処理を持つ第一小隊が3拍目に防塞を破壊し、余剰と追響で遠砲まで壊せる。これは「第一小隊が一部で強いが、新しい壁には別戦略が必要」という仮説を壊す。

HP12では次が同時に成立する。

- 第一小隊: 一拍3ダメージで3拍後も防塞HP3が残り、遠砲へ届かない。
- 重砲小隊: 一拍7ダメージで2拍目に防塞を破壊し、3拍目に遠砲を破壊する。
- 狙撃小隊: 防塞のHPと無関係に2拍目で遠砲を破壊する。

この変更は勝率調整ではなく、三つの勝ち筋を分離する構造条件である。

## 4. 因果イベント

参照エンジンは少なくとも次を保存する。

- attack: 元威力、装甲遮断、防壁遮断、HPダメージ、破壊、余剰。
- overflow: 次の対象へ渡る威力。
- echo: 何の攻撃を何回コピーしたか。
- brace / shield: 誰へいくつ防壁を与えたか。
- charge / consume_charge: 誰から誰へ電荷が渡り、砲撃威力がいくつになったか。
- wait / barrage: 遠砲が何拍目を待ち、いつ全体射撃したか。
- battle_end: 目標達成、全滅、期限切れ。

表示担当は独自の説明ロジックを作らず、このイベント列を一体ずつ再生する。これにより内部計算と画面説明の食い違いを避ける。

## 5. 面白さに関する現時点の判断

### 具体化できた核

「第一小隊が弱体化されたので使えなくなる」のではない。

- 群れでは、第一小隊が三通りの方法で明確に強い。
- 要塞では、その強さの構造上の弱点が露出する。
- 重砲または狙撃という、別の勝利経路を追加する。
- 二正面で、以前の強さと新しい強さの両方が資産として働く。

今回の好みである「思考→無双→新たな壁→前の戦略を残した追加→規模拡大」を、一章のイベント列へ変換できた。

### 未検証で危険な点

このままでは、M1=第一小隊、M2=第二小隊という仕分けが明白すぎる可能性がある。

これは最初の30〜45分のチュートリアルとしては許容できるが、長期ゲームの主食にはならない。次の段階では、新しい動詞を増やす前に、既存の三量を混ぜた敵を作る必要がある。

例:

- 小型機3体の後ろに遠砲機がいる。
- 装甲の低い防塞が二体いて、余剰と一撃の両方が意味を持つ。
- 二正面の片方は3拍、もう片方は5拍で、速さと生存の価値が逆転する。
- 一個しかない貫通指令を、どの小隊へ装備するか選ぶ。

ここで複数の割当が成立し、どれを選ぶかに予測と妥協が生まれるなら、相性表から戦略ゲームへ進める。
