# R14 — 常設する戦闘予測と、組み替えの値段

作成日: 2026-09-03（UTC）
状態: **実装済み。**機械検査と画面の通し（Chromium）は通過。
作者による現行版のプレイ評価は依然として未実施（analysis/CURRENT.md）。

## 0. この文書の位置づけ

作者の指摘はこうだった。

> 次のステージの完全な戦闘予測が得られる、というのがこのゲームのキモだと思う

R8 §11 は exact preview を「無料・副作用なし・実行と完全一致」と定義していたが、
**置き場所を一箇所にしか作っていなかった**——「戦闘前の最終確認」画面である。
組み替えの手（技能・装備・隊列）はキャンプのタブにあり、予測はその先にある。
一手触るたびに、進んで、見て、戻る。中心のはずのものが、往復の先に置かれていた。

ここはその置き場所を直し、**予測が完全であることから逆算して、組み替えの自由度に
値段をつけ直した**記録である。

---

## 1. 何を変えたか

| 変えたもの | 理由 | engine / schema への追加 |
|---|---|---|
| 戦闘予測をキャンプ上端へ常設 | 予測が組み替えの手元に無かった | 無し |
| 予測が走らせる盤面を呼び出し側から渡せるように | 「灰の門」を予測できなかった | 無し |
| 巻き戻す前の一戦では予測を出さない | 読めても直せない予測は脅しにしかならない | 無し |
| 技能を取り直し不可に | 予測が完全だと出し入れが最適解探しになる | 無し（経路の削除） |
| 装備は従来どおり自由に付け外し | 都度の調整はここへ寄せる | 無し |
| 補給の「偵察」を廃止 | 先を覗く枠に値段がつかなくなった | 無し（用途の削除） |
| result の actor に `startingHp` | 減少量を出す側が engine の計算を再現しないため | **engine 1点** |

## 2. 予測を上端へ

`forecastBar()`（ecology/app.js）が、キャンプの全タブと戦闘前確認画面の上端に貼りつく。
出すのは、各メンバーの **予測HP・減少量**、勝敗、要したラウンド数。

**計算経路は増やしていない。**`previewNextBattle` → `simulateNextBattle` →
`makeExpeditionBattle` → `simulateBattle` の、実行とまったく同じ道を通る
（R8 §11.1「同じ入力の正式実行と完全一致させる」）。preview 専用の試算を持った瞬間に、
いつか片方だけが正しくなる。

毎 render で戦闘を1回走らせるので、入力（盤面・roster・隊列・loadout・持ち越しHP・
生成装備・鍛錬・枠購入）の署名で memo している。engine は決定的なので、この cache は
結果を変えない。

## 2.1 予測が別の盤面を走らせていた

**これは不具合だった。**巻き戻したあとの再戦（灰の門）で、画面の exact preview は
`composeEncounter(encounterIndex, ...)` を固定で呼んでいた。灰の門は12戦の梯子に
属さない（`prologueEncounter` が出す、index 0 の盤面）ので、**画面は目の前にいない敵で
試算した結果を出していた**。R11 §5 の retryHint は

> 戦闘予測で、次の一戦の結果が先に読める。誰をどちらの列に置くかで、予測がどう動くか
> 見てほしい

と言っている。その当のものが合っていなかった。`simulateNextBattle(run, profile,
index, { composed })` で盤面を渡せるようにし、画面は `currentEncounter()` を渡す。

## 2.2 巻き戻す前は出さない

作者の指定どおり、Stage 0 初回の勝てない一戦（`prologueStage === "first"`）では
予測を出さない。まだ巻き戻す力を持っていないので、結果が読めても直せない。
巻き戻したあとに初めて出て、そこから「一手動かすと予測が動く」を学ぶ。

---

## 3. 技能は取り直せない、装備は自由

予測が完全になると、組み替えは**賭け**ではなく**探索**になる。技能を入れて、予測を見て、
気に入らなければ戻す——を繰り返せば、必ず最適解に着く。そこには決断が無い。

そこで、二つの資源に別々の役割を持たせた。

- **技能** — 取り直し不可。解禁した技能点は戻らず（`resetRunSkills` を削除）、
  枠へ装着した技能は外せない（`removeSkill` を削除）。撤退するか12戦を突破して
  遠征が終わるまで固定。**「いま強くするか、先の戦いのために枠と点を残すか」**
  の賭けをここに置く。行動の優先順の並べ替えだけは残した（構成を変えない操作なので）。
- **装備** — 従来どおり自由に付け外しできる。**「この敵に特に効く一品へ毎戦組み替えるか、
  どの敵にも通る一品を固定して安定させるか」**の選択をここに置く。

画面は、押す前に不可逆であることを言う。「解禁（3点・戻せません）」「枠へ装着
（外せません）」、装着済みには「固定」の印、枠が埋まりきった系統は解禁済みの技能でも
装着できないと明示する。

R6 §17.2 は「reset は使った点をそのまま戻す（罰を付けない）。遠征の途中で構成を
組み替えられないと、報酬で得た技能が死に札になる」と言っていた。**その懸念は残る。**
死に札になった技能点の逃げ道は、いまは装備と隊列しかない。作者のプレイで
「点を配られても使い道が無い」が出たら、報酬側（技能点の配り方）を先に疑うこと。

---

## 4. 偵察の廃止

R6 §12.1 の偵察は「補給1で、次の幕の通常戦の個体編成を先に見る」だった。
**次の一戦の結果そのものが常時見える以上、先の幕の並びを1つ前倒しで覗く枠に
値段がつかない。**補給は再挑戦・報酬の引き直し・野営治療の三用途になった。

`SUPPLY_USES` から `scout` を、RunState から `scoutedActs` を、画面から SCOUT 節を消した。
遠征開始画面の「その幕を偵察するまで伏せられます」も書き直した。

---

## 5. engine への追加（1点）

`buildResult` の actor に `startingHp` を足した。passive の `max_hp` 補正を足した
**あとの**開始HPである。これが無いと、減少量を出す側が `withPassiveBonuses` の
「満タンで来た人は上限が上がったぶんも満たして始める」規則を再現することになり、
同じ規則が二箇所に住む。

## 7. 未確認・次に疑う順

1. **巻き戻したあとの初期隊列が、すでに勝てる配置である。**camp の隊列は
   `defaultFormation`（シキ front_left・ナズナ rear_right）で作られ、負けた配置
   （ナズナ front_left）は引き継がれない。つまりプレイヤーは何も直さずに勝ててしまい、
   R11 §5 の「一手直して勝つ」が成立していない。**今回は予測の実装範囲外として
   触っていない。**直すなら、巻き戻し時に run.formation を `PROLOGUE.formation` へ
   合わせるのが最小の手。
2. 技能の取り直し不可が、遠征の中盤で「配られた技能点の使い道が無い」を作らないか。
   作るなら報酬側を疑う（§3 末尾）。
3. 予測が常に見えることで、戦闘の再生を見なくなるかどうか。**予測は数字だけで、
   因果は出さない。**再生を見る理由が残っているかは、作者のプレイでしか分からない。
4. 5人ぶんの予測帯は 390px 幅にちょうど収まる。それ以上の人数（Stage 4 以降）が
   来たら横スクロールになる。
