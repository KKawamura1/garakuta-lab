# SCRAPLINE 0.1 — 実装・検証チケット（履歴）

> この文書は0.5時点の履歴です。現行の0.6実装と検査結果は
> `analysis/SCRAPLINE_0_6.md` と `analysis/SCRAPLINE_IMPLEMENTATION.md` を参照してください。

現在の追試実装版: `scrapline-0.5`（弾道・敵予告・ラン変異・PWA・帰還再加工・敵弾→鉄塊を追加した版）

## 目的

「新しい車両を拾った瞬間に、手持ちの意味が変わる」ことを、短い因果ショーと次の再構築欲で検証する。既存ルートの置き換えではなく、`/scrapline/` の独立プロトタイプとして追加する。

## 体験仮説

プレイヤーは、強い部品を集めるからではなく、同じ鉄塊が `ホッパー → 加工車列 → 砲台 →（磁石なら逆走）` と変わる理由を見て、次の一手を試したくなる。順番の差が即座に見えるため、攻略情報を知った後も別の順番を試す余地が残る。

## 実装範囲

| 要件 | 実装 |
| --- | --- |
| 一つの鉄塊を車列順に加工 | `scrapline/engine.mjs` の `processLine` |
| 11種類の車両と希少なルール変更 | 切断・圧縮・帯電・溶解・磁石・装甲・回収・加速・逆走・ループ・傷跡 |
| 7区画・複数の問い | 群れ、装甲、速射、拾い屋、分解、混成、ボス。seedで第2〜6区画の順番が変わる |
| 順番の可視化 | プレビューと発射後の `CAUSE CHAIN REPLAY` |
| 毎区画の再構築 | 3枚の残骸候補、満車時の交換先選択、並び替え |
| 決定性・再現性 | 通常はランダム seed、`?seed=` で再現。候補と戦闘は純粋計算 |
| スマホ縦画面 | 横スクロールする車列、ドラッグ/矢印並べ替え、390px幅で折り返すフォーム、manifest/Service Worker |
| リロード復帰 | `scrapline-state-v1` を保存。report/reward/done から再開 |
| 観測 | 既存 `/api/runs` へ schema 4、`head: scrapline`、markers、車列、戦闘イベント |

## 今回追加した仮説検証フック

- **順番を変えた差が数値で返る。** 加速車は弾速を上げ、切断車は弾を減速させるため、`加速 → 切断` と `切断 → 加速` で fragment speed と到着 tick が変わる。
- **戻り弾にも局所的な仕掛けがある。** 磁石の後ろに溶解車を置くと戻り弾に炸裂印が付き、磁石の前に溶解車を置いた時とは別の因果列になる。ループ車は自分より後ろの車両だけを一周させる。
- **ラン開始点を二種類にした。** 帯電車始動と加速車始動を seed で分け、同じ候補でも最初の読み替えが変わるようにした。
- **報酬候補は一択を避ける。** 次の脅威への答えを最大三台含めつつ、候補の順番は seed で変える。スモーク用の `recommendedPolicy` は UI に出さない探索器で、各 seed に勝てる線があるかだけを確認する。
- **ショーと観測を同じイベント列から作る。** report のイベントを一コマずつ再生し、同じ `cause_replay_event` をテレメトリへ送る。終了画面では列車名、最後の三つの因果、次に試す問い、交換・見送り数を残す。
- **失敗しても次の試行を残す。** 回答送信に失敗した場合は `pending` と試行回数を localStorage に保存し、終了画面の「再送する」で再試行できる。
- **見て分かる戦闘ショーを同じイベント列から作る。** 車両を通る弾を車列上でハイライトし、弾の大きさ・色・粒子・敵の位置をイベントごとに表示する。音と振動は個別の因果へ対応させ、拒否されても視覚だけで読める。
- **終盤の質的変化を物体で返す。** ループ → 切断 → 磁石 → 逆走の列では、往路の4発が帰路の再加工で8発になり、各弾のID・分裂世代・帰還状態を追跡できる。装甲車が敵弾を受けた時は、吸収した一片が次の鉄塊へ戻る。
- **敵の問いをランごとに変える。** 最初の群れチュートリアル以降は、同じseedで同じ敵順、別seedで別の敵順を再現する。敵の攻撃イベントには被弾した車両を保存する。
- **操作と作品履歴を残す。** 車両はタッチドラッグで入れ替えられ、終了画面では連結・交換・移動・解体・見送りを区画順に振り返れる。
- **PWAと送信待ちキューを用意する。** `/scrapline/` 専用manifest/Service Workerを登録し、送信失敗時は最大20件をlocalStorageへ保存してオンライン復帰時に再送する。

## 面白さの核と仕掛け

1. **局所的な機構が全体を読み替える。** `切断 → 帯電 → 溶解` は手数・火花・爆風になり、`帯電 → 切断` は二つの小さな火花になる。新車両の価値を単独の数値でなく、車列の前後差で理解できる。
2. **着弾後にも因果が続く。** 磁石は戻り弾を作り、逆走車があれば逆順にもう一度加工する。発射だけで終わらないので、結果を見てから「次は磁石を前に置く」と考えられる。
3. **敵が違う問いを返す。** 群れは切断/爆風、装甲は圧縮/溶解、速射は加速、拾い屋は回収、ボスはそれまでの混成を問う。同じ車列の再利用が、単なる最適解の反復にならない。
4. **新しい車両を一台だけ渡す。** 3候補から一つだけなので、取捨選択が「数字の上振れ」ではなく、既存の車列にどんな因果を足すかになる。満車では交換が発生し、古い車両を捨てる判断が残る。

## つまらなくなる原因と回避策

| 失敗の兆候 | 原因 | 回避策 |
| --- | --- | --- |
| 勝敗だけ分かり、何が効いたか分からない | ダメージ式がブラックボックス | `before → after`、通過tick、敵装甲、戻り道を同じ画面で再生 |
| 毎回同じ車列になる | 一択の強車両・ランダム報酬の作業化 | 各区画に複数の答え、候補は seed 依存、満車交換、希少車は規則を変える |
| 長いだけで再プレイしない | 物語や演出が先行し、再構築が薄い | 7区画を10〜12分に限定し、毎区画で候補→順番→ショーを返す |
| 速い敵で理不尽に削られる | 車両を増やすほど遅くなる | 通過tickの増加を緩やかにし、区画間に具体的な応急修理を入れる |
| 拾い屋が磁石を罠にするだけ | ルールが負の驚きで終わる | 回収車があれば戻り弾を守れる。プレビューで戻り印を表示 |
| アンケートがゲームを止める | 初期値やネイティブダイアログ | 未選択の1〜5、インライン入力、送信失敗は再送待ち表示 |

## 検証の境界

### 今回の自動確認

- 同じ seed の初期状態・候補が一致する。
- 車両の順番で `帯電 → 溶解` と `溶解 → 帯電` の結果が変わる。
- 逆走車が戻り道のイベントを出す。
- `armor` 一台だけの不適切な車列で敗北できる。
- 推奨候補を拾う決定的ランが7区画を突破できる。
- UI ソースに `alert` / `prompt` / `confirm` がない。
- 加速・切断、磁石・溶解、傷跡、ループ、分解敵の順番差がイベントとプレビューに出る。
- seed 0〜15 の各サンプルに少なくとも一つ勝ち筋があり、最終車列が一つに収束しない。
- 終了画面の再生・列車名・次の問い・再送導線がソースに存在する。
- seed 0〜255 の推奨経路が全て7区画を突破し、敵順がseedで変わる。
- ドラッグ属性、敵の動き予告、イベントごとの車両ハイライト、PWA資産、送信キューの導線がソースに存在する。

### リリース前に人が確認すること

1. iPhone 390×844 で横スクロール以外の操作が詰まらない。
2. 画面をリロードしても、report/reward/survey の途中状態が復帰する。
3. 初見プレイヤーが10〜15分で、少なくとも一度「順番を変える理由」を口にする。
4. 7区画未満で止めた時も、面白かった瞬間と不明点をログへ送れる。
5. `/api/runs` の D1 行・moments JSON・イベント列が壊れず保存される。
6. 同じイベント列の再生が iPhone Safari で約10秒以内に収まり、音・振動が拒否されても画面だけで因果を説明できる。

## 成功 / 停止シグナル

**続行:** 初見の勝敗理由が `切断/帯電/溶解` のように具体的で、同じ人が順番を変えてもう一度始める。`payoff` が `unclear` より多く、車両の交換が単なる最強選択にならない。

**停止・再設計:** `preview` と実戦の違いを説明できない、全員が同じ5台だけを選ぶ、または7区画を完走しても次の実験仮説が生まれない。数値を足す前に車両の因果線と敵の問いを見直す。
