# SCRAPLINE 0.7 — コンセプト検証成立条件

更新日: 2026-08-27（UTC）  
予定 ruleset: `scrapline-0.7`  
予定 build: `scrapline-build-20260827-r7`

## 問い

加工車の順序と、列が長いほど着弾が遅れる共通物理を、自動戦闘のショーとして
追えるなら、新しい残骸を得るたびに既存列を再解釈し、別の並びを試したくなるか。

0.6 は弾の決定論的イベント列と順序差を実装した一方、結果をショーより先に表示し、
長編成の代償を一部の敵と隠れた四両例外へ限定し、報酬提示・途中終了を保存して
いなかった。このままでは、企画書の体験ではなく測定UIと特例調整を検証してしまう。
0.7 は企画の要素数を増やさず、因果表示、共通物理、測定完全性を直す。

## 変更・維持・複雑性予算

- 変更: 戦闘結果の公開タイミング、敵の接近時間、区画間修理、敵順、報酬予告、
  戦後因果、終了画面、満員列の交換操作、ログ契約。
- 維持: 7区画、通常8種＋レア3種、敵4種＋ボス、最大5両、決定論、既存
  `/play/` と比較ルート、D1の `/api/runs` 契約。
- 追加する概念は `approach`（敵が着弾までに進んだ時間）と、結果公開前後の
  `replay/revealed` の二つだけ。新しい資源、車両、敵、レシピは追加しない。
- 音は補助のままにし、ミュートでも弾ID、経路、被弾箇所、因果を読めるようにする。

## 成功信号・中止信号

作者テストで見る成功信号は企画書11節を維持する。特に、報酬後の二両以上の大改造、
車両と弾による結果説明、使わなかった車両への自発的な問いを一次証拠にする。

次のいずれかなら、0.7を面白さの支持とは判定しない。

- 結果表示だけを待ち、ショーを見ない。
- 第3区画以降に並べ替えも交換も不要になる。
- 長い列の時間代償が敵ごとの特例としてしか説明できない。
- 報酬候補または自動表示文が、次に試す回答を事前に教える。
- exportに提示候補、途中終了、自由記述、正確な行動列のいずれかがない。
