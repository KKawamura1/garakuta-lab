# EXPERIMENT LEDGER — garakuta-lab 全体実験台帳

更新日: 2026-08-26（JST）

この台帳は、散在する実験票、作者テスト、D1 エクスポート、機械検査、研究メモを「仮説→実装された条件→観測→判断→持ち越し」に揃えて読むための索引である。個別資料の代わりに数値を再掲するものではない。曖昧な点は、必ずリンク先の生ログ・実験票で確認する。

## 0. 棚卸しの結果

main の直近の履歴は 2026-08-17〜2026-08-26 に集中し、GitHub API 上では 565 コミット、ツリー上では 357 blob ファイルを確認した。analysis 配下は 218 ファイル（Markdown 94）あり、human-runs には README を除き 22 件の JSON がある。

これらは 565 個の独立したゲーム仮説ではない。大きく分けると次の三種類が混在している。

- 設計証拠: 作者プレイ、D1 生ログ、再現可能な機械実験、実験票
- 測定・実装インフラ: export、public E2E、stamp/cache、ログ修正、ゲート修正
- 歴史的な方針・運用: Sol/Terra、Claude runbook、過去の再開計画

新しい仮説を選ぶときは、インフラのコミット数を実験数として数えない。一方、インフラの不備で条件が成立していなかった場合は、設計仮説の反証として扱わない。

## 1. 時系列台帳

### EXP-00 — ARC / OBS 初期骨格

- 問い: パーツを 5 スロットに配置して自動戦闘を眺めることは、組み替えの面白さになるか。
- 実装: パーツ配置、攻撃/防御/エネルギー、5 スロット、自動戦闘。
- 観測: 防御やエネルギーの循環、万能な受け皿、初期ビルドの完成が他の選択を潰した。
- 判断: 基本骨格単体は不採用。計算の正しさと面白さを分離する。
- 持ち越し: ランダム素材を材料として扱う発想、配置結果を見せる自動実行。

参照: [EXPERIMENT_HISTORY](EXPERIMENT_HISTORY.md)、[DESIGN_LEARNINGS](../DESIGN_LEARNINGS.md)

### EXP-01 — MAT / CYCLE / 構造ゲート

- 問い: 多用途素材と、生成時の勝敗可能性・到達可能性を加えれば、死に手と理不尽さを減らせるか。
- 実装: multi-use material、解決可能性・役割・経路の機械チェック。
- 観測: 死に報酬は減ったが、万能受け皿と固定の最善配置が選択の重みを消した。構造ゲートはゲームが壊れていないことは示せるが、面白さを示さない。
- 判断: 不採用。検査資産は継続。
- 持ち越し: 乱数は答えではなく問題を与えること、ゲートは趣味の判定ではなく健全性の判定に限定する。

### EXP-02 — 機械評価 / エージェント評価

- 問い: 勝率、探索回数、グレード、エージェントスコアで、作者の面白さを代替できるか。
- 観測: エージェントは作者のパーツ価値づけ、意味理解、fun を再現しない。高い構造スコアでも作者には「すぐ解ける」「意味がない」と見える。
- 判断: fun の自動合否には不採用。機械は実装・到達性・ログの確認に使う。
- 持ち越し: proxy として主張せず、作者の自由記述と行動を一次証拠にする。

参照: [HYPOTHESIS_TESTING](../agents/HYPOTHESIS_TESTING.md)、[DESIGN_LEARNINGS](../DESIGN_LEARNINGS.md)

### EXP-03 — PHASE

- 問い: フェーズと順序を導入し、同じパーツでもタイミングと相手によって価値が変わるか。
- 観測: fun 4、replay 3 前後のランがあり、認知的な忙しさが局所的な楽しさに結びついた。最終ミッションの隠れた制限が、誤った敗北を生んだ。
- 判断: 順序・フェーズは候補。ただし不透明な制限は不採用。
- 持ち越し: 選択の価値は相手・順序・未来の行動に接続する。結果表示に制約を残す。

参照: [EXPERIMENT_HISTORY](EXPERIMENT_HISTORY.md)、[human-runs](human-runs/README.md)

### EXP-04 — RELAY

- 問い: 5 スロット、フェーズ、リレーを組み合わせると、方針を組み替える面白さと自己ベストが生まれるか。
- 観測: 最初のランで強い手応え（replay 5 相当）と記憶に残るアハが発生。しかし既知後の 6 ランでは replay が 5 から 1 へ低下した。
- 判断: 初回の discovery / mastery は支持。既知後の continuation は未解決。
- 持ち越し: 結果の振り返り、次の問い、複数の生きた方針。自己ベストやグレードだけを再プレイ装置にしない。

### EXP-05 — LAWS / T1 / T2 / T3 / ceiling

- 問い: ルール変化、解の狭さ、天井、順序差のどれが面白さ・再プレイ性に効くか。
- 観測:
  - T3「順序が意味を持つ」はブラインド比較で支持。
  - T2「解が狭いほど良い」は、PHASE の方が replay 4,3,3,3、CYCLE の方が 1,1 に近いという観測と整合せず、反証寄り。ただし完全な同条件比較ではない。
  - ceiling を必要条件にすると、RELAY の強い初回を落とす。
- 判断: 順序は候補。解の狭さ・天井・相対勝率は必要条件から外す。
- 持ち越し: 何が違うと作者の問いが変わるかを直接測る。

参照: [agents/HYPOTHESIS_TESTING](../agents/HYPOTHESIS_TESTING.md)、[analysis/RETROSPECTIVE](RETROSPECTIVE.md)、[DESIGN_LEARNINGS](../DESIGN_LEARNINGS.md)

### EXP-06 — COST / SQUEEZE / IDENT / SKIP

- 問い: コストや圧力、答えの可視化、攻撃のスキップで、迷い・気持ちよさ・再プレイが増えるか。
- 観測:
  - COST は overload の代償が実際には十分課金されず、fun 2 前後で薄かった。
  - SQUEEZE は圧力を加えたが長期の再試行理由にならなかった。
  - IDENT は答えが見えると検証作業になり、fun/replay 1。
  - SKIP は打撃そのものの瞬間が 3 回連続で最良の瞬間になったが、永続スコアや streak は 2 ランで持続しなかった。
- 判断: 数値コストやスコアは主役にしない。打撃・実行・結果の演出は候補。
- 持ち越し: 実行前の仮説と、実行中の期待更新、強い質的フィードバック。

### EXP-07 — EXP-01 MUTATE

- 問い: 中盤のチップが既存パーツの意味を変えると、同じ盤面を再解釈し、別の方針を試したくなるか。
- 実装: overclock / pressure / follow の途中変異。構造ゲート、4 作者ラン。
- 観測: fun 4,4,4,3、replay 5,4,2,4。再解釈、付け替え、ガチャガチャ、他のチップを見たいという反応があった。一方で、勝ち筋の狭さや follow の不可視性、敗北時の「不可能」感もあった。自然な再プレイの持続は未測定。
- 判断: コア候補として部分支持。チップ数追加や移動制限の調整は凍結。
- 持ち越し: 途中で既存の意味が変わること、変化を目で追えること、敗北から次の仮説を作れること。

参照: [exp-01](experiments/exp-01/R1_MUTATION.md)、[EXPERIMENT_HISTORY](EXPERIMENT_HISTORY.md)

### EXP-08 — EXP-02 DISCOVERY / PUZZLE

- 問い: 固定問題に対するひらめきと、解を見つけた快感は反復するか。
- 観測: 「ひらめき探しパズル」は局所的に面白かったが、固定解・デザイナー指定の組み合わせは反復で飽きた。機械ゲートも一部不成立で、候補選定まで進めなかった。
- 判断: 一回の insight は支持、固定パズルを主ゲームにする案は不採用。
- 持ち越し: 問いを解いた後に、新しい問い・未見の相互作用・自己表現が残る仕組み。

参照: [exp-02](experiments/exp-02/R1_DISCOVERY.md)

### EXP-09 — EXP-03 CONTROL

- 問い: 戦闘中の一回の短い選択を主動詞にすると、観察だけでない緊張が生まれるか。
- 観測: CONTROL 0.1 は攻撃フェーズが実装条件を満たさず fun 1 / replay 1。0.2 はゲートの参照点・量化・探索条件の修復に終始し、最終的に候補なし。
- 判断: この具体版は不採用。しかし「戦闘中の短い選択」そのものは未検証。
- 持ち越し: 仮説が実装されているかを先に確認し、未成立の条件から方向全体を否定しない。

参照: [exp-03](experiments/exp-03/R1_CONTROL.md)

### EXP-10 — EXP-04 GRAFT

- 問い: charge / strike / cover の選択と backlash / aftershock / hand-off の変異で、途中の判断と再試行理由を作れるか。
- 観測: 4 作者ランで、初回 fun 4 / replay 5、後続 fun 4 / replay 2、fun 2 / replay 2、fun 3 / replay 2。初回は仕組みを学び、次回方針を言えた。乱択方策でも一部の支配変異が強く、時間切れ敗北もあった。
- 判断: 仮説→実行→結果→次の方針という局所ループは支持。長期 replay と方策の多様性は未解決。
- 持ち越し: what-if の表示、学習が次の選択を変えること。支配戦略を単に弱くするだけでは再設計にならない。

参照: [exp-04](experiments/exp-04/R1_GRAFT.md)

### EXP-11 — ECHO

- 問い: 観測結果の違いを、次の行動と相棒の意味に接続できるか。
- 観測: 4 ランの fun は 1,3,1,3、replay は 2,3,4,1。反響が次の行動を作る局所性はあったが、36 パーツの意味と全体の目的が伝わらず、別の手の作業に見えた。
- 判断: 現行版は不採用。観測を主役にする方向は、対象と行動を一つに絞る場合のみ保留。
- 持ち越し: 観測→解釈→次の行動の可視化。

### EXP-12 — HAUL

- 問い: 7 個の部品を持ち帰る目的と、追加回収のリスクで選択の重みを作れるか。
- 観測: 4 ラン中 3 勝 1 敗。ただし fun は 2,1,1,1、replay は全て 1。7 個という目標は理解されたが、追加で拾う意味、safe/deep の差、持ち帰った物の結果が弱かった。
- 判断: 現行版は不採用。
- 持ち越し: 目標を具体化すること。ただし収集数だけを増やさない。

### EXP-13 — NIGHT-EATER

- 問い: 身体パーツ、6 夜、複数エンディング、雰囲気で短い育成/物語の再訪を生めるか。
- 観測: 300 seed の到達性、29 エンディング、公開 E2E は通った。作者 2 ランは fun 2,2、replay 3,1、感情マーカー 12 件中 7 件 unclear。「雰囲気かわいい」や局所的な洞察はあったが、全体のモデルがない。
- 判断: 現行実装は不採用。物語を長くするだけでは解決しない。
- 持ち越し: 具体的な相手の欲求→行動→即時反応→試練という最小育成モデル。

### EXP-14 — TOMORI

- 問い: 1 相棒、3 日、3 行動の短い育成なら、関係と再試行を作れるか。
- 観測: 公開 E2E と D1 export は通った。作者 2 ランとも fun 2、replay 2 と 1。listen/listen/listen、look/warm/listen などの行動は取られたが、場所・時間・なぜその行動が効くかが不明だった。
- 判断: 現行実装は不採用。育成方向そのものは未反証。
- 持ち越し: 一つの場所、一人の相手、一つの欲求、直後に見える反応。

### EXP-15 — EMBERLINE

- 問い: 地域を進み、4 スロットのエンジンを作り、資源とパーツをやりくりすると、毎回の判断と再訪が生まれるか。
- 観測: 構造ゲートは通過し、公開 E2E と D1 の合成確認も通った。作者 2 ランは両方勝利。seed12 fun 3 / replay 3、random181104049 fun 2 / replay 2、「簡単すぎ」。初期の組み立てで後半の選択がほぼ無意味になり、自由交換・抽象資源・最終ログ消失があった。
- 判断: 現行実装は不採用。単に難易度を上げない。
- 持ち越し: 守るもの/通すもの、使う/残す、具体的な動詞、結果ログの保存。早期完成を防ぐには、後から本当に再解釈が必要な状況を入れる。

参照: [EMBERLINE_0_1](EMBERLINE_0_1.md)

### EXP-16 — KINDLING

- 問い: 相棒の身体パーツと素材、6 場面、物語、Canvas の演出で、選択と関係の意味を生むか。
- 観測: 作者 1 ラン。fun 1 / replay 1、6/6 場面到達だが 4 pass / 2 fail、最終ルートは fail。感情マーカー 11 件は全て unclear。自由記述は「何をしているのかわからない」「選択が意味を成している気がしない」「値を満たす部品を置くだけで、10 秒で最適解/詰みが分かる」と明示した。初期版のメモ入力未クリアによる重複は UI バグとして修正済みだが、残りの unclear と自由記述は独立した失敗証拠。
- 判断: 現行実装は不採用。文章を長くする、部品を増やす、値の閾値を調整するだけでは続行しない。
- 持ち越し: 素材→装着箇所→相棒の行動→問題への効果→結末の因果を一本で示す。作者が一文で要約でき、失敗後に次の変更を言えることを最低条件にする。

参照: [KINDLING_0_1](KINDLING_0_1.md)、[D1_LOG_ACCESS](../docs/D1_LOG_ACCESS.md)、[HUMAN_TEST_RELEASE](../docs/HUMAN_TEST_RELEASE.md)

## 2. 研究・設計の統合

- [難易度・複雑さ・面白さ](../research/difficulty_complexity_fun.md): 複雑さ、深さ、難易度を分ける。低複雑・高深度も可能で、複雑さを足すだけでは死んだ複雑さになる。
- [面白さを難易度以外へ広げた整理](../research/fun_beyond_difficulty_2026-08-26.md): 熟達、発見、作者性、成長、感覚、物語、収集、謎、安心、社会の複数ループ。
- [育成ゲームサーベイ](../research/raising_game_survey_2026-08-26.md): 関係→成長→目撃される試練。観察可能な相手と短期反応が必要。
- [ランダム性を材料として使う整理](../research/randomness_as_material_survey.md): 素材の意味、コミットメント、可逆性、共通文法、結果の因果を設計軸にする。
- [RETROSPECTIVE](RETROSPECTIVE.md): 既存 8 ルールセットが同じ「5 スロットに置く→押す→眺める」骨格を共有し、差分が小さすぎた。

## 3. 次の実験を選ぶための未解決点

優先度順ではあるが、同時に全部は試さない。

1. 具体的な対象と問題を置いたとき、作者は 20 秒で因果を説明できるか。
2. 途中で既存の素材の意味が変わると、別の方針を自発的に試すか。
3. 数値ではなく、見た目・音・動き・能力の質的変化が、再試行理由になるか。
4. 失敗したとき、原因と次に変える対象が残るか。
5. 育成の相手の欲求と反応を、短いプレイで理解できるか。
6. 自動進行の実行が、予測と更新の時間として機能するか。

## 4. 次の実験票に必ず書く項目

- 仮説: 一文で、作者のどの体験を変えるか
- 主ループ: 今回主役にするループは一つか
- 実装差分: 既存の何を残し、何を捨てるか
- 作者が画面で見る差分: 数値だけでなく、行動・画面・音・物語の変化
- 比較条件: 何と何を、どの順番で比べるか
- 失敗条件: unclear、全選択同じ、初手完成、答えの可視化、次の計画なし等
- 機械ゲート: 到達性・ログ・版識別・import だけを先に検査
- 作者テスト: seed を見せず 1〜2 ラン、自由記述と実行ログを保存
- 判定: 継続、改修、凍結のどれか。数値を見て後から合格条件を緩めない
- 参照: この台帳のどの過去結果を踏まえたか
