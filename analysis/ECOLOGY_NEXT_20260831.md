## 0. 先に読むべき訂正 — HPは戦闘ごとに全回復する

**`ecology/app.js` の `resetBattleResources()` が、戦闘のたびに全員を maxHp へ戻し、
装備耐久も戻す**（作者いわく、敵を残してHPを回復させる戦術や、全滅後の余りAPでの回復を
どう扱うかが悩ましいため）。

**これまでの測定は全部、HPを戦闘間で持ち越す前提で書かれていた。**
`analysis/ecology-decision-space-smoke.mjs` を含め、耐久倍率はすべて
「12戦（または7区画）を通した消耗戦」として測っている。実際のゲームはそうではない。

### 何が影響を受けるか

| 結論 | HP全回復で変わるか |

| ほぼ全ての戦闘が1ラウンドで終わる（上限6〜15R） | **変わらない**（1戦の中の話） |
| 急かすが完了済みの準備にも反応権を払っていた | **変わらない**（修正済み） |
| 身代わりの引き取り合い | **変わらない**（修正済み） |
| 説明文と係数が6件ずれていた | **変わらない**（修正済み） |
| 準備中は行動権が無意味だった | **変わらない**（修正済み） |
| **「回復は積むほど得」** | **変わる可能性が高い。** 持ち越しが無いなら回復は永続資源ではなく、1戦の中の緩衝でしかない |

## 1. 検査を Phase A から Phase B へ移す（最優先）

`analysis/ecology-decision-space-smoke.mjs` は Phase A の7区画（`ENCOUNTERS` ＋ `makeBattle`）で
測っている。**Phase B（3幕12戦、ボスは4・8・12戦目）は main にマージ済みで、Phase A は役目を終えている。**

移す先: `EXPEDITION_ENCOUNTERS` ＋ `composeEncounter(index, difficultyRank)` ＋ `makeExpeditionBattle`。

あわせて直すこと:

- **HPは戦闘ごとに全回復させる**（上記 §0）。装備耐久も同じ。
- **測定は12戦目のボスで行う。** 道中は1ラウンドで薙ぎ倒すのが仕様どおりで気持ちよく、
  触るべきではない。ビルドの良し悪しが試されるのはボスだけ。
  連続量の倍率も**ボス戦だけに掛ける**（全戦に一律で掛けると道中の薙ぎ倒しまで壊す）。
- 床の関門は「雑な編成はボスで死ぬ」に読み替える。

## 2. 難易度の梯子が効いていない

`DIFFICULTIES` は rank 0〜5 で threat budget・変異・ラウンド上限・補給を動かすが、
**rank 0 で完走する編成は全て rank 5 でも完走した**（ラウンド差は1〜2）。
難易度を上げても何も起きていない。これは単独で潰す価値がある。

---

## 3. 探索を強くする（「作者の編成」1つに頼るのをやめる）

いまの関門は `作者が挙げた編成 ÷ 素朴な役割配分の最良 ≥ 1.5`。決定的で揺れないが、
**編成1つで評価するのは危険**（作者の手が変わると関門が動く）。

山登りの結果は種の置き場所に強く依存し、同じ content を定数倍しただけで
天井が 4.47 → 1.87 と動いた。だから天井とコンボ本数は関門から外してある。

やること:

1. **多点スタート。** 無作為の上位、素朴な役割配分の全21通り、
   手で設計したコンボ集（大溜め＋急かす、準備狩り＋行動権の循環、衝撃に備える＋溜め突きなど）
   を全部 seed にして、最良を採る。
2. **分散を実測する。** 別の乱数種で数回まわし、天井のばらつきを出す。
   **ばらつきが十分小さいと示せて初めて**、天井を関門へ戻す。
3. コンボ本数の関門化にはさらに (a) 探索設定を変えても本数が変わらない再現性
   (b) 相互作用項が点数の分解能に対して十分大きいことの裏取り
   (c)「同じ効果の2つ」を組と数えない除外規則 が要る。

## 4. 防御が弱いことへの手当て

戦闘が1ラウンドで終わることが主因だが、**防御は敵HPを上げた全ての設定でも最下位**だった。
別の手当てが要る。分かっている材料:

- 防御系の効果は全て `scope: "self"`（防壁形成・踏み固め・防壁の花・受け流し）。
  回復だけが `allies` を選べる。**防御は人数に対してスケールしない。**
- 防壁は `duration: "round"` で毎ラウンド消える。付与の 88〜98% が吸収されずに消滅していた。
- ただし「前列の味方へ張る」「戦闘中ずっと残る」へ変えても耐久倍率はほとんど動かなかった。
  **HP全回復（§0）を反映してから測り直すこと。** 結論が変わる可能性がある。

## 5. スキルツリーの深さと強さ

作者の希望：「スキルツリーの右のほうにあるスキルはそれだけで強くていい。
ただし完全上位互換はつまらないので避けたい」。

スキルツリーには `cost`（0〜2）と `requires` が既にある（35節点）。
tier と実効的な強さに相関があるかを測るところから。相関が無ければ、
**深い技能ほど強く、かつ浅い技能の完全上位互換にはしない**という制約つきで係数と条件を組み直す。
21技能ぶんの content 設計なので、単独の作業として扱う。
