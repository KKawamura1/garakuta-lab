# TOMORI 0.1 / NE-2 事前登録

更新日：2026-08-26

## 目的

NIGHT-EATER 0.1では、雰囲気は届いたが、作者が相棒の欲求・選択の意味・結末の理由を一周の中でつかめなかった。TOMORI 0.1は、育成要素を増やすのではなく、関係、変化、試験、結末の最小循環を検証する。

## 仮説

**相棒の状態が読め、接し方が即時に姿・反応・記憶へ残り、三日目にその変化が場面で返るなら、作者は「別の育て方を試したい」と感じる。**

## 変更と維持

### 変更

- 相棒を一体に限定する
- 育成期間を3日、1プレイ5〜10分にする
- 接し方を3つに限定し、各選択が覚えさせる性質を画面に明示する
- 選択直後に、文章・アニメーション・色・音で反応を返す
- 3日目に、育った性質を使った結末を出す
- 結末で未選択の可能性を具体的な短文として示す
- 前回の結末の一文を次の子へ手紙として残す

### 維持

- iPhoneの縦画面で遊べる静的Webゲーム
- seedは通常隠し、出会いの雰囲気をランダムにする
- 感情マーカーと任意メモ、終了アンケート、D1ログを残す
- 失敗作も独立ルートとして履歴を残し、既存のゲームを置き換えない

## ルール上の不変条件

- 3日目まで必ず到達できる
- 3つの接し方はすべて選択可能で、明示的な不正解を置かない
- 選択した性質は、選択直後に画面で確認できる
- 結末は、3日間の選択履歴から決定的に再現できる
- 同じ接し方を2回以上選んだ場合は、その性質の結末になる
- 3種類を一度ずつ選んだ場合は、混ざった性質の結末になる
- localStorageへの保存により、途中リロードで選択を失わない
- 結果画面で感情マーカーとアンケートを送れる

## 成功信号

- 終了直後に「この子は何を求めていたか」を説明できる
- 「自分の選択で何が変わったか」を、数値ではなく具体的な反応で説明できる
- 結末が3日間の育て方の結果だと説明できる
- 未選択の育て方を、自分から試したいと言う
- 面白さまたは再プレイ度が、NIGHT-EATER 0.1の1〜2から明確に上がる

## 失敗信号

- 3択が見た目の違いにしか見えない
- 相棒の欲求が分からず、ただボタンを押す
- 反応を読んでも、選択との因果が分からない
- 結末がランダム、または攻略表の照合に見える
- 物語を長くすれば分かりそう、という感想だけで次の行動が生まれない
- もう一度遊ぶ理由が「別の結末を回収する」以外に残らない

## 人間テスト後に聞くこと

1. この子は、最初に何を求めていたと思いますか？
2. あなたの選択で、この子の何が変わりましたか？
3. 最後の結末は、なぜそうなったと思いますか？
4. もう一度遊ぶなら、何を変えますか？

## 実装上の判断

隠しステータスによる最適化は置かない。内部では性質の個数を集計するが、プレイヤーへも「声」「ぬくもり」「まなざし」として表示する。ランダム性は出会いの起点に使い、行動の意味や結末を乱数へ委ねない。

サウンドは選択を補強する装飾であり、再生できない環境でも進行できる。作者の過去テストで音が出ない問題があったため、音だけに因果を依存させない。

## 実装・公開確認メモ（2026-08-26）

初回の公開確認では、タイトル画面までは表示されるが、開始後にタイトルが残る不具合が見つかった。原因は、`renderScene()` がHTML文字列を返しているのに、呼び出し側が `app.innerHTML` へ代入していなかったこと。状態とログだけが進み、画面が進まない典型的な結合不具合だった。

修正後の公開先では、初期表示、開始、選択、選択直後の反応、感情マーカー＋メモ、3日目までの進行、中盤リロードからの復帰を確認した。Pagesの静的アセットキャッシュで旧エントリが返り続けたため、現行の入口は `tomori/release.mjs` とし、旧エントリは経緯を残すため削除していない。

まだ完了していない確認は、公開先で朝の結果画面を最後まで開くこと、D1保存、Actions exportとの照合である。そこではテスト用の行動列・感情メモを外部へ送るため、送信直前に確認を取る。完了までは人間テスト公開条件を満たしたとは扱わない。
