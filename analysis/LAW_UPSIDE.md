# 「上がる条件が在る」と「上がる条件が満たせる」は別だった（2026-08-23）

## きっかけ

作者が二度、独立に、同じ形の不満を出した。

> 減衰：「減衰とダメージ上限のルール相性が悪く、理不尽に感じる」
> 単調：「反射を生かすには遮蔽が多数必要だけど、中途半端な数だと単調の『2つめは半分』にやられる。
> 　　　**周期2以上だと5つ並べても最大2.5個で3個に届かない**ので、単調が単純なデメリットになっている」

**二例目なので、法則ごとの事故ではなく関門の穴である。**
だから法則を一つずつ作者に訊くのをやめて、13法則ぜんぶを同じ物差しにかけた。

## 物差し（`analysis/law-upside.mjs`）

出荷している盤面で、**勝てる並び**の作動を数える。法則は1つだけ動かす（組にすると倍率が掛け算になり、
どちらの条件が効いたのか分からなくなる）。

| | |
|---|---|
| 上がる | 作動のうち、倍率 > 1 の割合 |
| 下がる | 作動のうち、倍率 < 1 の割合 |
| 捨てられた | 上がった作動のうち、**その巡が1巡上限に張り付いていた**割合 |
| **効いている上がる側** | 上がる × (1 − 捨てられた) |

張り付いた巡では、倍率を上げても敵HPは1も減らない。**倍率が出ることと、ダメージが届くことは別である。**

**下がる側の方が大きいのは2件だけで、それは作者が名指しした2件と完全に一致した。**
他の9法則は 27〜78%。境目は自分で引いていない——**分布が勝手に分けた。**

減衰の内訳が特にはっきりしている：1巡目の3倍は**94.5%が1巡上限で捨てられる。**
上がる側は名目だけで、実質は「毎巡1割ずつ落ちる」だけの法則になっていた。

（倍速と反射は掛け算をしないので、この物差しでは測れない。0%と出したら嘘になるので外してある。）

## やったこと

**消さずに、出す先を分けた**（`core/laws.mjs` の `RUN_LAW_IDS`）。

- **ランには出さない。**ランでは引いた法則と最後までつきあう。
  下がるだけの法則を引いたランは、最初から最後までハズレになる（削除した偏食と同じ形）
- **「破れ」の出題には残す。**出題は1問ずつ独立で、**越えられることが機械で確かめてある。**
  そこでは「下がるだけ」は理不尽ではなく、**解くべき制約**である。
  実際、減衰の1巡目3倍が上限に食われることに気づけるかは、そのまま問題になる

**同じ法則でも、置く場所で意味が変わる。**
ここを分けなかったら、破れの出題が7問から4問に落ちていた（一度そうなって気づいた）。

そして物差しを `analysis/smoke-laws.mjs` へ移した。
これまでの検査は「倍率1を超える条件が**存在すること**」だけを見ていて、
**満たせるかは見ていなかった。**同じ穴は二度開かない。

## 残る疑い

**上限で捨てられる割合は、上がる側の法則でも小さくない**（蓄積65.9%、静粛44.4%）。
1巡上限は「1巡決着を潰す」ために入れたもので、それ自体は要る。
ただ**倍率という語彙と、上限という語彙が食い合っている**のは確かで、
法則を足すたびにこの摩擦は増える。いまは分布の下2件を外して済んでいるが、
**上限の側を作り直す日は来る。**そのときはこの表が出発点になる。
