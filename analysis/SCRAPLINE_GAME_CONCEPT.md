# ガラクタ列車 / SCRAPLINE — ゲーム企画と面白さ仮説

更新日: 2026-08-26（JST）  
状態: 企画案。未実装・未検証。  
位置づけ: 既存版の数値調整ではなく、これまで支持された面白さを一本の体験へつなぐ新作候補。

## 0. 結論

ガラクタ列車は、加工車両を並べ替え、後尾から投入した一つの鉄塊を切断・圧縮・帯電・溶融・磁化し、先頭砲から撃ち出して終点を目指す構築オートバトルである。

狙う面白さは、次の一瞬に集約される。

> 強い車両を引いたから勝ったのではなく、その車両をここへ入れたことで、手持ち全部の意味が変わり、自分だけの異常な兵器が完成した。

この感覚を、次の連鎖によって作る。

> ランダムな材料を得る  
> → 既存の列を再解釈する  
> → 自分で大きく組み替える  
> → 動く前に結果を想像する  
> → 短い自動戦闘で予想以上の連鎖を見る  
> → なぜ起きたか理解する  
> → 次に試したい別の並びが残る

一回の発見だけで終わらせず、弱い開始から大改造、圧倒、振り返りまでを10〜12分の一ランに収める。

## 1. この案を選ぶ理由

この企画で、面白さに比較的近づいた観測はすでにある。

- [RELAYの作者テスト](./ROUND8_RELAY_HUMAN.md)では、部品の順序が結果を変え、勝てる並びが狭く、最後まで勝敗が決まらないランで再プレイ度5が出た。
- [MUTATEの判定](./experiments/exp-01/R3_MUTATION_DECISION.md)では、途中で得たチップが既存部品の評価を変える瞬間が支持候補になった。
- [GRAFTの4ラン分析](./GRAFT_0_1_PLAY.md)では、継ぎ火と遮蔽、反動と打撃の関係を理解した初回に面白さ4・再プレイ度5が出た。
- 一方で、RELAYとGRAFTはいずれも支配的な形を理解した後に急速に飽きた。
- [PROJECT_MEMORY](../PROJECT_MEMORY.md)に記録されたKINDLING、TOMORI、NIGHT-EATERでは、素材、行動、相手の変化、結末が同じ因果線上に見えず、雰囲気だけが残った。
- EMBERLINEでは構築と因果ログを置いたが、初期構成だけで進めるため後半の選択が消えた。
- [難易度・複雑さの外側にある面白さ](../research/fun_beyond_difficulty_2026-08-26.md)では、圧倒感、質的変身、視聴覚フィードバック、具体的な対象が過小使用だったと整理されている。

したがって、次に必要なのは新しい抽象ルールではない。比較的支持された「順序」「再解釈」「答え合わせ」を残し、それを物理的に理解できる一つの機械と、十分に気持ちよい結果演出へ変換することである。

## 2. プレイヤーがすること

一ランは7区画、10〜12分を想定する。

1. 次の敵がどのように襲ってくるかを見る。
2. 最大5両の加工車をドラッグで並べ替える。
3. 出発させ、10〜15秒の自動戦闘を見る。
4. 敵の残骸から加工車を一両選ぶ。
5. 新しい車両を入れるか、既存列を残すか、不要車を解体する。
6. 7区画目のボスを倒し、今回できた列車を振り返る。

戦闘中の細かな操作は置かない。プレイヤーの仕事は、動かす前に機械を作り、動いた結果から次の仮説を立てることである。

通常プレイでseedや最適解は見せない。内部の乱数は報酬と敵の組み合わせを決める入力にだけ使い、戦闘そのものは決定的にする。

## 3. 画面上の具体物

画面上に存在する主要な対象は四つだけにする。

- 列車: 守る対象であり、プレイヤーが作った作品そのもの。
- 鉄塊と弾: 車両を通るたび、数、重さ、速度、状態、軌道が見た目で変わる。
- 加工車両: 一両につき一つの基本動詞を担当する。
- 敵: 群れ、装甲、速攻など、現在の列へ具体的な問いを出す。

熱、電気、灯、絆のような抽象値を主役にしない。必要な内部状態がある場合も、火花、鉄片、弾の大きさ、車両の傷など、画面上の具体物として表現する。

物語は「この列車を7区画先の終点へ届ける」だけで開始できるようにする。文章で意味を補わず、失った車両、壊れかけた機関、最後に撃った弾がそのランの物語になることを狙う。

## 4. 部品ではなく、共通の物理文法を作る

### 4.1 一つの鉄塊が変形する

各射撃では、後尾の投入口から一つの鉄塊が入る。鉄塊は車両を一両通るたびに変形し、先頭砲から敵へ発射される。

車両の候補例:

| 車両 | 一文で表せる作用 | 主な使い道 |
|---|---|---|
| 切断車 | 通過した弾を二つに分け、重さと火花を分配する | 群れ、後段の一弾ごと効果 |
| 圧縮車 | 複数の弾を一つへまとめる | 装甲突破、散った資源の回収 |
| 帯電車 | 通過する弾それぞれへ火花を一つ加える | 弾数が多い列、溶融の準備 |
| 溶融車 | 弾の火花を消費し、命中時の爆発へ変える | 群れ、装甲の周囲、帰還弾 |
| 磁化車 | 弾を一度だけ列車へ戻す | 二度目の命中、帰路での再加工 |
| 装甲成形車 | 小さい弾一つを車体の装甲へ変える | 火力を捨てて速攻を耐える |
| 回収車 | 戻った破片を次の射撃の鉄塊へ足す | 長期戦、往復型 |
| 加速車 | 通過した弾の到達を一拍早める | 発射の遅い長い列、速攻敵 |

名称と数値は仮である。重要なのは、一両が一つの共通動詞を持ち、別の固有名詞との専用レシピを要求しないこと。

### 4.2 順序で意味が変わる

順序の差は、説明文上の倍率ではなく、動いている物の違いとして見せる。

例:

- 切断 → 帯電: 二つに分かれた弾の双方へ火花が付く。
- 帯電 → 切断: 一つの火花を二つの弾へ分配する。
- 切断 → 圧縮: 一度分けた弾を再びまとめる。途中の一弾ごと効果だけを稼げる。
- 装甲成形 → 切断: 射撃を一つ失った後に残りを分ける。
- 切断 → 装甲成形: 一片を装甲にしながら、もう一片を射撃として残せる。
- 磁化 → 溶融: 戻る弾そのものが爆発する。
- 溶融 → 磁化: 爆発後の破片が戻り、回収車や後続の仕組みへ接続する。

すべての組み合わせを特別実装するのではなく、弾、火花、重さ、帰還、破片という少数の状態に各車両が作用する。これにより、作者が列挙していない組み合わせが生まれる余地を残す。

### 4.3 車両を増やすこと自体に代償を置く

加工車を一両通るたび、発射まで一拍かかる。

したがって、五両をすべて使えば常に強いわけではない。

- 長い列: 一発は強いが、完成前に敵の攻撃を受ける。
- 短い列: 弾は単純だが、速く何度も撃てる。
- 装甲車を含む列: 生き残りやすいが、敵を倒すまで長引く。
- 往復する列: 一発から大きな価値を得るが、帰還まで時間がかかる。

これは追加のコスト数値ではなく、「列車が長いので弾が前へ届くまで時間がかかる」という物体固有の制約として見せる。

## 5. 敵はHPの壁ではなく、列車への問いにする

敵ごとに一つの正解を要求せず、少なくとも二つ以上の解法を残す。

| 敵の問い | 見た目と行動 | 解法の例 |
|---|---|---|
| 小型の群れ | 多数の小敵が別々の車両へ迫る | 分裂、爆発、帰還で複数回命中 |
| 装甲破砕車 | 軽い弾を弾きながら前進する | 圧縮した重弾、溶融、帰還による累積 |
| 高速砲台 | 三拍後に先頭車を撃つ | 短い列、加速、装甲成形 |
| 回収屋 | 後尾へ近づき、加工車を奪おうとする | 早期撃破、帰還弾、後尾の装甲 |
| ボス | 群れと装甲の二段階を持つ | 専門列の圧倒、または両方へ対応する妥協列 |

敵の情報は戦闘前に短いアニメーションで見せる。「装甲12」のような数字だけで要求を表現しない。

敵によって最適な列が変わっても、毎回すべてを総当たりするゲームにはしない。手持ちの車両は少なく、各車両の作用は一文で分かり、前回の戦闘で得た観測から二、三個の有力な仮説を立てられる状態を目指す。

## 6. 面白さの核

### 6.1 ランダム性が、欲しい物待ちではなく再設計を起こす

報酬前に完成図を決め、必要な固有部品を待つ構造にはしない。

新しい車両は単体でも現在価値を持つ。同時に、現在の列の一部へ作用し、既存車両の評価を変える。

例えば磁化車を拾ったとき、価値が生まれるのは磁化車だけではない。

- 溶融弾を二度当てられる。
- 戻った破片を回収車で次弾へ回せる。
- 長い往復時間を装甲成形で耐える意味が出る。
- これまで弱かった加速車が、帰還を間に合わせる役へ変わる。
- 逆に、現在の圧縮一撃型を壊して採用する必要がある。

この「新しい一両が、過去に拾った四両をもう一度考えさせる」ことが主食である。

### 6.2 強さに、プレイヤーの著者性を残す

レア車両は雑に強くてよい。しかし、置くだけで勝つ部品にはしない。

有力なレア例:

- 反転連結器: 命中後の弾が、車両を逆順に通って戻る。
- 二重床車: 直前の一両をもう一度だけ通すが、二拍遅くなる。
- 破砕機関: 車両が傷つくたび、次の鉄塊が大きくなる。
- 空撃ち機関: 弾が一つも残らなかった射撃の次だけ、鉄塊を二つ投入する。

これらは「攻撃力二倍」ではなく、既存列の読み方を変える。入手は偶然でも、強さを作るには全体の並べ替えと代償の受容が必要になる。

理想的な神ランは次の段階を持つ。

1. 強い方向を示す車両を拾う。
2. 現在の安定した列を壊して採用する。
3. 弱点を別の車両で補う。
4. 最後の一両で循環や反転が成立する。
5. 戦闘の見た目が明確に変わり、敵を圧倒する。

### 6.3 自動戦闘を、待ち時間ではなく短いショーにする

自動戦闘は内部計算の結果表示ではない。構築の因果と報酬を同時に見せる舞台である。

戦闘中に必ず見えるもの:

- 鉄塊がどの車両を通ったか。
- 各車両で数、形、色、速度がどう変わったか。
- どの弾がどの敵に当たったか。
- なぜ弾が戻った、爆発した、消えたか。
- 敵の攻撃が列車のどこへ届いたか。
- 完成した連鎖が、以前よりどれだけ派手になったか。

発動車両を光らせ、線と粒子で弾の経路を示し、重要な衝突では音と振動を返す。これは後から加える装飾ではなく、ルールを理解させ、強さを身体的な快感へ変えるゲーム本体である。

### 6.4 「予想どおり」と「予想以上」を同時に作る

完全に予想どおりなら退屈で、理由不明の予想外なら理不尽になる。

戦闘前には、各車両を通った直後の弾を短いループアニメーションで正確に見せる。これにより局所的な因果は分かる。ただし、敵の移動、複数回の射撃、被弾まで含めた最終的な勝敗を一行で予告しない。

プレイヤーは「分裂した二発が帯電するはず」と予測できるが、「戻った二発が次の群れまで巻き込み、回収弾が巨大化して最後の装甲も抜く」全体までは見切れない。

戦闘後には、最大三つの因果だけを短く再生する。

例:

> 切断で二発  
> → それぞれを帯電  
> → 帰還した二発がもう一度溶融し、群れを突破

数表や長いログではなく、プレイヤー自身の仮説を更新できる映像として返す。

### 6.5 弱い開始から、質的に別の機械へ育てる

開始時の列車は、投入口、単純な加工車一両、砲塔だけにする。一発の鉄球をゆっくり撃つ。

終盤には、次のような変化が画面上で分かる必要がある。

- 一発が八発へ分かれる。
- 小弾が戻りながら再加工される。
- 敵の攻撃を弾へ変換する。
- 一射撃のあいだに複数の車両が連続発火する。
- 画面の大半を弾、爆発、戻る破片が占める。
- 列車の外見と音が、開始時とは別物になる。

数字が増えただけでは成功としない。「今回の列車は何をする機械か」を動詞で説明できるほど、挙動が質的に変わる必要がある。

### 6.6 ラン終了後に、未完の問いを残す

最高得点や全部盛りの完成形を見せると、達成した瞬間に終わる可能性がある。

終了画面では、今回の列車を一枚の作品として残す。

- 最終車列。
- 最も派手だった一射の短い再生。
- 途中で捨てた車両。
- 大改造が起きた地点。
- 今回の列車を、その働きから自動命名した短い呼び名。

例:

> 往復溶融・五両編成  
> 二発に分けた弾を戻し、帰路で爆発させた列車

次のランを促すために未取得部品を黒塗りで並べるのではない。プレイヤーが自分から「あの回収車を残して磁化の後ろへ置いたらどうなったか」と考える状態を狙う。

## 7. 一ランの具体例

### 第1区画: 単純な列車

初期列は、投入口 → 加速車 → 砲塔。

鉄球を一発撃つだけで、小型敵二体のうち一体しか倒せない。列車は一両傷つく。

報酬で切断車を得る。

### 第2区画: 最初の発見

切断 → 加速にすると、二つの弾がそれぞれ速くなる。群れを突破する。

加速 → 切断では、先に与えた一つ分の勢いを二発へ分けるため届くのが遅い。順序の意味を動きで理解する。

### 第3区画: 現在の正解が崩れる

重装甲敵が現れる。二つの軽い弾は弾かれる。

報酬で圧縮車を得る。切断 → 加速 → 圧縮なら、加速を二発へ与えた後に一つへまとめられる。しかし列が長くなり、発射前に一度被弾する。

プレイヤーは火力と発射速度を初めて交換する。

### 第4区画: 方針転換

磁化車を拾う。現在の一撃型へ足すだけでは列が長すぎる。

圧縮車を捨て、切断 → 磁化 → 加速へ組み直す。軽い二発が敵を通過して戻り、二回ずつ当たる列へ変わる。

ここで「今回の列車」が一撃型から往復型へ変わる。

### 第5区画: 弱点が見える

高速砲台に、戻りを待っている間に先頭車を壊される。

装甲成形車を拾う。一発を装甲へ変え、残り一発だけを往復させる妥協列を作る。

火力は落ちるが、列車は生き残る。強さが一軸でないことを体験する。

### 第6区画: 神ランの成立

反転連結器を拾う。帰還弾が逆順で車両を通るようになる。

行きに切断・磁化し、帰りに加速・装甲成形を通るよう全体を再配置する。帰還した破片の一つが装甲になり、もう一つが再発射される循環が生まれる。

### 第7区画: 圧倒と答え合わせ

ボスは群れの後ろに装甲車を持つ。

最初の往路で群れを散らし、帰還弾で装甲を削り、戻った破片から装甲を作って反撃を耐え、次射で倒す。

開始時の単発鉄球とは別の機械が、画面上で自律的に働く。終了後、プレイヤーには「溶融車を拾っていたら帰還弾がどうなったか」という未完の問いが残る。

この例を唯一の正解として実装してはいけない。重要なのは、同じ感情曲線を異なる車両集合と異なる方針で作れることである。

## 8. つまらなくなる主な原因と回避策

| 失敗モード | なぜつまらないか | 早期の兆候 | 回避策 |
|---|---|---|---|
| 万能の車列ができる | 一度覚えた後、報酬も敵も意味を失う | 異なる敵3種に同じ列で勝つ。後半の操作0 | 敵の問いを弾数・重さ・速度・耐久へ分ける。長い列の時間コストを置く |
| 一両のレアだけで勝つ | 強さが抽選の功績になり、著者性が消える | レア取得後に並べ替えが起きない | レアはルールを変えるが、配置と代償がなければ働かない形にする |
| 固有レシピ待ちになる | 報酬が材料ではなく当落判定になる | 「磁化があるから回収待ち」など固有名詞待ちが続く | 全車両に単体価値と複数の接続先を持たせる。専用ペアを作らない |
| 並べ替えが総当たりになる | 発見ではなく、予告画面をガチャガチャ試す作業になる | 一戦で数十回移動し、理由を言えない | 局所因果を常時見せ、最終勝敗の完全予告は出さない。作用を一両一文へ絞る |
| 算数問題になる | 弾の意味が数字へ潰れ、表を読む作業になる | プレイヤーが挙動でなく合計値だけを語る | 弾数、形、軌道、破片、被弾箇所を視覚化する。倍率中心の車両を避ける |
| 敵が事実上の持ち物検査になる | 対策部品がなければ詰み、あれば自動勝利になる | 特定車両の有無だけで勝敗が決まる | 各問いに最低二つ以上の解法を設計し、初期列でも被害つき突破を残す |
| 初期に完成する | 後半の報酬と判断が消える | 第3区画以降、大改造がない | 中盤に既存列の弱点を見せ、レアは既存部品を再解釈するものへ限定する |
| 毎回違うが判断は同じ | 見た目だけ違い、常に強い物を左から置く | 最終構成は違うが行動列が同じ | 敵順、車両集合、時間制約が計画と妥協を変えたかを記録する |
| 演出が派手なだけ | 刺激はあるが、自分の選択との因果が分からない | 「何か爆発して勝った」で終わる | 発動車両と弾の経路を光・線・音で一対一に結ぶ。重要な因果を戦後再生する |
| 演出が長くて待たされる | 答え合わせが退屈な待ち時間になる | 早送り・離脱が常態化する | 一戦10〜15秒を目安にし、同じ小発動を省略して転換点へ演出を集中する |
| 文章で意味を補う | プレイヤーがゲームでなく説明文を解読する | 抽象名詞、比喩、長いログが増える | 名詞を画面上の物へ、動詞を実際のアニメーションへ対応させる |
| 一場面のアハだけで終わる | 仕組みを知った後の継続理由がない | 初回だけ高評価で2回目に急落 | 10〜12分で弱い開始、大改造、圧倒まで通し、二周目で別方針が成立するか測る |
| 難易度だけで延命する | 負けても新しい問いがなく、単に数値が足りない | HP調整だけで再テストを繰り返す | 敵の行動と車両の意味を変える構造仮説を先に置く |

## 9. 最初から守る設計上の境界

### 入れる

- 一つの鉄塊が変形する、追跡可能な因果。
- 配置順による意味の変化。
- 新報酬による既存列の再解釈。
- 車両数と発射速度の物理的な交換。
- 複数の解法を持つ、行動の異なる敵。
- 戦闘前の局所プレビューと、戦闘後の因果再生。
- 見た目、音、振動を含む質的な成長。
- 最終列車と大改造の履歴。

### 初版では入れない

- 熱・電気など複数の抽象ゲージ。
- 固有名詞A+Bの合成レシピ。
- 同一車両を重ねるだけのレベル上げ。
- リロールを中心とする店。
- 敵のHPだけを指数的に増やす難易度。
- 隠された命中率、発動順、敵行動の追加乱数。
- 長いストーリー、詩的な比喩、意味を後から説明する固有名詞。
- 永続得点や最高記録を主な再プレイ理由にすること。
- 大量の部品と敵で深さを代替すること。

## 10. 最小の完全な一ラン

[CURRENT](./CURRENT.md)とPROJECT_MEMORYでは、次に1〜3分の具体的な因果コアを作る案が提示されている。その診断は妥当だが、ガラクタ列車では因果コアだけを単独のゲームとして作者へ渡さない。

この案で確認したい面白さは、次の時間的な曲線にある。

> 弱い  
> → 仕組みを理解する  
> → 一度うまくいく  
> → 新しい敵に崩される  
> → 新報酬で全体を再解釈する  
> → 自分の列車が質的に変わる  
> → 圧倒する  
> → 別の可能性を考える

一場面だけでは、再解釈、成長、圧倒、次のランへの問いを測れない。そこで初版を「最小の機構」ではなく「最小の完全な感情曲線」とする。

初版の上限:

- 7戦、10〜12分。
- 通常車両8種。
- 全体の読み方を変えるレア車両3種。
- 敵4種とボス1種。
- 初期列2パターン。
- 一ランで全車両は出ない。
- 分岐マップ、恒久成長、図鑑、物語分岐は置かない。
- 見た目・音・弾道の演出は、仮画像でもよいが省略しない。

要素数を増やす前に、この範囲で異なる二つ以上の列車が成立することを確認する。

## 11. 成功信号と中止信号

### 最低限の成功信号

作者の一、二ランで、次の複数が自然に出ること。

- 新しい車両を得た後、既存列を二両以上動かす大改造が起きる。
- 同じ車両を、取得時とは違う目的で使う。
- 戦闘前に「こうなるはず」と予測し、戦闘中にその続きを期待する。
- 最良の瞬間として、報酬取得ではなく、自分の列が動いた出来事を挙げる。
- 結果を「数値が足りた」ではなく、車両と弾の因果で説明できる。
- 敗北後、次に変える車両または順序を具体的に言える。
- 終了後、使わなかった車両との組み合わせを自分から考える。
- 促されず二ラン目を始め、実際に別の方針を取る。

面白さ5だけを単独の合格条件にしない。ただし、最終目的は作者自身が繰り返し遊びたいゲームであり、構造指標が良くても再プレイ欲が低ければ不支持とする。

### 明確な中止信号

- 第3区画までに完成形ができ、その後の報酬を無視できる。
- 異なる敵に対して、同じ列を動かさず勝てる。
- 並べ替えの理由を言えず、全順序を試す。
- 最良の瞬間がレア排出だけで、戦闘の出来事にない。
- 戦闘を見ても、どの車両が結果を作ったか分からない。
- 二ラン目も同じ車両を同じ順で並べる。
- 演出を見ず、勝敗表示だけを待つ。
- 「ふわっと分かった」「何かできた」「なんか勝った」が主な理解になる。
- 因果を説明するために長文のヘルプや物語設定が必要になる。

これらが出た場合、敵HPや車両倍率を微調整して延命しない。主ループ、共通文法、フィードバックのいずれが失敗したかを分け、必要なら企画自体を凍結する。

## 12. 実装上の方針

既存リポジトリから再利用するもの:

- 静的PWAとiPhone向け公開基盤。
- 決定的乱数。
- 保存、再開、オフラインキュー。
- D1へのプレイログ。
- 感情マーカーと自由記述。
- 公開前E2E、版識別、seed再現、payload検査。

そのまま引き継がないもの:

- laws、熱、電気、既存の部品数値。
- 現在の5枠戦闘ルール。
- 正確な勝敗を先に出す予告UI。
- 既存ゲームの文章、世界観、抽象資源。

実装では、ルール計算と表示を分離する。弾一つの変形履歴をイベント列として保存し、同じイベント列から戦闘アニメーション、戦後の因果再生、D1ログを生成する。

機械検査は次に限定する。

- 全seedで最後まで進行できる。
- 同じseedと操作で同じ結果になる。
- 各車両が説明どおり弾へ作用する。
- 少なくとも複数の車列で各敵を突破できる。
- 一つの車両または車列が全敵を支配していない。
- 戦闘イベントと画面上のアニメーションが対応する。
- 保存、再開、送信が壊れない。

機械検査は面白さを判定しない。作者テストへ壊れた版を渡さないために使う。

## 13. 未決着の設計判断

実装前に紙上または小さなシミュレーションで決める。

1. 弾の共通状態を何個までにするか。候補は数、重さ、火花、帰還の四つ。
2. 車両が破壊されるか、単に列車HPが減るか。破壊は物語を作るが、ランダム損失になりうる。
3. 報酬を三択にするか、残骸から一つを直接拾うか。カード状のUIにはしない。
4. 車両を最大5両すべて保持するか、予備一両を許すか。予備が多いと毎敵の総当たりになりうる。
5. 局所プレビューでどこまで正確に見せるか。理解は助けるが、最終勝敗まで出すと探索作業になりうる。
6. 一戦の最適な長さ。因果を読める一方、繰り返しが待ち時間にならない必要がある。
7. 初回から音を必須にするか。少なくともミュートでも因果が読める視覚表現は必要。
8. ボスを専門列へのご褒美にするか、複数の問いを混ぜた総合試験にするか。

これらは面白さの核を変えうるため、実装者が便宜だけで決めず、企画票で明示する。

## 14. このゲームを一文で説明する

> 拾った加工車を並べ替え、一つの鉄塊が異常な弾へ変わっていく様子を見届けながら、自分だけのガラクタ列車で終点を目指すゲーム。

この一文で想像した体験が、実際の画面と操作と戦闘に一致しなければ失敗である。
