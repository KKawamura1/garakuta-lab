# EMBERLINE 0.1 / 火走り

状態：自動ゲート通過・公開確認待ち。TOMORI 0.1の人間テスト結果を受けた、独立した構築ゲームの縦切り。

## 問い

物語を増やす前に、プレイヤーが「何を目指しているか」「何を選んだか」「何が変わったか」を一周中に理解できる、短い構築ゲームを作る。そのうえで、ランダムに来た部品を選び、順序と組合せを変え、結果を見て次の方針を立てる循環は、TOMORIより面白さと再プレイ欲を生むか。

## 仮説

**ひとつの明確な目標（火種を灯台へ届ける）のもとで、毎区画に来る3つの廃材から1つを選び、4つの穴への装着順を変え、左から発動する短い自動走行を観察できるなら、プレイヤーは「次はこの部品をこの順で試したい」と思う。**

これは「必要条件」ではなく、面白さを増強する仮説として扱う。自動ゲートは面白さを判定せず、問題空間（選択・配置・順序・相互作用・結果説明）が実装されていることだけを確認する。

## 変更

- TOMORIの育成・抽象的な物語を引き継がず、機械を組む新規ゲームにする。
- 目的を「5区画を越えて灯台へ火種を届ける」と最初の画面で固定する。
- 4スロットの走行機関へ、毎区画3つの廃材から1つを選んで装着する。
- 部品は左から順に発動する。同じ部品でも前後の部品・残った火花・熱によって働き方が変わる。
- 発動後は30秒以内の短い自動走行結果を、部品名と理由つきで表示する。
- 霧、鉄門、群れ、ぬかるみ、灯台という5種類の問題を出す。一つの問題に複数の解法を残す。

## 維持

- iPhone縦画面、タップ中心、静的Web。
- 乱数は隠しseedで材料と区画順を変える。seedは保存ログには残す。
- 部品は単独でも小さな現在価値を持ち、固有の相方を待つだけの死に部品にしない。
- 部品の移動・交換・取り外しは無料にする。リロールを主役にしない。
- 感情マーカー＋任意メモ、終了アンケート、D1保存、Actions exportを踏襲する。
- TOMORI、HAUL、既定版を置き換えず、失敗作と比較基準を残す。

## 最小ルール

- 最初から「小さな車輪」を1つ装着する。車輪は推進2を作る。
- 各区画で廃材3つを見せ、1つを拾うか、今回は見送る。
- 拾った廃材は4スロットの任意位置へ装着でき、既存部品と交換できる。
- スロットの順序は走行前に無料で入れ替えられる。
- 部品は「推進」「守り」「火花」「熱」を生成・消費する。処理結果は短いログへ出す。
- 区画は必要推進と圧力を持つ。推進が足りなければ前進失敗、守りが足りなければ船体が減る。
- 熱が高すぎると追加損傷する。火花・熱・守りの使い方が部品の評価を変える。
- 5区画をすべて越え、船体が残っていれば成功。失敗しても最後まで結果を表示する。

## 自動ゲート（人間テスト前に実行）

以下の5問を、固定seedの全探索または構造検査で確認する。**3問未満なら人間向け実装・デプロイを停止する。** 3問以上でも、これは面白さの合格ではない。

1. **同じ材料の順序差**：同じ4部品の順列で、少なくとも2種類の発動結果が生まれる。
2. **選択後の判断**：同じ提示から異なる部品を選ぶ合法な経路があり、選択が最終結果へ影響する。
3. **複数解法**：各区画で異なる部品系統が少なくとも2つ、単独または組合せで必要推進へ届く。
4. **再解釈**：8部品すべてが、少なくとも2つの区画または配置条件で現在価値を持つ。
5. **結果説明**：すべての発動結果に、発動部品・増減した値・条件理由を含むログがある。

構造的に恒真になるゲートは採用しない。順序差・選択差・複数解法は、実際のシミュレーション出力を比較する。

## 成功信号

- 「この部品をこの順番に置けば、さっきより通りそう」と自発的に言う。
- 取得した部品によって、既存の部品の置き場所や評価を変える。
- 自動走行で予想外の連鎖が起きたあと、その理由を画面から説明できる。
- 失敗直後に、次に変えたい部品・順序・区画を具体的に言える。
- 「もう一度別の材料で試したい」が、単なる全結末回収以外の理由で出る。

## 失敗信号

- 3つの提示を見て毎回一択になる。
- どの部品も常に同じ穴が最適、または強い1部品を引くと判断が消える。
- 結果が負けても、部品・順序・熱・守りのどれを直せばよいか分からない。
- 数字は動くが、何を作っているか・何を守っているか分からない。
- 1プレイ後の面白さが2以下、または再プレイ度が2以下になる。

## 複雑性コスト

- 新しく理解する主語は「火種」「5区画」「4穴」「左から発動」の4つに限定する。
- 初期部品は8つ、資源は4つまで。部品文は一つ2行以内にする。
- 区画の固有ルールは毎回1行で表示し、隠し倍率を置かない。
- オート走行のログは発動順に並べ、予想外の結果も理由を明記する。

## 実装時点の結果（2026-08-26 15:41 JST）

`node analysis/emberline-smoke.mjs` は成功した。同じseedの再現、廃材の装着、順序変更、走行結果、
戦闘ログ、次区画への遷移を確認した。

1. 同じ4部品の24通りの順列から、8種類の結果が生まれた。
2. 最初の提示3択から、異なる2種類の結果が生まれた。

これは面白さの合格ではない。少なくとも、TOMORIで不足していた「選ぶ → 組む → 順番を変える →
結果の理由を見る」という問題空間は、作者テストへ出せる密度になった。次の判断は、作者が実際に
「次はこの廃材をこの順番で試したい」と思うか、そしてその理由が数字ではなく連鎖として残るかで行う。

## 期待する次の判断

人間テストで面白さが低くても、工程成功とは分ける。ルールが読めているのに面白くないなら、次は構築対象か相互作用の核を変える。ルールが読めないなら、部品を増やさずUIと因果表示を直す。TOMORIのように物語を長くして解決しようとはしない。
