# 破れ PUZZLE 0.1（2026-08-23）

**噛み合わせを見つけることだけでできたゲーム。**

## なぜこれか

全記録でいちばん強い感情は、勝敗でも等級でもなく**気づき**だった：

> 「そうか、一撃99の制限は2回攻撃なら198までいけるのか。**知識アンロック！**」

登録した条件（P1〜P12）はこれを一つも名指ししていない。
`analysis/RETROSPECTIVE.md` の結論：**8つのルールセットは同じ骨格の採点方法違いだった。**
9つ目の採点方法を作っても仕方がない。

**気づきを、勝敗の副産物ではなく遊びの本体にする。**

## 骨格を引き継いでいない

| | これまでの8版 | 破れ |
|---|---|---|
| 遊ぶ側の動詞 | 並べて、押して、見る | **目標を越えるまで並べ替える** |
| HP | 30固定 | **無い** |
| 負け | ある | **無い**（越えるか、まだか） |
| 報酬 | 3択×6回 | **無い** |
| ランの構造 | 独立6戦 | **7問。1問ずつ独立だが、法則の知識は持ち越す** |
| 敵 | 適応しない固定列 | **数値の制約そのもの**（1発の上限） |
| 打切り | 12巡 | 3巡で競う |

残っているのは「5枠に部品を置く」だけである。

## 出題は機械が作り、機械が検証する（`analysis/gen-puzzles.mjs`）

出題は「この相手に、**3巡で X ダメージ通せ**」。**X の置き方が全て。**

- **naive** … 法則を**足し算で読んで**組んだ並びが、実際に出す値
- **best** … 全列挙で見つかる最大値
- **目標 X は、その間に置く**

つまり**足し算で考えている限り届かない。噛み合わせに気づいた時だけ越える。**

| | 足し算 | 目標 | 最良 | 倍率 | 並びの数 |
|---|---|---|---|---|---|
| 単調＋消耗 | 369 | 424 | 480 | 1.30 | 820 |
| 倍速＋継電 | 428 | 502 | 576 | 1.35 | 820 |
| 単調＋共鳴 | 373 | 444 | 515 | 1.38 | 1520 |
| 過負荷＋単調 | 174 | 208 | 243 | 1.40 | 440 |
| 減衰＋倍速 | 305 | 368 | 432 | 1.42 | 1110 |
| 単調＋継電 | 578 | 723 | 868 | 1.50 | 440 |
| 倍速＋過負荷 | 157 | 206 | 255 | **1.62** | 820 |

**総当たりで潰せないこと**も条件にした（並びが400通り未満の出題は捨てる）。
5個の並べ替えだけなら60通りで解けてしまい、それは気づきではなく作業になる——
記録に残っている退屈の側そのものである（「ガチャガチャやってたらなんか勝てるので飽きてきた」）。

## 代償機関の失敗から引いた線

- **暗算を増やさない**（学び#30）。目標は**画面に出ている一つの数**で、
  いま何点なのかも常に出る。閾値を暗算する場面が無い
- **噛み合わせゼロの組み合わせを出さない。** 代償機関は13法則のうち8つで
  噛み合わせが0.0%だった（`analysis/ROUND15_COST.md`）。ここは**噛み合わせが出題の定義**である
- **制約ではなく目標。**「越えるな」ではなく「越えろ」

## 検査

- `analysis/smoke-puzzle.mjs`：全問について、解が存在し／足し算では届かず／
  総当たりで潰せず／答えが手持ちから作れること
- `analysis/browser-puzzle.mjs`：**実際の画面で最良解を組み立てて、目標を越えることを確かめる。**
  7問すべてで、画面の数値が表の最良と一致した

## 何を試している仮説か

> **噛み合わせを見つけること自体が、面白さの中心である。**

**外れの形：**
- 「越えたけど、なぜ越えたのか分からない」→ 気づきではなく偶然当たっている
- 「総当たりで解いた」→ 空間が足りない
- 「目標の数字にピンとこない」→ 勝敗が無いことが効いていない
