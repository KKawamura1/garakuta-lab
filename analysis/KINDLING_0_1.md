# KINDLING 0.1 実験票

更新日：2026-08-26

## 問い

難易度と規則の複雑さを増やさなくても、次の体験を一つの短いランで接続すれば、作者が「次は別の相棒を作って試したい」と思うか。

- 来た材料を自分の構成へ読み替える
- 構成が相棒の見た目とふるまいへ返る
- 弱い開始状態から、途中で明確に強くなる
- 失敗しても相棒と物語に変化が残る
- 結果が予兆、行動、派手な反応として返る

## 大きな変更

EMBERLINEまでの「部品の数値と戦闘結果を読む」構造をいったん外し、部品を生きた相棒の部位へ組み込む。道には具体的な問いを置き、選択の結果をCanvasアニメーションと短い物語で返す。

## 保持するもの

- ランダムに来る材料を、問題として扱う
- 材料の価値が取付先と状況で変わる
- 構築中心、短時間、seed再現
- 自動実行を構築の答え合わせにする
- プレイログ、感情マーカー、任意メモ、終了アンケート
- 人間テスト前に自動検査と公開先E2Eを行う

## 最小ルール

- 相棒には目・胸・手・脚の4つの部位がある。
- 各素材は、取付先によって別の行動になる。
- 各場面で二つの道から一つを選ぶ。道は異なる要求と報酬を持つ。
- 道を選んだあと、二つの素材から一つを選ぶ。
- 素材は空き部位か既存部位へ付け替えられる。歩き出した後は固定される。
- 道の要求を満たせば灯りが増え、失敗すれば灯りが一つ減る。
- 灯りが0になると失敗。ただし、失敗したランにも傷・記憶・結末を残す。
- 6場面を通過すると成功。

## 体験上の仮説

1. 物の名前と取付先が、単なる資源名より相棒への愛着を作る。
2. 数値の増加を姿・動き・音へ翻訳すると、構築の有能感を感じやすい。
3. 道に具体的な目的を置くと、現在の選択に重みが出る。
4. 失敗後にも相棒の反応と物語が続くと、敗北が次の問いになる。
5. 新要素の解禁と、同じ素材の別用途が、低い規則複雑さでも再プレイを作る。

これは複合仮説であり、KINDLING 0.1だけで各要因の因果を分離しない。縦切りの体験として作者が再プレイしたくなるかを先に見る。支持された場合、次に演出・物語・構築の対照版を作る。

## 成功信号

- 「この物をここに付けたから、こうなった」と具体的に言える
- 相棒の変化や発動の瞬間を、勝敗以外の出来事として語る
- 道の選択に本気で迷う
- 失敗後に、次に変える構成または見たい結末を言える
- 終了後に、同じseedの再現ではなく別の道・取付先・素材を試したい
- 終了画面の姿・履歴・物語を見返す

## 失敗信号

- 取付先ごとの最適解が常に固定される
- 二つの道が同じ数値問題に見える
- 派手な演出はあるが、自分の選択と結びつかない
- 相棒の見た目が変わっても、何をしたか意味がない
- 失敗がただの損失になり、次の問いがない
- 途中で一つの構成が完成し、残りの選択が消える
- storyや解禁を増やさないと一周目の満足が成立しない

## 公開前の受入条件

- HTML/CSS/JavaScriptの構文と主要状態遷移を自動検査する
- seed再現、全6場面の成功・失敗、素材の取付・交換、道の両分岐を検査する
- Canvasが390×844相当で画面内に収まる
- 途中リロードから復旧する
- 勝利・敗北の最終画面、最終構成、履歴、surveyを確認する
- emotion markerへ任意メモを紐づける
- 公開先で最長経路を通し、D1保存とexport照合を確認する
- versionとbuild stampを表示する

## 判定

自動検査の合格は、相互作用とログが存在することの証拠であり、面白さの合格ではない。作者の1〜2ランを待って、面白さ、再プレイ度、記憶に残った瞬間、次の具体的な計画で判定する。


## 2026-08-26 balance revision: 選択を死なせない

初回の公開前ブラウザ確認と、seed 6・12・ランダム相当の経路探索で、次の問題を発見した。

- 1場面目の初期形によって、表示されたルートの片方が「追加素材を1つ入れても必要な2軸を満たせない」場合があった。
- 2場面目以降にも、前場面を通過しても次のルートへ一手で繋がらない状態が残った。
- これは難易度の問題ではなく、プレイヤーが選択の結果を学習できない「死んだ選択」の問題である。

そこで、初期形を「つながり＋灯り」にし、提示素材を不足量まで満たせる候補へ寄せた。さらに、速度→火花→跳躍、守り→修復、あたたかさ→なおす→帰還という連鎖を6場面のデータに接続した。経路探索では seed 6・12・20260826 の各条件で6場面の成功列を確認した。

この修正は「全ルートを勝てるようにする」ものではない。選んだ道と組んだ体が次の場面の下地になること、失敗はその連鎖を外した結果として読めることを狙う。公開後は、成功率よりも次を観測する。

1. プレイヤーが素材の部位変更を自分の発見として語るか。
2. 失敗後に、同じ答えの再試行ではなく別の道・別の形を試すか。
3. 最終的な「帰った」は、物語だけでなく自分の組み方の帰結として受け取られるか。


## 2026-08-26 browser E2E finding: 触ったあとまでを一つのループと数える

公開画面で実際に「素材を選ぶ → 部位へ組み込む」まで操作したところ、組み込み後に selectedPart が空になる一方、開始ボタンの有効条件が selectedPart の存在になっており、歩き出せない不具合を発見した。自動的なルール検査では検出できなかった。

開始条件は「素材を選択中ではないこと」に修正した。以後の結合テストでは、表示・選択・組み込み・開始・結果までを一つの導線として確認する。
