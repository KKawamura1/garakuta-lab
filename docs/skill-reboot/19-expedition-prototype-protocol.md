# 十二戦の勢いと考える楽しさを測る試験計画

更新: 2026-09-28。状態: **未採用の試験計画。** 親文書: [12戦を走り抜ける遠征の仮説](./18-expedition-engine-hypothesis.md)。前版の二戦固定・経路分岐・予測ロック案を主試験から取り下げた。実際のゲーム挙動をこの文書では変えない。

## 1. 何を確かめるか

主な問いは「毎戦どれほど悩めるか」ではない。**一度考えた選択が数戦にわたって強くなり、問題が起きた時だけ短く直して、もう一度走れるか。** 現行の取得予約と次の一戦の正確な先見機を使い、一Stageの12戦を通して測る。二戦だけの試験では、蓄積した機構が後半にどう変わるか、走る楽しさと退屈の境界、有限の必殺をどこで使うかを測れない。

試作対象は実際のengineから作る12席と五人。新たな経路、固定区間、敵専用の状態、予測回数制限を足さない。現行の敵・有効技能が足りず、12席で違う接続を観察できないなら、既存カタログの節から小数を選びengineに実装する。紙上の未実装技能を「実際に勝った」と報告しない。

## 2. 比較順

最初は同じ戦闘ルール・敵・技能を使い、速度と説明だけを比較する。次に内容を作り、最後に試映後の確定方法を比較する。一度に全部を変えない。

| 条件 | 変えるもの | 保つもの | 反証したいこと |
|---|---|---|---|
| P0 現行 | なし | 現行の12戦、取得予約、正確な予測、試映と実戦の別操作、キャンプの戦果一枚 | 既に「予想→連勝→微調整」が楽しいか |
| P1 速度と一筋の表示 | 続ける操作の視認性、任意の速い再生、取得節と実イベントの短いハイライト | 勝敗・敵・技能・SP・補給・先見機の正確さと編集可能範囲 | 設定をいじらない時間が、連鎖の見返りとして感じられるか |
| P2 接続が育つ十二席 | 同じ共有語彙で技能の節目と敵の入力差を整える。P1の画面を使う | 十二戦構造、予約、一戦先の予測、自由な小調整、有限の必殺 | 勢いは画面演出ではなく戦闘内容から生まれるか |
| P3 試映した結果の確定 | 最後まで試映した同じ入力・イベント列をその場で一度だけ確定する。P2の内容を使う | 正確な予測と本番の一致、設定変更後の再計算、現行の資源制約 | 二重再生を減らす利益が、反復探索を速める損失より大きいか |

P1で改善したらP2が不要とは決めない。表示だけで連鎖が弱い敵を救えたと誤認しやすい。P2で敵や技能を変えた効果はP0との差だけで評価せず、P1と同じ表示で内容を変えた差を見る。P3は保存・確定経路にも影響するため、有望でも実装せずに「確定」ボタンの操作模型でまず意向と編集回数を測り、実戦比較では本物のevent列と一度きりのcommitを実装する。

## 3. 十二席の試作素材

実際の戦闘を書く前の入力設計。各席に「違う技能を持っていないと詰む」という鍵を置かない。敵の戦闘能力・位置・防壁・準備・治療といった既存の行動を使う。4・8・12は現行どおり幕ボスと装備候補を置く。以下は**戦闘の意図であり、既存Stageの勝敗・数値や新しい報酬仕様ではない**。

| 席 | 機構へ通す入力 | 強いビルドにも残す観察点 |
|---|---|---|
| 1–3 | 前衛の防護、後列の治療、少数の素直な攻撃を順に混ぜる | どの対象で連携を始めるか。序盤に今後育つ鎖の入口が見えるか |
| 4 幕ボス | 準備した大打撃と前衛の防護 | 予約の節目がここまでに届くか。必殺を温存する代償と装備候補 |
| 5–7 | 多段の小打撃、空きマスのある位置、後列からの干渉を組み合わせ方を変えて出す | 防壁がRPを消費して反撃に回らない、移動で対象が変わる等の入力差 |
| 8 幕ボス | 主力の接続を一つ妨げるが、別の出口も働く | 一手の変更で持越HPが改善するか。装備の意味 |
| 9–11 | 第2戦の前衛防護＋後列治療を強めて一度だけ再登場させ、別系統を交ぜる | 前回より強い同系統を短いラウンドで突破できるか。その差が倍率だけでなくイベント列に現れるか |
| 12 幕ボス | 複数の既知の圧力を同時にかける | 残った必殺・持越HP・完成した鎖をどう使ったか |

この表どおりに敵を機械的に並べない。たとえば4戦目までに予約が届かない技能ツリーもある。勝利SPは各人物+1、予約は一人一目標で前提から自動解禁、ボス装備は4・8・12戦目だけ、補給は遠征内で増えないという現行条件でシミュレーションする。途中で全員のHPを回復させたり、新SPを上乗せしたりして理想例を作らない。

### 五人の小さな機構

既存の [武器カタログ](./11-weapon-catalog.md) から、ゴウは戦槌と格闘具の「追い拳→拳順」、ナギは大盾の防壁と長槍の被弾後反撃、ツグミは医療具の手当てを主に置く。残り二人にも現在実装可能な移動または準備の節を持たせ、発火する場面を最低一つ用意する。一人5〜8節程度を目安にするが、強制の装備枠制限ではない。未実装節をテストする場合は同じルールで動く小規模な実装を先に作る。

具体的な観察: ナギが味方への先行防壁にRP1を払えば、HP損失を防ぐ一方、被弾後の反撃が条件不成立になりうる。ゴウの追い拳は同じ対象へ命中すれば連携につながるが、撃破や対象変更で切れる。強い自動技能を増やすだけで常に嬉しいとは限らない。同じ五人で異なる敵を通した時に、勝敗が全部同じでも**発火・RP・対象・HP損失・戦闘の長さ**に意味ある違いが出るか見る。

紙上の事前検査では三つの異なる出発構成を用意する。追撃・連携型、防壁からの反応型、準備と移動を軸にした型を候補にし、早期のSPで核が作れるか、同じ敵を相手に少なくとも二つのイベント列が質的に異なるか確かめる。「一番強い構成」と比べるだけにせず、どの構成でも最初から最後まで同じ対象を殴るなら敵の著作をやり直す。

## 4. 操作と表示の境界

現行の通常勝利は結果画面を挟まずキャンプへ戻り、一枚にHP損失・ラウンド等が出る。P1はこの一枚を利用し、プレイヤーに読む義務を増やさない。

- **新しい取得**: 「拳順が開いた。追い拳の命中から連携へ」のように、解禁した節と今あるイベント語彙の接続を一行。実際には次戦で発火しないこともあるので、発火の予言としては書かない。
- **戦闘後**: その戦闘で本当に起きた短い鎖一つと、前回からのHP・ラウンドの変化。変更した技能が原因だとevent列だけでは言えなければ因果を断定しない。短い行を押すと実際のログの箇所へ戻る。
- **予測敗北や大きい損失**: 現行の正確な予測は維持する。短い操作候補をゲームが勝手に「正解」として薦めない。プレイヤーが隊列、必殺、主行動、対象、RP競合のうち自分の仮説に対応する一箇所を選べるよう、採用中の設定と相手の行動を見やすくする。何箇所も試す自由は奪わない。
- **再生**: 初見の鎖は通常速度、既知の戦いは速くする選択肢を出す。再生をスキップしても次へ進め、同じ戦歴を後から見られるようにする。先見機を完全再生して実戦も同じ長さで見る行動が多ければP3を検討する。

不発理由は現行のevent列だけで分からない場合がある。候補判定・RP不足・対象死亡等をengineの同じ判定点で診断できるまでは、「この技能が働かなかった理由」を推測して表示しない。短い因果表示の正確さをイベントと突き合わせる。予約完了でアクティブが主軸へ、リアクティブが優先列へ入る現在の挙動を計測し、**取得前後に自分の望まない置換が発生した件数**を記録する。取得しても採用を維持する案はこの後に別途比較する。

## 5. 観察票と停止点

テストは開発者の通しプレイと、仕組みを知らない少数のプレイヤーを分けて記録する。同じ敵・初期SP・所持技能・決定論的な入力を使い、順番の学習効果を記す。作者が先に敵を知った回と初見の感想を混ぜない。P0→P1→P2と作る過程の数値比較には順序効果が残るため、有望なら参加者の順序を入れ替えて再試行する。統計的に成功と呼ぶ予定はない。

| 記録する量・発話 | 実際に見ること | 赤信号 |
|---|---|---|
| 十二戦の編集履歴 | 同じ方針で何戦連続して進んだか。主軸・予約の改造と隊列・必殺の一手を分ける | ほとんどの戦で五人分の設定を開き、変更理由が説明できない |
| 予測の使い方 | 一戦内の設定変更回数と再予測、最後に何が変わったかの本人の言葉 | 「緑になったから」のみで同じ敵に何度も再照会する |
| 予約の見返り | どの戦で予約が進み、どの戦で初めて節が発火したか | 新節がいつ働いたか知らず、次も同じ倍率節を無理由に選ぶ |
| 戦闘の速度 | 完全再生・早送り・スキップ・後からの見返し、各画面と一Stage全体の時間 | 連勝中、戦闘にも機構にも興味がなく、画面を消化するだけ |
| 敵の違い | 同じ構成に対するイベント列、RP用途、対象、HP損失、ラウンド | 十二席で敵の見た目だけが違う。再登場した同系統の敵が、成長後も同じ処理時間・発火のまま。または一戦ごとに採用し直さないと進めない |
| 必殺と持越し | 各人物一度の使用戦、補給による再挑戦・野営治療、次戦へのHP | いつでも必殺を切れば勝ち、将来の代償を感じない。逆に必殺を使っても窮地を凌げない |
| 心地よさ | 「どこで走り出したか」「どこで止めたか」「もう数戦やりたいか」を自由回答 | 編集しないことを快感とも達成とも感じず、実質待ち時間だと言う |
| 説明できるか | 終盤に主力一筋と、働かなかった別の一筋を本人が短く説明 | 「何が起きたか分からないが勝つので触らない」 |

試験前の仮の目安: 十二戦で深い構成見直しは0〜2回に収まる走り方が少なくとも成立し、同じ方針で五戦ほど連続して進む区間があり、その区間を本人が楽しいと答えること。これは**達成を強制するルールでも、成功率の測定結果でもない**。簡単にしすぎてこの数字だけ達成しても失敗。対照に、十二戦通して一度も調整せず勝つ試験も残し、そこで何を見たくなったかを聞く。既存 [GAME.md](../GAME.md) の十二戦35〜45分目安から大きく長くなるなら、メニュー・再生・試映のどこで増えたか分けて判断する。

### 難しい批判を先に試す

1. **二手で救えたのは先見機の総当たりでは**: 同じ敵で設定を変えて正確な予測を照会した履歴を残す。変更前に理由を一言述べてもらい、戦闘後の原因説明と比べる。見せ方を誘導しすぎない自由プレイも別に採る。
2. **気持ちよい連勝は敵が空気だからでは**: 同一構成で各席のイベント列と持越HPを比較する。自分の機構の違う面を挙げられなければ、爽快さが一度きりの演出だった可能性を認める。
3. **予約はメニューの先延ばしにすぎないのでは**: 解禁時に目に見える新しい出来事がない、完了後に未使用SPが溜まっても選びたい節がない場合は、技能の接続と取得順を直す。予約UIだけを磨かない。
4. **P3は緑探しを速くするだけでは**: 試映一回あたりの時間短縮と、一戦あたりの再予測・設定変更回数、理解の発話を合わせて比較する。重複再生が減っても無理解な探索が増えたら採用しない。
5. **終盤の大量発火は演出で隠しただけでは**: 原ログと簡易表示を照合し、本人が説明できないRP競合や意図しない主軸置換が多ければ、技能内容・取得数・自動採用の分類を削る。

どの条件でも予測編集が日常的な緑探しになるなら、現行先見機を残す賭けは失敗。予測制限や区間固定をすぐ足す前に、**一戦先の正確さ・編集の自由・無理解な探索の排除を同時には保証できない**ことを前提に、何を残したいかを再議論する。

## 6. 実装に進む前の確認

- 現在の20節だけで五人の連鎖が足りない場合は、実装済みとカタログ上の節を厳密に分け、小試作用の少数実装から始める。Stage 6以降や190節全体へ先に展開しない。
- 正確な先見機、勝利時SP、予約進行、幕ボス装備、必殺の一遠征一人一度、有限の補給とretryを現行と同じにしてP0/P1を比較する。
- P3を実装するなら、試映のBattleInput fingerprintとevent列、設定変更による無効化、確定済みの再入防止、勝利SP・HP・装備・戦歴の一度きりの更新、save/reloadを試験する。試映中には予約を進めない。
- 十二区画で「どんな能力が実際に変わるか」をまずengineで確認する。戦闘の見た目だけを調整して多様性があると言わない。
- 有望と判断できるまで現行のGAME.md、Stage 0/1教材、190節の正本を書き換えない。
