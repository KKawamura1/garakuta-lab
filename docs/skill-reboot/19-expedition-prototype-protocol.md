# 遠征エンジン仮説を潰すための小試作

更新: 2026-09-28。状態: 試験計画。親文書: [18-expedition-engine-hypothesis.md](./18-expedition-engine-hypothesis.md)。採用仕様・実装指示ではない。

## 1. 本当に比較するもの

「現行の戦闘が面白くない」や「二戦区間なら面白い」を先に決めない。比較対象を四つに分ける。

| 条件 | 戦闘前の構成 | 正確な先見機 | 戦闘間の選択 | 潰したい疑問 |
|---|---|---|---|---|
| V0 現行 | 毎戦変更可 | 変更のたび勝敗・残HPを自動表示 | 報酬・構成 | 無理解の勝利探索がどれだけ起きるか |
| V1 区間固定 | まず2戦ごと。3戦は追加試験 | 次戦へ進むと決めた後に再生 | 事前に予約した技能の自動取得 | 総当たりを止めると単なる鑑賞になるか |
| V2 区間固定＋経路 | V1と同じ | 行き先を選んだ後に再生 | 事前予約の自動取得と次の敵・報酬の選択 | 同じ機構のまま敵に向き合う判断が復活するか |
| V3 試験室 | 二戦で同じ構成。出発までは再編集可 | 二戦とも出発前に何度でも正確に試す | 設定を直して二つの結果を同時に改善 | 編集と再試験自体が理解を伴う面白さになるか |

二戦区間を本編候補とし、三戦版は退屈の閾値を探る試験にとどめる。三戦区間版は現行の三幕と幕ボス報酬の位置に合わない。V1とV2を分ける。V1が退屈でもV2の経路選択が意味を持つなら、追加の手番操作なしで成立する。V2も退屈なら、UI改善や敵数の増加で押し通さない。V0の優位が明確なら、完全予測の欠点を受け入れ、因果表示で質を高める案へ戻る。V3がよければ「総当たりは常に退屈」という仮説を捨て、区間全体を解く編集ゲームへ明確に寄せる。V3では経路選択の分岐を外し、まず二つの固定敵で測る。

## 2. 一区間の盤面例

5人は整備時に決めた主行動・対象・隊列・装備のまま二戦する。現行の三幕×四戦を保ち、各幕を二戦ずつに区切る。既存の一人一目標の技能取得予約は出発時に固定し、一戦目の勝利SPで前提から自動取得した技能は二戦目から働く。新しい主行動・対象規則を取得しても、採用する設定は次の整備点まで変わらない。以下は**内容を説明する仮の盤面であり、既存Stageの実数値や勝敗ではない**。敵は既存の行動・位置・防壁・状態だけを使い、新しい状態名を足さない。

| 席 | 公開される入力 | 選ぶ理由 | 失うもの |
|---|---|---|---|
| 1 固定 | 前列に庇う敵、後列に治療する敵 | 単体火力・対象選択・遮蔽を観察する | 長引けば持越HP |
| 2A 分岐 | 多数の小攻撃をする敵 | 被弾反応・複数対象処理の価値が出る。上乗せ報酬は次の整備で使う追加技能点（試作の仮設定） | 細かい攻撃による反応資源不足 |
| 2B 分岐 | 少数の大攻撃を準備する敵 | 防壁・怯み・先行撃破の価値が出る。上乗せ報酬は精算時に得る活動資金（試作の仮設定） | 準備中の敵を止め損ねたときの大きなHP損失 |


分岐後は次の二戦区間へ合流する。これなら一つの区間で戦闘の著作量は三編成で済む。次の区間には位置を崩す敵と固定の幕ボスを置き、席2の傷を持ち越す。4・8・12戦目の幕ボスとその装備報酬は現行どおりにする。安全な道をゲームが暗黙に決めてはいけない。例えば守りの弱い隊には2Bの準備技を怯みで止められる利点があり、反応資源に乏しい隊には2Aの連打が痛い、という逆転がありうる。報酬の単純な優劣も避ける。**この逆転が実際のengineで起きなければ、この配置案は失敗**である。

## 3. 手持ちカタログから作る小さな機構

テスト用の技能案を無理に190節へ増やさず、既存の [武器カタログ](./11-weapon-catalog.md) にある組合せを使う。未実装節を本編で取得可能にする意味ではない。

- ゴウ: 戦槌の主行動と初撃強化、格闘具の「追い拳」(単体近接の初撃命中でRP1の追撃) と「拳順」(同じ敵への命中で連携を蓄積)。追撃が命中すれば次の同対象攻撃が育つ。早い撃破や対象変更は連携の蓄積を切る。これは「命中→RPを払った追撃→連携→次撃」の既存語彙だけの鎖。
- ツグミ・ナギ: 医療具の防壁・被弾後手当てと大盾の庇護。ナギが大盾「盾を差す」(味方が狙われた時、RP1で防壁)と長槍「迎え槍」(他の味方がHPダメージを受けた時、RP1で反撃)を両方覚えた場合、同じナギのRPを取り合ううえ、前者が傷を完全に防ぐと後者の条件自体が成立しない。ツグミの医療具「連携治療」(RP2)は別人物のRPを使うが、同じくHP被害を防いだ結果として不発になりうる。取得技能を毎回全部足し算しない。
- ヒバナ・ゲンゾウ: 移動や準備の現在の節から、現行runtimeで動くものを選ぶ。未実装の技能を入れた紙上勝率を報告しない。どちらかの行動が出ない試験は「五人の寄与を見られるか」の失敗として記録する。

一戦目の勝利でゴウの予約した「拳順」が開いた場合、二戦目では追い拳のhitが連携へつながる。必要な前提とSPが揃わなければ開かず、その結果も観察する。同じゴウでも、庇う敵を倒す前に対象が変われば連携が切れる。治療敵への到達が遅ければ、蓄積する前にHPが削られる。多段の敵ではナギの防壁が薄く広く消え、同じナギのRP1を先行防壁へ使うか被弾後の迎え槍へ残すかが効く。ツグミの回復はナギのRPを使わない。ここに**盤面により鎖の得手不得手が見える**はず、という予測を置く。すべてで勝つこと自体は失敗ではないが、発火・持越HP・次の報酬判断まで同じなら、この試作に意味はない。

### 経路が本当に選択になっているかの事前監査

試験者に出す前に、開発用の同一engineで、二つの異なる機構を両経路へ通す。まず報酬を同じにして被害・ラウンド・反応発火を比較し、機構Aは2Aの負荷が軽く機構Bは2Bの負荷が軽いという**好みの逆転**が起きるかを見る。逆転がなければ、報酬を盛って無理に分岐へ見せかけない。その後だけ報酬を追加技能点／活動資金へ戻し、次の固定ボスまで含めた得失を確認する。提示する二択で片方がもう片方より「常に被害が少なく報酬も多い」なら、その二択は設計ミス。ここで両経路の実結果を調べるのは開発者であり、プレイヤーの先見機には出さない。

## 4. 画面で確認する因果

戦闘前に「この敵で一番働くと予想する鎖」を一つ記録する。自由文一行でよい。演習・本番後は次を元のevent列から引く。

1. 起点となった主行動・攻撃・被弾の時点。
2. 接続が起きた箇所と、起きなかった箇所。RP不足・対象変更・遮蔽・既に敵死亡など、実際の不発理由だけ。
3. 結果への寄与。たとえば追い拳1hitとその後の連携値、被害を防いだ防壁量、支払ったRP。結果に直接因果を帰属できないなら「この効果だけで勝った」とは書かない。
4. 前戦との差。敵の変化と、予約による技能取得の変化を分けて示す。どちらが原因かイベント列だけでは切り分けられなければ、因果を断定しない。何もなければ「同じだった」と認める。

「全イベント要約」を新たに創作しない。ログの特定行へ飛べる短いハイライトから始める。スマホの最初の一画面は人名・動詞・共通語彙の短い鎖一つ。詳細はタップで見る。

## 5. 取得が罠にならないか

候補の自動技能を一つずつ追加し、追加前後を同じ六盤面でengine比較する。勝敗、持越HP、消費RP、発火順、対象、ラウンド、撃破順を記録する。**勝率が下がったという一値だけで削除しない**。敵を早く倒したことで後続の回復機会を失ったのか、反応がRPを先食いしたのか、対象が切り替わったのかを説明する。

- 単独でも効果があり、既存選択を横取りしない節だけ自動適用候補にする。無料効果でも撃破順を変えるため「絶対に悪化しない」と書かない。
- 主行動・対象・RP競合・対象変更を持つ節は取得すると**選択肢が増える**。出発時に明示的に採用しない限り、予約による途中取得がいまの動作を変えない。
- 自動候補が二つ以上の普通の盤面で悪化し、その説明がプレイヤーへ短く示せないなら、分類を選択式へ変えるか技能自体を再設計する。自動で大量発火して因果を辿れない場合も同様。SPを払った後の不可逆な罠を「上級者向け」と呼んで正当化しない。
- 選択式が増えて整備操作が重くなるなら、技能数・相互作用の設計を削る可能性を認める。取得と採用の二重選択をすべての節へ広げるのも失敗である。

## 6. 観察票

各版で同じ敵候補・同じ初期技能・同じseedを使う。V0/V1/V3は固定経路、V2だけその固定経路を含む二択を出す。共通経路の比較と、V2の選択理由・別経路の開発用反事実を分けて記録する。順序効果が強いので、複数人なら版の順序を入れ替える。作者一人でも、初見と二周目を混ぜず別に記録する。ここでは統計的な有意差を主張しない。

| タイミング | 書くもの | 失敗と見なす具体例 |
|---|---|---|
| 構成決定前 | 次の入力で働きそうな鎖、弱点、一つ選ぶSPの理由 | 毎回同じ最大倍率を選び、理由が敵や既存鎖に触れない |
| 敵選択前 | 一戦目の結果と予約取得を見て、どちらを選び、何を得て何を失うと予想するか | 高報酬側または安全側を無理由に固定 |
| 先見機の直後 | 実際の起点・変換・利益、不発の理由 | 「緑になった」以外を説明できない |
| 敗北・撤退時 | 次の整備で変える因果箇所 | 適当に位置を変えて再挑戦し、理由は言えない |
| 一区間の末尾 | 二戦で同じ構成の違う働きがあったか、SP選択が変わったか | 敵が違っても全ログが同じ主攻撃の反復 |
| 端末操作 | 編集回数、予測照会回数、緊急整備の補給消費、経路の偏り、戦闘視聴・スキップ、メニュー時間 | V2がV0より調整作業を増やし、因果説明も改善しない。V3で両方緑になっても変更理由を語れない |

試験後の一問は「もう一区間遊びたいか。次に見たい自分の機構の変化は何か」。好意的な答えでも説明が空なら継続判定には使わない。

## 7. 失敗した場合の分岐

- **V1が退屈、V2が面白い:** 敵を選ぶ行為に価値がある。経路ごとの報酬と敵軸の逆転をさらに試す。
- **V1もV2も退屈:** 二戦でも改造の間隔が長いか、戦闘がただの映画。区間をさらに細かくして現行と同じに戻すより、区間固定そのものを捨てる。
- **V2で経路が常に同じ:** 報酬か敵の圧力が一方的。数値を何度も盛る前に、その選択が現在の機構によって逆転しうるかを分析する。
- **V3が好まれ、修正の因果も説明できる:** 予測は欠点でなく遊びの核だった可能性。二戦をまとめて通す構成を主軸にし、経路と複雑な報酬を安易に重ねない。
- **V0が好まれる:** 結果を見て直す作業そのものが面白い可能性。説明可能性を維持したまま、総当たり回数と所要時間を許容範囲として定義する。ただし「勝つまで変更したが理由を知らない」が多いならV0の支持は勝利保証の支持かもしれない。
- **どの版も説明できない:** 先見機と経路以前に、技能発火の見せ方・共通語彙・RP競合が破綻。190節展開より因果の表示と技の設計を先に直す。
- **どの版も説明できるが退屈:** 明瞭さだけで楽しさは作れない。大きく違う働き方の機構を二つ以上作り、選択と成長の変化量を試す。

## 8. 実装前の停止点

1. 紙上で、両方の経路が選ばれる具体的な初期構成を少なくとも二つ書けるか。書けなければ実装しない。
2. 既存engineの同一イベント列を使って「主行動等は固定し、予約の自動取得だけを反映して次の敵を変える」小試験ができるか。新しい戦闘仕様を先に発明しない。
3. 結果確定前の安全撤退が、現行の活動資金・Blueprint・装備持ち帰りと整合するか。敗北と等価な結果を「安全」と呼ばない。補給を使う野営治療は先見機を見る前に不可逆に支払う。敗北予測からの緊急整備は現行retryと同じ補給1個を先払いし、同じ敵へ構成を組み直して再固定する。区間ロック、route固定、取得予約、save/reloadの組合せが抜け道にならないか検査する。
4. 先見機が固定後のみ結果表示になることは、現在の Stage 0/1 の教材と [GAME.md](../GAME.md) §3 を変える。導入の再設計案と同時に評価する。現行の教材を半端に残さない。
5. 有望と判定するまで現行の190節カタログやStage 6のruntime契約を書き換えない。
