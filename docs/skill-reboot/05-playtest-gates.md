# 面白さを反証する試遊計画

状態: 設計段階の検証仕様。未実施。#165 / #166。

## 何を成功と呼ぶか

技能の件数、テスト成功、全シナリオクリアだけでは十分でない。序盤で選んだ方針を使えること、拾った装備で未使用SPの使い道が変わること、後の解放で初期技能に別用途が生まれることを確認する。

| 観察 | 合格の目安 | 失敗と判断する例 |
|---|---|---|
| 第1シナリオの分岐 | ゴウ+ツグミで3つの異なる構成が第4〜6戦までに動く | 全構成が同じ主攻撃+回復で倍率だけ違う |
| 装備との接続 | 低レアの異なる2品で、次のSP配分か配置/優先順位が変わる | レア度が高いものへ交換するだけ |
| 横断コンボ | 1つの共通状態に異なるテーマの発生源2つ/使い道2つがある | 固有SkillIdの一致が必須 |
| 旧技能の再解釈 | 後続テーマ導入ごとに旧テーマ2つ以上との実行可能な接続 | 旧技能が新しい高威力技能に置換されるだけ |
| 核を使う時間 | 核が成立してから通常戦とボスを複数回遊べる | 第12戦の勝利報酬でやっと解放 |
| 対抗軸 | 敵圧力が変わると有利なビルドが入れ替わる | 高guardも多段も後列敵も同じ取得順が最善 |
| 因果の理解 | 「誰が何を起こし、誰が得たか」をログで一文で説明できる | 勝ったがなぜ強くなったか分からない |

目安は品質の関門であり、面白さを数式で証明するものではない。数値目標を満たすための無意味な技能追加はしない。

## 紙上・仮実装で比較する盤面

| 盤面 | 主な問い | 複数の解法として残すもの |
|---|---|---|
| 2人、単体の大攻撃 | 先に倒すか、止めて返すか | 準備大技 / 防御と反撃 / 弱体と継続攻撃 |
| 2人、複数の小攻撃 | 手数をどう扱うか | 対象を減らす / 攻撃側を弱める / 各hit軽減 |
| 高guardの敵 | 小さい攻撃を積む方針をどう変えるか | 大きな一撃 / guardを越す効果 / 他の敵を先に処理 |
| blockを複数持つ敵 | 一撃をどう通すか | 多段で剥ぐ / 別対象へ狙いを替える / block対応技能 |
| 前衛が後衛を守る敵 | 射程と配置をどう組むか | 後列へ届く技 / 前列突破 / 列を使う攻撃 |
| 長い準備の敵 | 攻める時間を何に使うか | 短期撃破 / 防御準備 / 妨害 |
| 初期HPに差がある隊 | 傷を抑えながら火力を維持できるか | 位置変更 / 防御 / 敵由来被害を戻す反応 |
| 5人、低火力の仲間 | 高威力役以外に育成する理由があるか | 状態の供給 / 防御変換 / 有限の行動支援 |

盤面は特定の技能名を鍵にしない。新技能未取得でも勝てる別解を用意する。敵の具体数値はバランス調整段階で固定する。

## 自動戦闘固有の反証

- 条件成立の瞬間に対象が存在するか。先の反応で対象が死亡/移動/状態消費した場合、次の技能が安全にスキップするか。
- 条件付き主行動を上に置いたとき、同じ技能ばかり選ばれて派生の回収技能が永遠に出なくならないか。
- 準備を開始する技能と進める技能が同じ手番を要求していないか。AP1のゴウでも完成するか。
- 後列の武器減衰、技術の低いゴウ、低腕力のナギ、AP2のヒバナ、RP4のゲンゾウで、記載したコンボが実際に得になるか。
- 同じroundに動く予定だった味方が移動した場合の行動順を曖昧にしない。速度値を前提にしない。
- 同じRPを回復/庇う/反撃/連携が奪い合うことを取得例に含める。全反応が毎回発動する想定で威力を足さない。
- 無制限装着でも、全て常設をLv1だけ取るより専門化に意味があるか。UI負担を避けるためだけに装着上限を戻さない。

## 連鎖の安全性は面白さを支える

発生源の変更により、既存装備が新しいループを作りうる。技能だけを独立して検査しない。

1. 敵からの被害と自傷コストを区別する。自傷は治療のための新しい回復枠を作らない。
2. 治療の再配分を扱う場合、元の敵由来被害に対応する回復可能量を二重使用しない。余剰回復を無尽蔵の利益源へ変えることは採用しない。
3. APを渡す行為とAPを新しく作る行為を分ける。往復授受・準備加速・撃破再行動を含む循環を確認する。
4. 発火上限は「そのキャラのその技能」なのか「隊で共有」なのか、「hit/行動/連鎖/round/戦闘」のどれかを定義する。engineの最大イベント数エラーを通常の停止条件にしない。
5. battle内の上限だけではanti-stallを証明しない。敵を残して待つ操作で次戦へ持ち越すHP・補給・装備状態が良くならないことを別途確認する。
6. 技能・固定装備・生成装備が同じ発生源から同じ意味のイベントを出す。予測と本番の同一経路を維持する。

## 遊んだときの記録

各構成について、seed/content version、取得順と累計SP、編成・優先順位、装備、成立した最初の戦闘、使わなくなった技能、方針を変えた報酬、理解できなかった連鎖を残す。

作者には最初から完成レシピを渡す試験だけでなく、目標だけを伝え自分で組んでもらう試験も行う。発見の余地を評価するため、説明なしで気づいた接続と説明後に気づいた接続を区別する。
