# 五人の一巡は十二戦を支えられるか――反証手順

更新: 2026-09-28。**試作前の測定計画。** 親文書は[22](./22-five-action-fun-thesis.md)。20/21の危険選択・交互手番を主案として実装しない。ここに書く合格目安は小規模な設計上の警報で、統計的な保証ではない。

## 1. 問いを小さくする

「技能がたくさん接続できる」ではなく、**予約中に本人が待ち望んだ五人の動きが、完成時に本当に見たくなるか**を調べる。その後に十二戦をもう一度続けたいかを問う。先見機が正確だからという理由で、勝敗を聞き続ける検索に化けていないかも同時に測る。

試作対象は五人がそろった一Stageの十二戦、三幕×四戦、4/8後の全回復、現行の一戦先の先見機と取得予約。味方の順番は**維持**する。装備選択や必殺などは、最初の比較では現行どおり。敵に新たな先制・必須技能・幕ごとの危険を追加しない。難度調整と敵の差は同じ条件のテストに可能な限り共通させる。

## 2. 比較条件

| 条件 | 実際に変えること | 失敗したときに分かること |
|---|---|---|
| P0 現行 | 現行のStageと技能・予約・先見機 | 予想していた連鎖・開通の瞬間・見る楽しさが既にあるか |
| P1 数値だけの成長 | 最小の試作枝で、同程度の取得時期・勝ちやすさになる単純な火力／防御上昇を与える | 技能の質ではなく単に強くなることが楽しいのか |
| P2 一巡が変わる成長 | 同じ取得時期に、余剰ダメージの引継ぎ、撃破対象から次の敵への状態受け渡し等、既存の出来事で五人の結果を変える数節を与える。行動順・敵・報酬機会はP1と同じ | 「予想→開通→数戦の見返り」が、数値強化より楽しいか |
| P3 十二戦の演奏 | P2の技能に、通常勝利を軽くつなぎ、初発火・生存ぎりぎり・幕ボスで自然に立ち止まれる再生と戦歴を足す。取得予約は自動進行 | P2が面白い場合、間の操作や長い既知の再生が勢いを損なっていたか |

P1とP2の勝率や撃破ラウンドを完全一致させることはできない。まず同じ生存帯を目安に係数を合わせ、**単にP2が圧倒的に強いから喜ばれている**可能性を質問とログで切り分ける。P2に必要な大技能は二、三系統だけ。全190節の実装はこの比較に含めない。現行実装済みの節と設計カタログ上の節を混同しない。

## 3. 敵と技能の最小セット

- 序盤・中盤・終盤に、同型の「前衛が残る布陣」を一組だけ置く。HPや一体の追加で強くなるが、特殊な無効化はしない。前回に対し初巡の撃破順・残HP・敵手番がどう変わるか観測できる。
- 別の敵は小型複数、後列の支援、回復する敵、長く残るボスなどにする。どの型も火力・集中攻撃・防御・残り資源で複数の突破を許す。「ある節がないと敗北」の相性を作らない。
- P2は少数の大きな受け渡し節を、五人のうち少なくとも三人にまたがるよう置く。元の攻撃、次の対象、消費された余剰、状態の受け渡しをログで追えること。敵の数や実際に余ったダメージ以外の架空の無限燃料を作らない。
- まず節が少ない状態で筋を確認し、その後に五人それぞれ5〜8技能程度を持つ終盤条件へ進める。小試作で説明できても、五人の実際の終盤で説明できなければ採用しない。

## 4. 何を見聞きするか

試作UIに予言クイズを強制しない。観察担当が出発前に「予約した節で何が変わると思うか」を一度だけ尋ね、回答を保存する。技能が開いた直後には**結果を見せる前に**何を期待しているか聞く。戦闘後には「予想通りだった部分／予想外だが理由が分かる部分／理由が分からない部分」を聞く。プレイヤーが自発的に見返す・次へ進む行動は発話より重視する。

| 記録 | 答えたいこと |
|---|---|
| 予約の選択と変更 | 先の節が欲しくて経路を選んだか。二本目の予約が作業になったか |
| 初発火の戦闘 | 見る前に想像した五手と、実際のイベント列がどう違ったか。本人が因果を説明できたか |
| 十二戦のリズム | 何戦を連続して進めたか。どの再生を最後まで見て、どれを飛ばし、あとで何を見返したか |
| 心が動いた箇所 | 「一巡で倒せなかった→あと一節→一巡で越した」を具体的な敵と行動で挙げられるか |
| 思考の負担 | メニュー滞在時間、各戦の設定変更、予約候補を読んだ量、先見機を再計算した回数 |
| 敵の存在 | 同じ初動でも、敵の構成が結果・次の予約の考え方をどう変えたか。逆に全部同じ映像になったか |
| 最終的な動機 | 初発火を見終わった後も、「次にこれを足したい」「もう一Stage」と自発的に思ったか |

先見機での結果検索は、再予測の**回数と意図**を記録する。負けた理由を説明できる一回の見直しと、結果が緑になるまで設定を変え続ける行為を同じ「編集一回」に数えない。手慣れた人と初見を混ぜて平均しない。可能なら条件順を入れ替え、数人規模の印象を統計的な証明と呼ばない。

## 5. この案を捨てる条件

1. **予想の喜びがない。** 出発前に本人の「こうなるはず」がなく、事後も「強くなった」以上の説明が出ない。設計メモの核が本人の遊びではなかった。
2. **数値上昇と区別できない。** P2はP1より派手に勝つが、本人が新しい接続を見たくならず、予約選択や次Stageへの意欲も同じ。因果ではなく倍率が快感だった。
3. **開通まで退屈。** 予約の道中に働く節がなく、二、三戦をただ飛ばして完成を待つ。大技能を遅く渡すだけではカタルシスにならない。
4. **完成すると終わる。** 一回だけ新連鎖を見たら、その後の通常戦もボスも飛ばし、次の予約も欲しくない。十二戦という長さ自体が不要かもしれない。
5. **敵が消えるか鍵穴になる。** どの編成にも同じ五手・同じ戦歴、または敵ごとにロードアウトの変更が必要。この両端を別々に測る。
6. **頭の中の像が壊れる。** 終盤は五人の行動と発火を本人が追えず、短い因果ログを見ても「何となく強い」となる。状態・RP競合・技能密度を削る。
7. **先見機が総当たりになる。** 通常戦の大半で複数回の予測と無料編集を繰り返し、変化の理由を説明できない。完全予測と可逆な大量編集の同居を再設計する。
8. **P3でしか気持ちよくならない。** UIの圧縮で操作は減っても、P2の技能が心を動かさない。速度改善を「戦闘が面白くなった」と取り違えない。

結果が厳しければ「敵を焚く」に戻る理由にはならない。技能の見返りが足りないなら節を作り直す。五人の予想が面白いが十二戦が長いなら戦数を減らす。自動実行をどうしても見たくならないなら、戦闘中に選ぶJRPGやタワーディフェンスへ**ゲームの核ごと**移す。プレイヤーが面白がった場所を残してから仕様を選ぶ。

## 6. 実装の境界

このPRは文書だけ。P2の具体節・数値は未採用。試作を実装するなら別PRで、現行の決定論、同じ入力からの予測／本番イベント一致、取得予約・SP・戦果の一度きりの精算、有限の連鎖、保存復帰を検証する。P3の連戦操作は、取得やボス報酬の確定と次戦を混同せず、一戦ごとに保存する。面白さのテストへ入る前に大規模なUIと190節を完成させない。
