# 遠征を「自作の戦闘機構の負荷試験」にする仮説

更新: 2026-09-28。状態: **議論・試作提案。採用仕様ではない。** 対象は Stage 5 以降の本編。PR #336 の戦槌実装とは独立し、この文書だけではゲーム挙動を変えない。

## 0. 結論を先に

一番賭けたい案は、**一戦ごとに構成を最適化する代わりに、二戦を一つの区間として同じ機構を通し、戦闘間には「次にどの負荷を引き受けるか」を選ぶ**こと。強さの問いを「この敵に勝つ設定は何か」から「異なる負荷を受けても、自分の連鎖がどこまで働くか」へ移す。

先見機は残す。ただし現在のように、構成・隊列・装備を触るたび、次戦の勝敗・HP・ラウンドを無料で即時更新する形とは両立しない。**区間の設定と次の行き先を確定した後**に、その一戦を本番と同じイベント列で試映し、結果を確定するか、安全撤退する。試映した後に構成や行き先を戻して再試映することは、同一区間ではできない。撤退するとその区間は終わるので、戻って同じ状態から別設定を試す操作にもならない。試映を飛ばして即時確定もできる。決定論と予測・本番同一経路は維持する。

ここで避けられない関係を明示する。**(i) 次戦の完全で正確な結果、(ii) 設定を無料で何度も戻せること、(iii) 勝敗表示を見ながらの無理解な探索が成立しないこと**を、同時に保証することはできない。入力を変えて結果を何度も照会できるなら、因果を読まずに探索できるからだ。理解したい人が探索してもよいが、それを標準の勝ち方にしたくない。この案は (ii) の「次戦についての可逆性」を手放す。区間出発前の演習の自由と、次戦の正確さは守る。

これは「もっと情報を隠す」案ではない。敵の編成・技能・公表法則・経路報酬は決定前に読める。**確定後の結果だけは、確定前に照会できない**。事前に自分の挙動を学びたい場合は、踏破済みの敵や固定の訓練盤面へ現在の構成を当てて、報酬なしで何度でも試せる。この演習は次の実戦そのものの勝敗照会にならない。

既存作の不満は有益な仮説であって、個々のレビューだけで因果を確定しない。特に「予測があるから鑑賞になる」は、操作の場所・目標・再試行可能性を分けて検証する必要がある。

## 2. 三度考え直した記録

### 案A: 現行の完全予測に因果表示を足す

勝敗だけでなく「誰の何が何を発火させたか」を見せる。理解は進む可能性がある。しかし配置を一マス動かすたび勝敗が変わるなら、因果表示を読まなくても緑を探せる。**理解支援は必要でも、総当たりの誘因には効かない。** 単独案として棄却する。

### 案B: 予測の回数に資源を課す／乱数を混ぜる

回数制限は失敗を恐れて試運転を減らし、最も学習が必要な初心者を罰する。敗北時の再読込にも弱い。予測と実戦の乱数をずらせば、何を改善したか分かりにくくなり、現行の決定論契約も壊す。**いずれも主案として棄却する。**

### 案C: 二戦を同じ構成で進み、敵を選ぶ

直前の微調整を防ぎ、敵ごとの違いを「解くための着替え」ではなく「自分の機構が得意な入力と、欲しい報酬との取引」にできる。予測を完全に残しても、次戦の設定をいじって緑にする操作ができない。欠点は深刻で、二戦目に失敗を知っても改造できず、純粋に観戦だけの時間が増える。**この欠点が実プレイで上回れば棄却する。** 次節は採用決定ではなく、この案が成立する最小仕様。

## 3. 最小の遊びの循環

1. 整備点で次の二戦の候補、敵の行動・位置・報酬を読む。技能点を使い、装備・隊列・主行動・対象方針・競合する反応を決め、次の勝利で解禁する技能を予約する。ここでは次の勝敗数値を出さない。複数敵への対応は同じ設定に織り込む。
2. 区間を出発すると、その設定を保存して固定する。出発後の再読込でも固定は解除されない。区間内の一戦ごとに二つ程度の行き先から一つを選ぶ。ただし幕ボスなど固定の席では分岐しない。選択肢は同じ敵のHP違いではなく、前衛の防護／多段の圧力／後衛の治療／位置の撹乱など、公開された少数の軸と異なる報酬を持つ。
3. 行き先確定後、先見機で**本番と同一の戦闘**を通して再生する。プレイヤーは何が発火したかを見る。終了時にはその結果を確定するか、既存の撤退・精算規則に従って退く。勝敗だけを繰り返し問い合わせる画面はない。早送り・即時確定も可能。
4. SPは一戦ごとに得る。装備候補は現行どおり4・8・12戦目に出る。装備変更と主行動・対象・反応の並べ替えは次の整備点まで待つ。一方、**出発前に各人へ予約した取得順は固定したまま、勝利時のSPで自動解禁して次戦から働く**。現行の取得予約を「途中で成長するが、見た結果に合わせて書き直せない計画」として使う。予約がなければSPは貯まる。装備報酬は次の整備点で選ぶ。二戦後に考え直す。12戦なら六区間が基本案。現行の三幕×四戦と4・8・12戦目の幕ボスを維持し、各幕に二戦区間を二つ置く。試作では三区間案の情報量も比較するが、本編へ採るなら幕ボスと装備報酬の位置を変える大工事になる。

**敵を選べることの理由:** 同じ機構で「防護役を先に処理すると連携の起点を失うが、後列治療役を先に狙うと前衛の多段でHPを削られる」のような違いが見える。安全な道は補給、危険な道は次の接続技能や装備を得る。どちらも自分の構成に応じて得失が変わる必要がある。常に安全・常に高報酬が正解なら経路選択は失敗。

**戦闘中に何もしないことの扱い:** そこは意図して受け入れる犠牲。代わりに戦闘の視聴は「仮説の検証」、経路選択は「機構へ通す入力の選択」、整備は「次の区間へ向けた改造」に役割を分ける。二戦でも観戦が長すぎる可能性がある。その場合は区間固定そのものを疑う。演出を長くして埋めない。

## 4. 構築を読める大きさに保つ

190節を同時にONにする思想は採らない。技能の**取得**と、挙動を変える**採用**を別の意味にする。

- 主行動・ターゲット変更・RPを奪い合う反応は、取得で「選べる方針」が増える。区間の整備時だけ選ぶ。主行動は一人一つ、対象は原則一つ、反応は発火窓ごとの競合を明示する。取得直後に既存の優先列へ勝手に割り込ませない。予約で主行動やターゲット候補を得ても区間中の設定は変えず、次の整備点で採用する。
- 資源を奪わず他の行動を抑制しない強化は原則として自動適用。ただし無料でも撃破順や状態の消費を変えうるため、「自動なら必ず強くなる」とは保証しない。取得前に現在の機構で何を変えるか、影響する発火窓を見せる。横方向の技能で悪化が頻発するなら、自動枠へ置いた分類自体を改める。
- 戦闘表示は全イベントを同じ重さで並べず、**起点→変換→利益**の短い鎖を1〜3本だけ表に置く。残りは展開可能なログへ。例: ゴウの戦槌が初撃命中 → 格闘具の追い拳がRP1で追撃 → 拳順で連携を蓄積 → 次の同対象攻撃が強化。現行カタログの技能を用い、反撃ダメージを攻撃hit扱いしない。この鎖は実イベントから導出し、存在しなかった接続を美談にしない。
- 戦前には「今回は連携からの追撃が出るはず」のように一つだけ予想を置ける。的中報酬は付けず、試映後に発火した／しなかった理由を表示する。知識を試す自発的な補助であり、義務化しない。

## 5. 敵設計の条件

敵の役目は技能IDの鍵穴ではなく、機構の異なる性質を測る入力。各区間に少なくとも二つの異なる圧力軸を置く。特定の武器でしか対処できない敵を作らない。

例: 同じ「防壁で守る／追い拳→連携で攻める」隊に対し、(a) 少数の大打撃は防壁の価値を試す、(b) 多数の小打撃は反応回数と守りの在庫を試す、(c) 後列の治療役は対象選択と撃破までの時間を試す。三種類の盤面で同じ結果・同じ戦闘ログになるなら、敵もしくは技能接続が弱い。特定の一戦だけ全く機能しないなら、それは持ち物検査に近い。**得意／苦手の差と、代償が見えるが、代替の勝ち筋もある**範囲を探す。

### 接続は数ではなく、役割と制動で設計する

既存カタログの「追い拳→拳順」は、同じ敵へhitを重ねると育つが、対象変更・撃破で連携が消え、RP1も払う。医療具の「血へ還す」は残存防壁をHPに変えられるが、その防壁を全員から消しRP2を払う。鉤縄の「釣り出し」は移動させた敵の防壁を除き隙を付けるが、空きマスと移動の成立を要する。このように**発生源・変換・利益・制動**を共有語彙の上に置く。単なる「命中で+15%」だけを連ねると、接続本数が多くても戦い方は一つになる。

| 接続の軸 | 成立すると変わる判断 | 明示する制動 |
|---|---|---|
| 同一標的へのhit→連携 | 倒し切るか、次撃のために同じ対象を残すか | RP、対象変更、早期撃破 |
| 防壁→残量のHP変換 | 今守るか、ラウンド末に治すか | 防壁全消費、RP、次の被弾 |
| 移動→防壁除去・隙 | 後列の敵を引き出して誰に渡すか | 空きマス、移動可能性、RP |

複数の入力で同じ技能が毎回最高なら制動が弱い。反対に発火条件が稀すぎて購入が罠なら入口が弱い。**強い連鎖は歓迎するが、五人全員の主行動を同じ倍率装置へ集めない。** 終盤は「主力の連鎖一つと失敗した連鎖一つ」を本人が説明できるかを測る。表示を簡略化して理解不能を覆い隠さない。

## 7. 実装を急がない検証順

現行の「毎戦編集・常時正確な予測」を対照として残し、**戦闘ルールと敵の数値を同じにした**小さな試作で比較する。いきなり190節やStage 6の全敵に展開しない。5人にそれぞれ短い技能5〜8個、共通状態は既存語彙だけ、圧力軸の違う敵を6編成、まず二戦区間を比較する。三戦は二戦で退屈が見られなかった場合の追加試験に限る。既存Stageの12戦・SP配布・チュートリアルとの整合は試作後に決める。

観察するのは勝率より、(1) 試映前に「何が起きると思うか」、(2) 見た後に発火と失敗原因を説明できるか、(3) 次のSPで既存連鎖をどう変えるか、(4) 同じ構成で別の敵を見る意味があるか、(5) 予測・本番・メニューの滞在時間、スキップ率、(6) 経路が常に一方に偏るか、(7) 事前に見えない必敗があるか。ログと短い発話で記録し、作者以外も試す。

中止条件の例: 三人中二人以上が、勝敗を変えた因果を答えられない／戦闘を見ずに最適経路が自明／区間内に次の判断が欲しくて苛立つ／整備にかかる時間が戦闘を大幅に上回る／全員が同じ万能構成に収束する。人数や閾値は統計的な証明ではなく、次の開発を止めて原因を調べる目安。試験者が少ないので、反例の具体的な説明を優先する。

**次の判断:** 案Cが成立すれば、現行の常時結果表示・試映キャンセル・戦闘後の取得操作・Stage 1の「敗北→必殺で勝利」の教材を書き換える大きな仕様変更になる。Stage 0の構成チュートリアルは踏破済み敵への演習で因果を教え、Stage 1の必殺教材は予測表示の緑化を必須にせず、公開された盾二枚への有効な選択として教え直す必要がある。成功判定前に既存UIやカタログへ適用しない。失敗したら、案Aの因果表示だけを現行へ戻す可能性があるが、それで総当たり問題が解けたと主張しない。
