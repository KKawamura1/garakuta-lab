# 12戦を走り抜ける遠征の仮説

更新: 2026-09-28。状態: **議論・小試作提案。採用仕様ではない。** [反証用の試験計画](./19-expedition-prototype-protocol.md)と対で読む。現行の [GAME.md](../GAME.md) と実装はこの文書では変更しない。

## 0. 訂正と賭け

前版は「同じ構成で二戦進む区間」を主案にした。**これは撤回する。** 12戦を六区間に分けると、六回も出発前の判断を期待する。苦しい敵を越えた後も次の区間で足を止め、取得予約がもたらす「仕込んだ機構が成長しながら最後まで走る」楽しさを削る。敵分岐・区間ロック・予測の事後公開・敗北時だけ補給を払う緊急整備も主案から外す。現行の三幕×四戦、4・8・12戦目のボス報酬、技能取得予約、次の一戦の正確な予測、戦前の隊列・必殺・技能設定を保ったまま試す。

賭けたい体験は、**序盤の少数の選択を仕込み、何戦も自分の連鎖が育ち、敵の圧力が変わっても走り抜けること**。一区間をクリアするゲームではなく、十二戦の中で「うまく回った」「苦しいので一手だけ手当てした」「また回り始めた」という速度の差を作る。毎戦の変更は可能なまま、必要も義務も生まれにくい敵と成長を設計する。うまくいけば、十二戦すべてを同じ方針で越えてよい。

この賭けはプレイヤーの深い思考を常に要求しない。考える時は「次にどの接続を育てるか」と「今の傷をどの一手で減らすか」を短く選ぶ。その結果を数戦の自動戦闘が増幅し、戦闘を見たり早送りしたりする。**賢い一手に対する長いご褒美**が主役。

## 2. 十二戦で何を選ぶか

| 場面 | 典型的な判断 | 操作の基準 |
|---|---|---|
| 出発前 | 五人の主軸と、それぞれ次に欲しい節の予約。継続プレイなら前回の方針を使ってよい | 深く考える最有力の場面。取る順番が数戦の挙動を変える |
| 通常の勝利後 | 戦果、取得予約で開いた節、次の敵を確認して進む | 前の設定を保持。技能の解禁や未使用SPで画面を塞がない。次に何をするか選ぶ必要がなければ一手で進める |
| 強い敵・予測で苦しい時 | 隊列、必殺の構え、主行動・対象・反応の採用を一箇所から試す。必要なら補給や取得方針も見直す | 変更の自由を維持。現行の必殺は人物ごとに遠征で一度だけなので、目先の勝ちと後半の余力を取引できる |
| 幕ボスの後 | 現行どおり4・8・12戦目の装備候補を選ぶ。必要なら次の予約を置き直す | 報酬を選ぶことはするが、五人全員の構成編集を毎回求めない |

取得予約は現在、一人一目標で、勝利SPが入るたび前提から自動解禁し、目標に達すると消える。未設定や完了後にSPを貯めても遠征を続けられる。現行の取得ではアクティブが主軸に入り、リアクティブが優先列に入るなど、**予約完了が意図せず戦闘を変える場合がある**。これを無視して「予約したら放置で安全」とは言わない。取得前にどの採用が入れ替わるかを短く見せ、取得直後に変わった採用と予測結果を目立たせる試作を先に行う。取得しても現在の採用を維持する方式は、区間ロックとは別の**要検証の仕様変更**であり、単純な既存UI変更として扱わない。

新しい予約の提案は「自分の既存の攻撃／防壁／移動に入る次の接続」を最大二、三個ほど示す程度を試す。全ツリーは常に見られる。推奨の自動選択で答えを代行しない。本人の予約が完成しても次の選択を強制せず、「もう一つ増やしたい」と思った時だけ開ける。小さい選択から大きな変化が得られず、毎戦同じ薄い数値節を薦めるなら、この方式は失敗。

### 一つの遠征の仮の手触り

開始時にゴウの命中後の追撃と、その追撃が同じ相手への連携へつながる節を予約する。第1〜3戦では早い撃破を楽しみながら、追撃がRPを使うことを知る。第4戦でその接続が開き、初めて二人目の攻撃まで連携が届く。次の敵は小打撃を重ねるため、ナギの防壁反応がRPを使い、予測で一人のHP損失が大きい。そこで第5戦だけ隊列または必殺の構えを調整し、以後はそのまま進む。第8戦の装備が守りを助ければ、第9〜11戦は初期には難しかった敵の群れを高速に抜く。第12戦のボスでは、残していた一人の必殺を切るか、素の機構に任せるかを考える。

これは**実測された攻略例でも、常に苦戦する戦数の割当でもない**。第4戦で予約が完成するSP、具体的なRP・敵数・HPは実際のengineとカタログで確かめる。第1〜12戦を一度も編集せず完走するビルドも歓迎する。その場合でも少なくとも「初めに期待した接続がいつ働き始め、どの敵で異なる働きをしたか」を戦歴から辿れる必要がある。

## 3. 速度と見せ方の試作

現行は通常勝利後に結果画面を挟まずキャンプへ戻り、上端の一枚が戦果を示す。先見機は現在の次戦の勝敗・HP・ラウンドを正確に更新し、試映は無確定、実戦は確定する。この土台で以下を順に検証する。

1. **続ける一手を目立たせる。** 現行の結果一枚に、今回解禁した節・予想した連鎖の発火・HPを持ち越した代償を各一行以内で足す。次戦への操作を画面移動で増やさない。情報がない回は何も足さない。
2. **再生は長さを選べる。** 速度と、連鎖だけを見返す入口を試す。初めて新しい技能が発火した戦いでは短い強調があり、既知の反復では早送りできる。12戦を無断で自動確定しない。速く抜けた人にも後で見られる戦歴を残す。
3. **試映を最後まで見た時の二重再生を試す。** 現行では試映から戻って実戦を再生する。別案として、試映した同じ入力・同じイベント列を一回だけ確定できる操作を比較する。途中で設定を変えた場合や現在HP・装備状態が変わった場合はその試映を確定に使わない。戦果の二重付与を防ぐことが実装条件。勝敗探索を速める副作用も同時に測る。
4. **因果を一筋見せる。** 成立した「命中→追撃→連携→次撃」などを実際のeventへ戻れる短いハイライトにする。未発火の理由は候補判定が残っていなければ推測しない。見て分かったと思わせる誤説明を避ける。
5. **任意の連戦操作を最後に比較する。** プレイヤーが明示的に「続けて進む」を選ぶと、各戦を現在の設定・取得予約で順に実行し、勝利を一戦ずつ保存して次へ進む。進行中に止める操作は次の戦闘の前に効く。次戦の正確な予測が敗北、ボス後に装備選択、遠征終了、または本人の停止でキャンプへ戻る。技能解禁は短く示して止めない。最初から十二戦分の結果を計算して採用する機能ではない。これなら「あと一戦」の入力を何度も求めず、一つの構成で走れる。**ただし敗北直前で自動停止する仕様は緑の予測だけを通す装置にもなる。** 観察と介入を奪わないか、予測編集が増えないかを別条件として測る。

一つ目と二つ目は説明・速度の試作である。三つ目・五つ目と取得後の採用維持は確定・保存経路に触れるので別実装。いずれもこの文書では未採用。

## 4. 敵と育成に課す条件

十二戦のすべてを難問にしない。序盤に接続を作る余地、いまの機構が勝ち抜く区間、圧力の種類が変わる敵、幕ボスの節目を混ぜる。ただし「四戦目だけ難しい」と数で設計を固定しない。敵が違っても同じ構成で抜けられ、**勝ち方・傷・RPの使途・対象・所要ラウンドのどれかが変わる**ことを試験する。全部が同じなら敵の違いは薄い。毎戦の設定変更が必要なら持ち物検査である。

たとえば前列防護＋後列治療では同一対象への追撃が育つ前に治療されるかもしれない。多段の小打撃では味方の防壁反応が連続し、RPが反撃へ回らない。準備した大技では怯みの価値が上がる。同じ機構が各戦で有効でも、戦後のHP・必殺の消費と次の敵への余力に差が出る。万能機構が難敵を粉砕する回も残す。敵をすべて強くして連勝の報酬を奪わない。

技能は「別の名詞を覚える」より、現在の鎖を既存イベントで別の出口へつなぐ瞬間に価値を置く。取得すると競合するRP・ターゲット・主行動を変えてしまうなら、技能文と採用時の差を明示する。自動的に強くなる節だけで埋めれば購入は自明になる。強い横道が一時的に弱くなりうるのは許すとしても、短い説明で理由が分からない購入の罠は許さない。

### 反復する敵を成長の物差しにする

第2戦で出た「前列が庇い、後列が治す」敵の組合せを、第9戦では一人増やすか耐久を高くして再登場させる。第2戦は治療で追撃が途切れ四ラウンドかかったが、予約した接続が開いた第9戦は二ラウンドで治療役まで届く、という**同じ構造の比較**を作る。前回より強い敵でも早く越えられるなら、育てた機構の変化を読める。これは敵を再利用して楽をする意図ではない。何が同じで何が違うかをプレイヤーが見分けられる相手を一組だけ置き、残りには別の圧力を混ぜる。

**第一案: 戦闘速度と短い戦果表示だけ。** 改善すれば操作は軽い。しかしその十二戦がほぼ同じ映像なら、単に退屈を飛ばすボタンになる。そこで、予約による節目と「前に苦しかった入力への再挑戦」を内容に入れる。**第二案: 再登場する敵を増やす。** 強さの比較は分かりやすいが、既知の敵ばかりでは発見が消える。再登場は一幕を通した一組程度を仮の出発点とし、新しい役割の敵も混ぜる。さらに同じ敵でラウンドだけ短くなり、発火の種類が変わらない場合は、育成を単なる倍率上昇にした疑いが残る。試作では数値差とイベント列の質の両方を見る。

### 一戦先が正確でも、十二戦先の代償は残るか

現行の先見機は**次の一戦**の結果を確定的に示す。必殺は人物ごとに遠征中一度、HPと装備状態は次へ持ち越され、補給も有限である。「次戦で勝つ」は十二戦を進む目的の一部分に過ぎない。第5戦を必殺で無傷にできても、第8戦でその一人の必殺を使えない。この遠征全体の代償は、一戦先の勝敗表示だけでは一つの緑に畳めない。ここが、先見機を残してなお短い戦略を考えられる最も有力な理由。

**反論:** 必殺を使わず隊列や採用の無料変更だけでHPを減らせるなら、その敵で何度も予測して最良値を探す作業は残る。未来の代償も万能の免罪符ではない。無料編集の組合せが多すぎる場合は、次の一戦についての合理的な総当たりが支配しうる。この回数と説明可能性を十二戦で測り、駄目なら設定の種類や先見機との関係を改める。試映を見た結果の採用もこの検索を速めるので独立の比較条件にする。

## 5. 厳しい反論

| 反論 | 今の回答と反証条件 |
|---|---|
| 十戦近く流せるなら、遊びは開始前だけでは | 走る途中で予約取得・敵の違い・持越HP・有限の必殺が見える必要がある。連勝中のプレイヤーが数戦先まで見たいと思わず再生を全部飛ばすなら、テンポだけ整えても失敗 |
| 完全予測と無料の編集があれば緑探しになる | **その通り。完全な防止策は提案しない。** 危機の一、二戦で因果を追う小調整なら許容しうるが、毎戦の勝敗検索、説明できない編集、何十回もの再予測が常態なら、先見機または編集可能範囲を改める。画面の因果表示だけでは原理的に防げない |
| 予約がすべて決めるなら、自動進行が虚無になる | 予約の節目で働き方が大きく変わり、ボス装備や次の予約の魅力が見える必要がある。数値を少し足すだけの節が続くならカタログから直す |
| 先見機に勝利が出ると戦闘を観ない | 完全再生を見せることを義務にしない。連鎖を見たい回が現れない、戦歴にも戻らないなら、プレイヤーは機構を観察したいわけではない。その時は鑑賞の演出で延命しない |
| 敵を易しくすると単調、難しくすると着替えが要る | 通常戦では強さの差を見せ、ボスや少数の圧力で持越HPと有限資源を問う。ただしこの配分を「黄金比」として先に固定せず、十二戦を通した実測で調整する |
| 取得節が増えると、終盤は理解不能 | 表示で隠すだけでは解決しない。五人の実際の発火鎖を説明できないなら、重複接続、RP競合と取得密度を削る。190節というカタログ総数は一遠征の有効ルール数ではない |

**受け入れる犠牲:** 戦闘中のクラッチ操作はない。完全予測で次戦のサスペンスは弱い。得意な機構で数戦を容易に越えると、その間はゲームから問いが少なくなる。これは気持ちよく走れるか、単に退屈かが分かれる賭け。無料の予測と編集を残す限りブラックボックス最適化を理論上排除できない。これを隠したまま「理解するゲーム」と宣言しない。

## 6. 判断保留と記録

[19の試験計画](./19-expedition-prototype-protocol.md)で、一戦ごとの編集回数だけでなく、**連続して同じ方針で進んだ最長区間、予約が開いた直後に起きた変化、意図的に再生を見た回、予測を検索に使った回、次も走りたいと思うか**を記録する。十二戦を通じて「初めに考えたことの見返り」が残るかを問う。

前版の二戦ロックは、正確な先見機・可逆な編集・総当たり防止を同時に満たせないという原理上の指摘には価値がある。ただしプレイ体験の主案としては、区切りの多さと爽快感の損失を過小評価していた。もし現行の巡航案で毎戦の探索が支配的になった時に限り、ロック等を再比較する。二戦固定へ自動的に戻さない。
