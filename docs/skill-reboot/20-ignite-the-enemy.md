# 「敵を焚く」――十二戦を走るための破壊的な試案

更新: 2026-09-28。**議論用。現行仕様ではない。実プレイで面白さは未確認。** この文書を今回の主案とする。以前の[巡航案](./18-expedition-engine-hypothesis.md)は比較用の履歴、[試験計画](./21-ignite-prototype.md)は反証用。採用前に `GAME.md` や190節の正本を改変しない。

## 1. 面白さを一つの場面にする

第5戦、敵が前衛を二度殴って防壁が割れる。「やばい」と思った直後、こちらの新しい規則が発火して敵に破甲がつく。格闘家の追撃がそこへ入り、連携を受けた射手が後列を落とす。第6戦では別の敵の初動に同じ機構が違う順番で働く。第8戦まで育成予約で追撃が伸び、最初は代償だった敵の攻撃を待ち遠しく感じる。

**プレイヤーは四戦続く危険と、その危険を力に変える規則を自分で選んだ。** 「作ったものが動いた」に加え、「自分で選んだ脅威を食って動いた」が爽快さの核。この一場面が面白くなければ、下の制度を磨いても無意味。

## 2. 現行の退屈をどう診断するか

`docs/GAME.md` と現行実装・序盤の画面確認からの**設計上の仮説**。十二戦通しのプレイ観察ではない。

| 現行の構造 | 遊びに生じうる空白 | 強い反証 |
|---|---|---|
| 通常戦後のSPと取得予約は自動で進み、装備の二択は主に4・8・12戦目 | 良い予約ほど戦間は「次へ」の確認だけになり、戦闘も予測済みの領収書に見える | 予約の完成や戦況の差を、プレイヤーが自ら見返して次を待つ |
| 次戦の勝敗・残HP・ラウンドまで正確に表示し、無料で設定を直せる | 原因を知らずに緑の結果を探せる。見せるほど本番の緊張は減る | 編集回数が少なく、変更の理由を本人が説明できる |
| 現行は味方全員の手番の後で敵全員が動く | 火力が増えるほど敵の行動前に終わり、敵の固有性と被弾反応の出番が消えやすい | 高成長時でも敵の圧力が異なる連鎖を実際に生む |
| 一戦は完全オートで、一人一度の必殺も戦前に条件設定する | 危機の瞬間に人が参加できず、強い連鎖ほど眺めるだけになりうる | 観察そのものが十二戦にわたり自発的に楽しまれる |
| 技能の数と接続を増やす | 低倍率の節が増えれば選択は薄く、長いイベント列は理解を失わせる | 少数の新しい規則で戦い方が大きく変わり、その理由を追える |

4・8戦目の後には全回復する。HPの持越だけで十二戦すべてに緊張を作る想定は正確ではない。危険は**四戦の幕**の中で意味を持たせる。既存の35〜45分という一Stageの目安は短縮も含め再計測する。

## 3. 他作から借りる構造と、灰に足りない動詞

| 一次資料 | 一つの短い判断が何を変えるか | 灰への示唆と危険 |
|---|---|---|
| [Vampire Survivors](https://store.steampowered.com/app/1794680/Vampire_Survivors/) | 武器の育成判断を多数の自動攻撃で増幅。移動は常時プレイヤーが行う | 予約成長と画面の増幅は合う。灰には移動という遊ぶ動詞がない |
| [Slay the Spire](https://store.steampowered.com/app/646570/Slay_the_Spire/) | 札・遺物・道を選ぶと後の戦いが変わる。毎ターン手札も選ぶ | 少数の選択の長期効果は学べる。完全オートで毎戦同等の選択を要求すると手間になる |
| [Balatro](https://store.steampowered.com/app/2379780/Balatro/) | Jokerでルールが大きく変わり、毎回手札を出して爆発を作る | 「+5%」より規則の変換が強い。自動発火だけでは能動の手札選択が欠ける |
| [Loop Hero](https://store.steampowered.com/app/1282730/LoopHero/) | 敵を置いて自分の道を危険にし、戦利品と資源を増やす | 敵を自分で招く判断を借りる。ただしカードを頻繁に置く操作は十二戦の巡航と合わない |
| [Into the Breach](https://www.subsetgames.com/itb.html) | 敵の攻撃を予告し、毎ターン自分で応答する | 正確な情報そのものは面白さではない。予告への応答を失うなら、先見機は検索装置になる |
| [FTL](https://store.steampowered.com/app/212680/FTL_Faster_Than_Light/) | 戦闘中に一時停止して電力・人員・攻撃先を指示する | 危機への一点介入を後述の対抗案として借りる。iPhoneで全指示を再現しない |
| [Monster Train](https://store.steampowered.com/app/1102190/Monster_Train/) | 強化・複製で既存の主力に大きく投資する | 育てた軸の完成を報酬にする。報酬の種類を毎勝利に足す理由にはならない |

ここからの「灰に効く」は推論。人気作の部品を足せば成功するという証拠ではない。JRPGの雑魚戦は作戦と速度で流し、ボスでは手動で判断できることが多い。灰でその差を作らないなら、強い通常戦を速く飛ばすだけになる。

## 4. 考えた四案と一度目の反論

| 案 | 最高の瞬間 | 厳しい弱点 | 今の判断 |
|---|---|---|---|
| A. 既存ループを高速化し、取得予約の節目を見せる | 育てたものが十二戦を駆け抜ける | 退屈な戦闘を飛ばす仕組みだけにもなる。敵が火力の背景に退く | [18](./18-expedition-engine-hypothesis.md)に保存。単独の主案を撤回 |
| B. 幕ごとに大きな「規則＋危険」を一つ選ぶ | 自分で強くした敵が連鎖の燃料になる | 一番安全な組合せが支配し、四戦がまた鑑賞になるかもしれない | **主案として試す** |
| C. 戦闘を止めて一人の行動順を一度だけ早める | 回復前の被弾を防ぎ、倒れる寸前に連鎖を起こす | 毎戦使うなら手動戦術ゲームへ戻る。予測と本番が分かれる | Bに混ぜず、独立した対抗案として測る |
| D. 敵の予告に毎ターン手動で応答する | 一手ごとの盤面パズルが確実に成立する | 十二戦の巡航と自動機構の観察という核を失い、iPhoneで重い | B/Cが不成立なら本格的な別作品として検討 |

## 5. 主案「敵を焚く」の最小ルール

1. 一Stageを現行どおり十二戦・三幕×四戦とする。出発時、4戦目の後、8戦目の後に**二つの提案から一つ**選ぶ。提案には、次の四戦にかかる敵の危険と、遠征中ずっと残る味方の変換規則を短文で併記する。各幕の選択は三回。選んだ提案はその四戦の間固定し、戦前の隊列・主行動・対象・予約の小調整は維持する。第12戦の後はStage終了。
2. 最初の試作では4・8戦目の現行装備二択をこの選択へ**置き換える**。既存の装備を足すなら同じ提案に含め、戦後に別の選択画面を増やさない。第12戦後の次Stage報酬は一Stage試作の範囲外。正式採用するなら装備経済とSPを再設計する。
3. 選択時には危険の内容・敵編成・現在の取得予約を見せるが、両候補について最終勝敗の試算を並べない。確定後に次戦の先見機を使える。選択に未知の乱数や隠し係数を使わない。「この危険を今の機構が利用できるか」を選ぶ。
4. **味方全員→敵全員**の固定順を試作では崩す。各ラウンド、現行の味方並び順と敵並び順をそれぞれ作り、味方一人・敵一人を交互に実行する。片側が尽きれば残りが動く。最初の味方は防壁や準備を張れ、次の敵は攻撃する。行動不能・死亡は順番で飛ばす。これは敵を行動させ、被弾と回復に意味を作るための**大きな変更**であり、難度を再調整する。
5. 大きな規則は既存の「被弾・防壁破壊・敵防壁破壊・命中・撃破」を別の出口へつなぐ。新しい状態名を大量に作らない。同一出来事を自分の出力で再度呼び出す無限循環は作らず、戦闘ログに元の敵行動→味方への作用→変換→追撃を一本表示する。各提案の発火窓・回数・累積は明記する。
6. 取得予約は十二戦を通して維持する。予約が完了した時、メイン行動や優先列が意図せず置換されるなら、採用と技能取得を分けて表示する。強い選択を三回に抑えても、五人の節を毎戦考え直させたら失敗。

### 例。数値は試験用で、実装・均衡の宣言ではない

| 提案 | 四戦の敵側 | 残りのStageで味方側 | なぜ面白い可能性があるか |
|---|---|---|---|
| 砕ける幕 | 各戦の最初の敵行動は前衛へ二回の小打撃。撃破していない敵だけ行動する | 各ラウンド最初に**味方の防壁が壊れた時**、壊した敵に破甲1。一戦の開始時だけ前衛一人に小さな防壁を得る | 防壁が「減らしたくないHPの代わり」から「破ってほしい導火線」になる。薄い防壁・反撃・破甲追撃が接続する |
| 奪う幕 | 各戦、敵二人に小さな防壁が付く。対象のHP・攻撃は大きく上げない | 各ラウンド最初に**敵の防壁を破った時**、味方全体に連携1 | 貫通・多段・対象選択の価値が変わる。前幕の破甲と追撃がそのまま使える保証はない |
| 誘う幕 | 最初の二ラウンド、敵後列の一人は行動後に前列へ移動する | 各ラウンド最初に**移動した敵へ命中した時**、別の敵へ一回追撃する。追撃自身はこの規則を呼ばない | 対象と順序が変わり、同じ自動機構の別の枝が出る。立ち位置が単なる初期設定で終わらない |

これらは「各幕の唯一の正解セット」ではない。実験では各幕に二つの異なる提案を出し、現行の五人がどちらも選び得るか調べる。二択が「防壁ビルドなら常に砕ける幕」に固定されるなら、組合せの余地は偽物。危険と規則が一対一の完全な免疫・相殺にならないよう作る。一方、初見で一方が死に札なら提案しない。

### 十二戦の速度

| 時点 | 主な入力 | 走っている間に確かめたいこと |
|---|---|---|
| 出発 | 予約、最初の提案一つ | 「この危険が私の連鎖を育てる」という仮説 |
| 1〜4 | 原則は続ける。負けそうなら小調整や有限の必殺 | 前衛の盾割れが破甲を生み、その敵を追うか |
| 4勝後 | 次の提案一つ。予約の向きは維持も変更も可 | 違う圧力でも今の機構が働くか |
| 5〜8 | 予測やログを見たい時だけ。通常戦は速く通過 | 敵の防壁が邪魔か、連携を作る資源か |
| 8勝後 | 最後の提案一つ | 二つの持続規則に三つ目がどう入るか |
| 9〜12 | 機構の完成とボス。連勝できれば一気に行く | 以前は痛かった危険を利用して勝てるか |

緊張が必要だからと毎戦正解探しを要求しない。勝ち続けるなら十二戦をそのまま走ってよい。ただし**少なくとも三幕の危険はプレイヤー自身の署名**であり、その選択が戦闘ログ・HP・連鎖の質に観測できなければ案Bは失敗。

## 6. 二度目の反論――自分の案を壊す

1. **わざと敵を強くすると損をするだけ。** 強いビルドは危険を無視し、弱いビルドは挑戦する余裕がない。危険を利用する成功例が複数の育成筋で出なければ撤回する。「強敵だから楽しい」とは言わない。
2. **危険と報酬のセットが答えになる。** 「被弾を増やす＋被弾時に得する」だけなら安全なパズル。提案間の差を、最初の一発、複数戦のHP、相手の順番、ボスへの余力まで含めて判断できるようにする。ただし説明に何画面もかかれば、この案はiPhoneに合わない。
3. **十二戦のうち九戦は鑑賞かもしれない。** ヴァンサバの移動も、スレスパの手札もここにはない。戦闘を見る意味が残らないなら、次の「一度だけ割り込む」対抗案Cか、オートバトルをやめるDを選ぶ。速送りは解決と数えない。
4. **交互手番で難度と技能を全壊させる。** 既存の味方先行を前提にした支援、RP、敵AI、予測が変わる。先に単独比較し、単に全体が苦しくなっただけなら導入しない。敵が動いても持ち物検査になれば意味がない。
5. **三つの持続規則が終盤の怪獣になる。** 規則は幕ごとに一つ。一つの原因に対し一ラウンド一度程度の発火、画面ではその三規則だけを太字で見せる。それでも因果説明ができなければ、持続は次の一幕まで、あるいは古い一つを置換する。強さを惜しんで理解を捨てない。
6. **正確な先見機と無料編集は緑探しを残す。** 選択済みの危険を四戦固定しても、各戦で隊列・対象・採用を試し続けられる。現行先見機はまず保持して実測する。再予測の理由を説明できない反復が常態なら、結果の提示・編集の可逆性・完全オートのどれかを削る。因果表示だけで原理上の問題は消えない。
7. **報酬が勝者をさらに勝たせる。** 強い人だけ有利な危険を選び、以降は圧勝が続く。見送りまたは安全な候補が生存の道として必要かを調べる。ただし自動の難度補正で成功を罰しない。強くなった快感と、退屈な圧勝を別々に聞く。

現状では**Bを作る価値はあるが、成立の証拠はない。** 細かいUI、190節の大量追加、先見機の再生短縮から始めない。約束するのは「三つの判断が十二戦に効く」試作と、それが退屈なら撤回する記録だけ。

## 7. 対抗案Cを独立させる理由

戦闘の次の行動直前に任意で止め、一幕一度だけ、味方一人のまだ残っている通常行動を**その場へ前倒し**する。その人物は元の順番では動かない。追加AP・追加攻撃にはしない。前倒し後の対象・死亡・資源はその時点の盤面で決める。使わずに四戦を抜けてもよい。基準予測は「割り込みなし」の結果だけを示し、割り込みは本戦で確定する。時限の反射入力にはせず、一時停止で考えられる。

この仕組みは「強敵を見て一手だけ変える」という主体性を作り得る。一方、毎戦の使用が義務になるか、割り込みが最も強い火力役の前倒しだけに固定されれば失敗。BとCを初回から同時に入れると何が面白さを生んだか分からない。[21](./21-ignite-prototype.md)で別条件にする。
