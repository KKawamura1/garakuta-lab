# 操舵案を撤回し、三列防衛の成立条件を定義する

更新: 2026-09-28。状態: **未採用の代案／紙上設計**。[技能の紙上検算](./27-stationary-defense-combo-audit.md)と対で読む。現行の戦闘・技能カタログ・物語を変更しない。[24](./24-card-grammar-and-action-defense.md)・[25](./25-five-hero-action-defense-slice.md)の一指操舵案は主案から撤回し、失敗した試行として残す。

## 1. 前案の何が未定だったか

- 「隊の進行方向」と書きながら、隊と敵の初期位置、移動速度、止まる条件、戦場の境界を決めていなかった。両者が常に動くなら、敵を漏らさないために常時操舵するゲームになる。技能予約を思い描く時間より指の操作が主役になりうる。
- 「灰火のHP」は新しい目的物を説明せず持ち込んだ言葉。味方のHP、敵の到達地点、どの条件で勝敗が決まるかも不明だった。
- 「ナギが味方に向かう弾を止める」は守備位置と弾道を指定していない。五人のうち誰を、どの範囲で、何回守るかが決まらず、都合よく全員を守る技能になっていた。
- 二本の連鎖も弱い。火床と弾の幾何は成立する保証がなく、「反射＋貫通」は並んでいるだけの場合がある。独立した戦い方が何通り生まれるかを示していない。

これらは数値調整や「試作で確認」で片づく穴ではない。24/25はゲームの定義として足りなかった。SNKRXは動く英雄集団を操舵する実在のゲームだが、その形式を借りることは、今回欲しい「準備が当たり、しばらく快走する」感覚の根拠にはならない（[公式ストア](https://store.steampowered.com/app/915310/SNKRX/)）。

## 2. 何を先に固定するか

今回の代案は**四人が固定位置を守り、ヒバナだけが決まった二列を巡回し、敵が門へ進む**。プレイヤーは戦闘中、指で隊を操舵しない。時間は一拍ずつ進み、一時停止・早送りできる。配置・取得順は遠征前に選び、順調なら十二波を途中で考え直さずに進める。

[Monster Train](https://www.themonstertrain.com/)は敵が複数の防衛階を通り、抜ければ中枢を傷つけることで「どこで止めるか」を明瞭にする。ただし各ターンのカード選択がある。[Loop Hero](https://store.steampowered.com/app/1282730/Loop_Hero)は自動で進む旅へ地形・敵の札を置くが、旅の途中で札と装備を選び続ける。本案はそれらの常時入力を省いて、遠征前の配置・技能取得予約へ選択を集める。省いた入力が面白さの本体だった可能性は最後に検査する。

## 3. 場所・HP・勝敗の契約

縦長画面に**左・中・右の三列**を表示する。各列には入口側から門側へ距離4、3、2、1の四マスがあり、距離0が全列共通の門。これ以上の高低差、分岐、地形、火床は最小試作に入れない。

| もの | 位置・動き | HPと役割 |
|---|---|---|
| 門 | 三列の距離0。動かない | 試作値8。敵が到達すると通常敵1、ボス2減る。遠征を通して持ち越す |
| ゴウ・ナギ・ゲンゾウ・ツグミ | 遠征前に各人の担当列を選ぶ。同じ列に固定できるのは二人まで。戦闘中に自動では歩かない | 試作値はゴウ6、ナギ5、ゲンゾウ3、ツグミ3。0になるとその波では行動不能。波の終わりに全員全回復 |
| ヒバナ | 遠征前に左↔中、または中↔右の二列を選び、毎拍交互に巡回する。巡回中の列だけで攻撃し、被弾もしうる | 試作値3。倒れたらその波の巡回を止め、次波には復帰 |
| 敵 | いずれかの列の距離4に出現し、原則毎拍1マス門へ進む | HPが0で消える。距離1から門へ入ったら門のHPを減らして消える |

敵が距離1へ来た時、その列に行動できる仲間がいれば、敵は一人（ナギ→ゴウ→ヒバナ→ゲンゾウ→ツグミの固定順）を攻撃し、その拍は進まない。誰もいなければ門へ入る。敵弾は**撃った敵と同じ列**を門へ進み、その列の最初の仲間に当たる。仲間がいなければ門へ当たって1減る。ナギは自分の担当列にいる時だけ、味方や自分へ当たる**その拍最初の敵弾一発**を盾で無効化する。別列の弾は止めない。「味方に向かう」とは、この射線上の仲間のことである。近接攻撃は盾の弾受けの対象外。

勝利は**第12波の全敵が死亡または門へ到達し、門HPが1以上**。門HPが0になった拍に敗北。味方全滅は直ちに敗北とはせず、残った敵が門へ到達すれば敗北しうる。味方のHPと門HPは別物である。「灰火」という未定義の対象は採用しない。これらの数値はバランスの結論でなく、ゲームを紙上で追えるための試作値。

## 4. 一拍の解決順と、プレイヤーの介入

1. 次の敵が距離4に現れる。埋まっていれば入口の外で一拍待つ。
2. ヒバナが指定した隣列へ移り、その列の距離1か2の最も門に近い敵を一回攻撃する。
3. ゴウ、ツグミ、ゲンゾウがこの順で生存中なら行動する。各行動後に対象を選び直す。射撃二人の既定対象は全列で最も門に近い敵。同距離なら左→中→右。新しい対象優先列はない。
4. 敵の遠隔射撃を解決し、ナギの盾をここで一度だけ判定する。
5. 生きている敵が門に近い順に、近接攻撃か1マスの前進をする。敵同士の同じマスへの進入は不可。門へ入った敵を取り除く。

遠征前に四人の担当列、ヒバナの巡回二列、五人の改造A/Bとその解禁順を選ぶ。**一つ目の改造は第1波から**、残りは第2・4・6・8波の後に予約どおり開く。波の間にショップや設定画面を強制しない。第4・8波の後には希望すれば配置と残り予約を見直せるが、見ずに進める。

救済用の仮ルールは、各四波の幕につき**一回だけ**、停止中に二人の固定仲間の担当列を交換する「緊急交代」。次拍から有効、巻き戻し不可、未使用の回数は持ち越さない。常に触る必要はない。門が次拍で0になる見込みの時だけ自動停止して選択機会を示す。この機能そのものが毎幕必須なら、事前の構築に失敗しているので撤回する。

未来視は、次の二拍に**敵がどの列に現れ、いつ動く・撃つつもりか**を表示する。味方の最終HPや第12波の勝敗は告げない。手を入れなければ始まる敵の行動予定だけを確定情報とする。実戦はそのまま進み、予測と本番を二度再生しない。

## 5. まだ解けていない厳しい反論

1. **五人の砲台では。** 四人が立ち、敵を撃つだけでは現行オートバトルより面白くならない。敵の移動、列移動、敵同士の衝突、射撃と守りの受け渡しが、毎回同じ最初の一巡を崩すかを[27](./27-stationary-defense-combo-audit.md)で検算する。
2. **空の列があると毎波着替えになる。** 射撃二人は全列を狙え、ヒバナは二列を巡り、門は少数の漏れを受けられる。なお、配置変更した方がよい敵の列を毎波出すなら失敗。難度でそれを強制しない。
3. **門HPが単なる別の持ち物検査。** 門が削れることは失敗への距離であり、特定の攻撃属性を要求する鍵穴ではない。盾・集中火力・押し戻し・治療による時間稼ぎの複数策が成立しなければ削る。
4. **強い押し戻しで完封。** 押す技能は必ず同時にダメージを与え、敵HPが有限なため、永久に無傷で同じ敵を止める仕組みにしない。それでも全敵を押すだけが最善なら却下する。
5. **12波を眺めるだけ。** 技能開通後の数波を圧倒する時間は欲しい。しかし早送り以外の感情が生まれず、次の解禁順を考えたくならなければ失敗。常時操作を足して救わない。
6. **制作費と物語。** 門を守る理由はまだ物語に接続していない。現行Stageや五人の会話を、この試作に合うと断言しない。独立した小画面で成立してから移植を考える。
