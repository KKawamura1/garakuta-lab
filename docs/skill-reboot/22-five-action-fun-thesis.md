# 五人の一巡を育てる――楽しさから再出発する設計メモ

更新: 2026-09-28。**未採用の再提案。実プレイによる面白さは未検証。** [21までの「敵を焚く」案](./20-ignite-the-enemy.md)は主案から撤回し、批判の履歴として残す。[23の反証試験](./23-five-action-playtest.md)と対で読む。`GAME.md`、実装、190節の正本はまだ変更しない。

## 0. 前案の何を見落としたか

「砕ける幕」は、味方の防壁を割らせるという新しい正解を設定した。防壁が割れないと火力不足になりうるなら、敵の攻撃は代償ではなく発火スイッチである。これは敵の違いに応じた着替え・持ち物検査を別名で作る。提案と危険が同じカードに書かれているので、むしろ正解は読みやすい。

交互手番も、単純に敵の行動を増やす以上の損失がある。現行では先に味方五人の行動が続くため、プレイヤーは**敵の詳細を知らなくても自分の最初の連鎖を想像できる**。それを予約中に「三人目が破甲を付け、五人目が刈る」と思い描くこと自体が遊びである。交互手番はこの像を敵AIと対象変更で途切れさせる。敵が目立つ利益と引き換えに、企画の数少ない確かな快感候補を削る。

前案の反論欄は「危険が自明な最適解になる」「五人の予測可能性を壊す」という、これらの最も強い反論を先に書けていなかった。大きな規則・行動中の割り込み・危険の選択を、もう主案の前提に置かない。

## 1. 楽しさの原点についての仮説

一番欲しい瞬間を次の五段階に分解する。

1. **想像:** 「この節を予約すると、いま三人目で途切れる連携が五人目へ届くかもしれない」。出発前に自分の五手の絵がある。
2. **投資:** その節へ向かう数戦のSPを使う。即座に別の枝へ広げられず、今はまだ敵が一体残る。
3. **兆候:** 途中の技能でも少し連鎖が伸び、前回は二ラウンドかかった敵がもう少しで一巡で倒れる。先見機で実際の動きを見られる。
4. **開通:** 予約した節が開き、残っていた敵へ過剰ダメージや状態が渡る。「先に思い描いたこと」と「実際に起きたこと」が合う。それ以上の連鎖も出ればなおよい。
5. **巡航:** 新しい一巡が以後の複数戦を高速に抜く。少し後のボスで通じなくなっても、次の予約にはもう仮説がある。

快感の式を仮に書くなら、**自分で予想した接続が開く × それが複数戦へ波及する × 予想外の余剰がある**。ここでの「予想外」は隠し仕様ではなく、知っている短い規則が重なった結果。攻撃アニメーションの数や勝利表示だけでは代えられない。

この仮説はユーザーの体験に関する推測であり、一般の心理法則として主張しない。ゲーム研究の[Ryanらの研究](https://selfdeterminationtheory.org/SDT/documents/2006_RyanRigbyPrzybylski_MandE.pdf)は、ゲーム内の自律感・有能感と楽しさの関連を報告するが、灰でこの五段階が成立する証拠にはならない。

## 2. 違うジャンルは何の辛さを引き受けているか

一次資料で確認できる遊びの構造と、こちらの**設計上の解釈**を分ける。各作品の人気やレビュー数を灰の成功根拠には使わない。

| ジャンル・作品の公式説明 | 強い快感に至るまでプレイヤーが引き受けること | 灰で借りられる部分／借りられない部分 |
|---|---|---|
| 自動機械のパズル: [Opus Magnum](https://www.zachtronics.com/opus-magnum/) | 部品を組み、機械が仕事を終えるまで設計し直す。速さ・簡潔さ・小ささも比較できる | 作った連鎖が動く鑑賞は成立し得る。ただし一問に長く設計する遊びを毎戦やればスマホの十二戦には重い |
| 工場: [Factorio](https://www.factorio.com/) | 小さな流れを作り、詰まりを直し、より複雑な生産へ広げる | 取得予約を「数戦先に工場の新しい一列がつながる」約束として使う。常時手を入れる保守は移さない |
| 計画と実行: [Teardown](https://store.steampowered.com/app/1167630/Teardown/) | 壊せる環境で経路を作り、その後は自分で走って計画を実行する | 準備したものが本番で形になる気持ちは近い。灰は自分で走る操作がないので、実行の緊張まで借りたことにはならない |
| タワーディフェンス: [Bloons TD 6](https://store.steampowered.com/app/960090/Bloons_TD_6/) | 防衛の配置と強化をして、迫る敵を観察し、必要なら次の配置・能力使用へつなぐ | 「抜けられるか」という見える閾値と、強化後に以前の波を圧倒する比較。敵ごとの必須装備だけを借りると持ち物検査になる |
| アクションの成長: [Risk of Rain 2](https://store.steampowered.com/app/632360/Risk_of_Rain_2/)・[Noita](https://store.steampowered.com/app/881100/Noita/) | アイテムや呪文の相互作用を育て、敵の圧力が増す中で自分で撃ち、避け、生き残る | 思いがけない組合せと、双方が強くなる長い上昇線。戦闘中の射撃・回避がない灰へ、敵の激化だけを移すと理不尽 |
| FPS: [DOOM Eternal](https://bethesda.net/en-US/news/raze-hell-doom-eternal) | 体力・弾薬・装甲が乏しいときに、異なる攻撃を自分で使い分けて敵から取り返す | 苦しさと突破が同じ行為につながる好例。ただし前案「防壁を壊させる」はここから**プレイヤーの実行判断だけを抜いた**ものだった |
| 規則パズル: [Baba Is You](https://store.steampowered.com/app/736260/Baba_Is_You/) | 決まった盤面の規則を動かし、解法を発見する | 一つの短い規則が世界を変える強さを借りる。各敵に一つの正解を置けば、灰も十二問のパズルになってしまう |
| 自動成長: [Vampire Survivors](https://store.steampowered.com/app/1794680/Vampire_Survivors/)・[Balatro](https://store.steampowered.com/app/2379780/Balatro/) | 小さな取得が多数の攻撃や得点へ広がる。前者は移動、後者は手札を出す判断を続ける | 重要な取得を繰り返し働かせる。ただし両作にある戦闘中／手札の入力は灰にはない |

多くの参照作には、設計後にも行う「撃つ」「避ける」「配置する」「札を出す」がある。灰があえてオートを続けるなら、Opus Magnum型の**完成したものを動かす喜び**と、成長作の**数戦かけた跳躍**に賭ける。それを一回の長いパズルにも、一戦ごとの正解探しにもしないのが最難関。

## 3. 快感に必要な辛さと、減らす辛さ

| 残す・作る辛さ | カタルシスへの役割 | 失敗した形 |
|---|---|---|
| 取りたい節まで二、三戦かかり、その間は完成形で戦えない | 前に立てた仮説と、開通する日を生む | 途中の節が無意味で、ただ待つ |
| 予約する枝を一つ選ぶと、他の枝は今は取れない | 深さか広さの機会費用を生む | 正解の枝だけ強く、選ぶ意味がない |
| 敵のHP・配置・役割が、今の五手での撃破を時々ぎりぎり逃す | 「あと一つつながれば」を具体化する | 特定の技能を持たないと詰む |
| ボスが一巡を耐え、敵の行動で初めて守りと持越資源を問う | 完成した火力と、まだ足りない守りの両方を見る | 味方の初動を毎回妨害するだけ |

減らす辛さは、毎戦のON/OFFと隊列調整、隠れた処理順、微小な係数を大量に読む時間、予測の緑を探すための無理解な試行である。**敵を先手で倒して一度も攻撃させない勝利は許し、強い瞬間として祝う。** それを防ぐために敵へ先制を配らない。

## 4. 主案「五人の一巡」を育てる

現行の味方五人→敵、十二戦、予約、一戦先の正確な試映はまず維持する。変える優先順位は以下。

1. **報酬の中心を、五手のつながりが目に見えて変わる節へ寄せる。** 一Stageで手に入る「見せ場」の節は、攻撃対象、余剰ダメージ、状態の受け渡し、追撃の順番など、五手の絵のどこかを変える。単なる+15%を全部禁止する必要はないが、連続した取得が係数節だけなら失敗。190節の一律実装を急がず、少数の枝をまず作り直す。
2. **予約は「この技能が手に入る」で終えない。** 選んだ節と前提の三段程度を、五人の今の一巡へどうつながるつもりか想像できる形で見せる。ゲームが正解の組合せを薦めたり、将来の勝敗を計算して予約を代行したりはしない。
3. **十二戦は一つの演奏として扱う。** 勝利後の取得は予約に従い進む。問題がなければ次戦へ軽く進み、目当ての技能が初めて発火した回だけ実際の因果列を少し強く見せる。ボスや本人の停止でしっかり考える。戦闘を飛ばせる速さは必要だが、編集頻度を上げる仕組みは増やさない。
4. **敵は持ち物検査ではなく、五手がどこまで通るかを変える。** 小型が三体、硬い前衛と脆い後衛、回復が間に合う敵、ボスの高耐久など。どの枝も全敵に万能である必要はないが、「その技能を持っていなければ負け」にはしない。敵を一巡で沈められれば爽快で、残れば何が残ったかが次の育成仮説になる。
5. **同型の相手を二度置く。** たとえば序盤で前衛を残された布陣が、より強くなって後半に再登場する。予約の開通後にどう一巡が変わったかを測る物差しにする。十二戦を同一相手の反復にはしない。

### 小さな架空例（既存実装の保証ではない）

第2戦。二人目が前衛Aに破甲を付け、三人目がAを殴り、五人目がAを倒す。Bが残り、敵の手番になる。プレイヤーは、目標として予約した「倒した敵に残った破甲を次の敵へ渡す」と、その前提となる「撃破の余剰ダメージを次の敵へ渡す」を考える。第4戦で前提が開くと余剰がBを削るが、そのHPは少し残る。第6戦で目標も開くと、Aから破甲と余剰ダメージを受けたBも倒れ、予想外に弱いCまで届く。元の攻撃の余剰を敵ごとに消費するため、敵の数を越えて続かない。

ここでは敵にわざと自分の防壁を壊させていない。いつもの五人の動きが成長した。後でボスが一巡を耐えると、同じ枝の火力を上げるか、守りの接続を予約するかに新しい迷いが生まれる。スキル名・対象・数値は実装契約ではなく、**先に思い描ける変化／実際に届く変化**の例。

## 5. 反論を先に立てる

1. **「これも現行のままでは？」** 五人の順と予約を守る点はそう。違いは技能カタログ、報酬の節目、十二戦の見せ方に絞ること。現行の20実装済み節と今の報酬でこの五段階がすでに体験できるなら、文書だけの美化である。[23](./23-five-action-playtest.md)で現行と少数の大胆な節を比較する。
2. **「結局ずっと見るだけでは？」** あり得る。完成した機械を見るのが楽しいのは、事前に本人がその機械を考え、違いを認識できたときに限る。取得直後を一度見て残りを全部飛ばす場合、それでも次の予約を楽しみに進むかを測る。進みたくないなら完全オートを守るために演出を足さない。
3. **「毎回同じ最初の五手で敵が空気になるのでは？」** 強くなった結果としての数戦の圧勝は欲しい。十二戦を通して同じ敵の姿しか記憶に残らず、ボスも一巡の倍率だけなら失敗。敵を先制させるのでなく、配置・残HP・再生・撃破順で五手の結果を変える。ただしこれが毎戦の対象変更作業に化ければやはり失敗。
4. **「途中のSP取得は待つだけでは？」** その通り。前提節も働き、開通前の一巡に少しずつ変化を出せる構造でなければ、予約は退屈の延期。深い終点まで何戦かかるかと、その間の実際のイベントを検証する。
5. **「正確な先見機は勝敗検索になるのでは？」** 解決していない。入力の候補が多く無料なら、結果を見て調整できる。予測画面の色や説明を変えるだけで原理的には治らない。無理解な再予測が頻発すれば、無料編集・結果開示・自動戦闘の組合せ自体を削る決断が必要。
6. **「五人の連鎖が本当に読めるのは序盤だけでは？」** 取得した節が25〜40になる頃、頭では追えない可能性が高い。見せ場になる規則が三、四本でも追えないなら、技の追加数、RPの競合、ターゲット優先列を削る。ログで隠して正当化しない。
7. **「正解の予約が一つになるのでは？」** 火力の直線投資だけで十二戦を越せるなら、枝選択は儀式。近い将来の一巡突破と、ボスを耐える守り、横へ伸ばす次の接続に、複数の合理的な道があるかを測る。敵を特定技能への鍵穴にして分岐を作らない。

最も厳しい反論は**「五手の予想と開通が、スマホで十二戦遊ぶほど楽しいか」**である。Opus Magnumなら一問を長く考えられ、Vampire Survivorsなら移動を続けられる。灰は双方を薄くした可能性がある。十二戦のテストで目当ての開通を待つ感情が生まれなければ、戦闘数を削るか、オート自体を捨てる。守るべきは現行仕様ではなく、その瞬間の強さ。
