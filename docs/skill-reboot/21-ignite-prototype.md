# 「敵を焚く」の反証試験――十二戦で本当に遊べるか

更新: 2026-09-28。状態: **未実装の小試作計画。** 親文書: [「敵を焚く」](./20-ignite-the-enemy.md)。この計画の数値は調査の足場であり、統計的な成功基準ではない。現行の正本は `docs/GAME.md` と実装。

## 0. 先に予想しておく失敗

危険を選ぶという一手は魅力的に聞こえる。しかしプレイヤーが実際には「盾のチームだから盾を壊す提案」だけを選び、先見機で緑を確認して、十二戦を早送りするなら、前の案から面白さは増えていない。別の失敗は、交互手番で敵が動くようになっても単に長く苦しいだけになること。**プレイ前にこの二つを失敗と書いておく。**

## 1. 最小の実験単位と比較条件

原則は現行の一Stage、十二戦、4・8・12のボス、4・8後の回復、SP/取得予約、五人、決定論、有限の必殺を保つ。試験用の敵は三種類の圧力（小打撃、防壁、移動）と混合、既知の敵が一度再登場する計十二編成。危険の規則は**一戦内で実際に起こる**こと。既存の敵の数字を一律上げただけの試験をしない。

| 条件 | 変更 | 分かること |
|---|---|---|
| P0 現行 | 現行の進行・手番・装備報酬・先見機。試験用の同じ敵編成を可能な限り当てる | 退屈、強さ、予測編集、十二戦の所要時間の基準 |
| P1 手番のみ | 味方一人・敵一人の交互手番。報酬は現行のまま。敵のHPと攻撃をP0と同じにして始め、明らかな破綻だけ記録して調整する | 敵に手番を渡すだけで違いが出るか。単に負けやすくなるだけか |
| P2 主案 | P1の手番に、出発時・4・8戦目後の二択「敵の危険＋味方の変換」を入れる。装備二択をそのパネルへ置換し、十二戦の強さを調整 | 三つの選択が、四戦の巡航と危険を食う爽快さを両立するか |
| P3 一度だけ割り込み | P2に一幕一度の行動前倒しを追加。追加行動はない。未使用ならP2と同じ | 戦闘の参加感が増すか、それとも四戦ごとの手動義務になるか |

P0とP1は同一の敵・技能を使うが、P2の危険とP0の既存装備報酬は同じ強さにはならない。**勝率だけを比較しない。** 戦う理由、入力の数、異なる連鎖、説明可能性を合わせて見る。P3を最初から主案へ混ぜない。P2が退屈でCが救う場合は、B+Cの新案として改めて設計する。

## 2. 実装する内容の上限

- 五人それぞれ最終的に短い技能5〜8個程度。現行の実装済み節とカタログ上の190節を区別する。初回の動作確認は少数でよいが、**終盤に五人で25〜40節が動く**試験を行わずに理解可能と判定しない。
- 基本となる三つの育成筋を用意する。例: 防壁を割らせて反撃する、敵防壁を破って連携する、敵の移動を読んで後列を狙う。どれも二つ以上の提案を取れるようにする。特定の技能を持たないと四戦を突破できない配置は除く。
- 各幕二候補、計六つの提案を試作する。双方とも発火する具体的な機会があること。危険は四戦だけ、変換はStage末まで積み上がる。三つの変換が同時に動いても一つの出来事に対し無限再帰しない。再帰防止を黙った全体上限に隠さず、技能文に元となる出来事と「追撃では再発火しない」等を表示する。
- 提案以外の戦間UIはまず現行で測る。先見機の結果表示・設定変更・予約の挙動もまず残す。連戦確定、予測の結果採用、スキップ仕様、報酬抽選はこの実験に一緒に足さない。
- 仮に交互手番の実装コストが高ければ、先に紙・イベントログ用の同一十二戦を使ってプロトタイプを作る。画面映えのための演出は因果が成立してから着手する。

## 3. プレイヤーの二つの視点で記録する

同じ人にP0からP3を順に全部遊ばせると学習が比較を歪める。複数人なら条件順を入れ替え、初回プレイと既習プレイを区別する。一人でも先に紙上で自分の最適解を決めず、各条件で「最初の意図」「戦いの途中で予想と違った箇所」「次の四戦の期待」を声または短文で残す。少人数なので数字の有意差を装わない。

| 記録 | 具体的な問い |
|---|---|
| 入力負担 | 開始時と4・8勝利後の選択秒数、戦前編集数、予約変更、各戦の予測回数、一Stageのメニュー滞在時間 |
| 巡航 | 編集なしで進んだ最長連続戦数、早送りした戦闘数、「もう一戦」と自発的に進んだ回数、離脱した位置 |
| 主体性 | 選んだ危険をどう利用するつもりだったか、実際どの敵行動が入力になったか、一番見返したい戦い、割り込みを使った理由 |
| 因果 | 直後に「敵の一手→味方の防壁／状態→誰の追撃→HP」の筋を説明できるか。ログを見た後にも説明できないか |
| 選択の質 | 二候補を比べた理由。強い育成筋で同じ提案ばかり選んだか。予約で次に取りたい節に迷いがあったか |
| 敵の存在 | 同じ編成のままでも、敵三種類に対し違う損失・順番・発火が出たか。予測の最終HPだけを覚えていないか |
| 緊張と快感 | 「自分が選んだ危険が逆に決め手になった」具体的な戦いはあるか。圧勝の楽しさと空虚さを分けて聞く |

戦闘ログには、提案の発火元、対象、失った防壁・HP、増えた状態、派生行動、発火しなかった理由、最終損失をイベントIDで結ぶ。ログの本文を読むことを前提にしない。画面では一戦に二、三本の因果を指で辿れる程度に絞る。発火しなかった理由を実装で記録していない場合は憶測で表示しない。

## 4. 判定を甘くしない仮の停止条件

数値は小規模テストの注意信号。プレイヤー数、難度、戦闘速度で変更し得るが、結果を見た後の後付け合格にしない。

1. **危険を食った場面がない:** 一人の十二戦で、本人が「この提案を選んだからこの敵の行動が燃料になった」と因果つきで挙げられる戦いが二戦未満ならBを疑う。全員が演出だけを覚えるなら撤回。
2. **まだ受動的:** P2でも戦闘をすべて飛ばしたくなり、P0と比べて進みたい理由・見返したい場面が増えないなら、二択だけでは足りない。P3の任意割り込みを検証し、それも重いなら完全オート自体を再検討。
3. **緑探し:** 通常戦の過半で結果表示を見てから二回以上設定を変え、勝利への変化を本人が説明できないなら、現行先見機を含むループに赤信号。提案選択を四戦固定しても治っていない。
4. **着替えの強制:** 三つ以上の通常戦で主行動・対象・隊列・技能の組替えを迫られる、または特定技能の未取得で詰まるなら、十二戦巡航の目的に反する。
5. **選択が偽物:** 異なる三育成筋でも、同じ候補が毎幕の「正解」になる。あるいは説明なく危険の小さい方だけが選ばれる。敵と報酬を調整して再試行し、それでも同じならBの構造を諦める。
6. **終盤の怪獣:** 最後のボスで、本人が三つの提案のどれが勝敗に効いたか言えず、短いログを見ても分からない。人数全員で起きるなら、提案の数・期間か反応技能数を減らす。
7. **爽快さが数値だけ:** 第10〜12戦で勝ちが速くても、初幕と同種の攻撃を単に倍率で上書きしただけなら、規則変更の報酬としては失敗。
8. **割り込みが毎回の義務:** P3で各幕の使用位置がいつも第一戦の最大火力役、または常に第4戦のボスまで温存して同じ火力役になる、あるいは使わないと通常戦を越せないならCは削る。温存と介入の両方に理由が必要。

逆に、一人の発言が面白くても成功宣言しない。複数の育成筋で「危険を選んでから四戦進めた」「機構を説明できた」「次の幕でも試したい」が揃うかを見る。勝率、所要時間、快感の三つを一つの点数へ潰さない。

## 5. 失敗したらどう進むか

| 観測 | 次の設計判断 |
|---|---|
| P1から敵の個性が増え、P2が余計なメニューになる | 幕ごとの提案は捨て、交互手番と少数の大きな技能だけを残す |
| P2で危険を利用した興奮はあるが戦闘が鑑賞になる | P3を試し、一幕に一度の割り込みが自発的に使われるか確認 |
| P2で常に一候補が勝つ | 二択の係数調整だけで済ませず、危険と変換の結び付き方を再設計。勝者だけが得をする加速なら案を捨てる |
| P2/P3ともに無理解な予測検索が多い | 一戦先の最終結果表示と無料編集の同居をやめる方向を決める。候補は短い先見・編集確定・完全オート廃止などだが、黙って試行回数の罰金を足さない |
| 戦闘入力の面白さだけが残る | 十二戦オートの前提をやめ、少数の手動戦闘を中心とした別作品案Dへ移る |

## 6. 実装と引継ぎの境界

このPRでは**文書だけ**を更新する。提案はスキルツリー・敵AI・報酬・先見機の互換性を大幅に変える。採用前に現行 `docs/GAME.md`、`docs/ARCHITECTURE.md`、Stage教材や保存形式を書き換えない。P1/P2を実装する場合は別PRで、同じ `BattleInput` からの決定論、先見機と本番のイベント一致、戦果・SP・HPの一度きりの精算、保存復帰、再帰の有限性、四戦をまたぐ提案の期限と累積を検証する。既存の手番・装備・予測のテストが落ちるなら期待値を理由つきで更新する。

再開時に最初に行う作業は、十二戦のテスト敵三種類、六つの提案、三つの育成筋の紙上定義を**一画面の戦闘ログ**へ落とし、P1の手番だけで敵が本当に「入力」になるか確かめること。190節を先に作らない。
