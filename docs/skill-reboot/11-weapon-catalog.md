# 武器ツリー・カタログ案 — 10武器 × 19節（全面改稿）

更新日: 2026-09-22
状態: **PR #288で10武器190節をplayer registryへ接続し、初期ロードアウト・敵技能分離・pack分離・取得予約の基盤を検査済み。最終係数・プレイ感・UI表示は未検証。**
前提: `10-weapon-tree-reboot.md`

## 0. 読み方

全武器を同じ19位置で書く。

- `R`: 通常は1SPを払って入る代表アクション。ただし人物ごとの代表武器2本では、初期技能として無料で持つ。
- `A → AA`: その武器で最も単純な王道。無条件中心で、読んだ通りに強くなる。
- `A → AB`: 王道から分かれる、範囲・回数・攻防配分の扱いやすい応用。
- `B → BA`: 条件と他武器への連携。
- `B → BB`: その武器で最もトリッキーな規則破り。
- `A3 / B3 / AA3 / AB3 / BA3 / BB3`: 親の主軸を置き換えるアクティブ形態。

| 種類 | 解決規則 |
|---|---|
| アクティブ | 選択中のメインアクション一つだけ。APごとに同じ主軸を再評価する |
| リアクティブ | 指定eventで優先列を上から検査し、その人物で最初に成立した一つだけ発動してreturnする |
| ターゲット | 対象問い合わせ時に優先列を上から検査し、最初に有効候補を返した一つだけ使う |
| パッシブ | 条件を満たすものをすべて適用する。反応窓を消費せず、早期returnしない |

各リアクティブには`発動後に残すRP`を設定できる。現在RPから費用を引いた値が留保未満になる技能は飛ばして
次を検査する。頻出RP1を取りつつ、後で起きるRP2の蘇生や完全防御を予約できる。

ターゲットは複数取得でき、優先列の上から最初に候補を返せた規則を使う。どれも成立しなければ
単体攻撃は最も近い有効な敵を狙う。非攻撃アクションは各Rに既定対象を書く。
各アクティブ本文の「最も近い」「最も遠い」「HP割合最低」は、固定対象と明記しない限りfallbackであり、
成立したターゲットがあればそちらを先に使う。

攻撃の既定射程は近接である。近接は前列から使うと最終ダメージ125%、後列から使うと40%になり、敵前列が
生存する間は敵後列を候補にできない。長射程・遠隔は使用位置の減衰なしで敵後列も候補にできるが、敵前列越しの
後列攻撃は遮蔽で75%。支援は味方への距離減衰を受けない。係数は量だけを決め、例外は各武器の「射程」に明記する。

アクティブ形態以外は出身武器を発動条件にしない。攻撃、基礎hit数、射程、準備、回復、防壁、移動などの
行動特性が一致すれば、別武器の主軸でも発動する。hit由来の状態・固定値・防御無視は原則1行動1回、割合補正は
一行動の合計へ一度だけ適用し、多段へhit数倍しない。

割合、回数、状態段数は比較用の仮値である。ただし確率は使わない。「しやすい」は、優先、固定値、回数、
閾値、確定付与のいずれかへ書き換えている。


### 0.1 PR #288で固定した実装境界

このカタログの190節は、PR #288でプレイヤー武器技能registryへ接続した。実装で追加・確定した境界は次のとおり。

- 10武器すべてを19節のcontentとして保持し、manifestは遠征中に利用できる武器だけを選ぶ。技能レベルmapや旧共通packツリーは使わない。
- 各人物の初期ロードアウトは代表武器2本のR＋A1。Rはactive候補2つ、A1はpassive2つで、初期reactive／targetは空。activeはその中から一つだけ選ぶ。
- 敵のactive／reactive／passiveはプレイヤーの表から分離した敵専用registryに置き、敵actorが参照する定義だけを残す。敵技能をこの190節へ足さない。
- 装備packと武器技能packは別registry・別manifest欄にする。UIの一体表示は見せ方のaliasであり、解禁対象と装備抽選の正本は分ける。
- 取得予約は一人一目標。前提を飛ばさず、SPが揃えば前提から順に解禁する。旧saveの移行、旧技能レベルの復元、解禁の払い戻しは行わない。

したがって、以下の表の「R」は通常取得時には武器への入口（1SP）だが、上記の代表武器2本では初期技能として無料で持つ。

この境界は `analysis/ecology-weapon-loadout-smoke.mjs` で、初期4技能、敵registryの使用集合、装備／技能packの種別分離を検査する。

### 0.2 実装契約・表示用効果文・フレーバー

各節には三種類の文章を持たせる。

- **実装契約:** event名、固定順、fallback、資源の生成禁止など、予測と実戦を一致させるための完全な規則。
- **表示用効果文:** プレイヤーが取得判断に必要な対象、条件、量、期間、費用、上限だけを書く。event名、内部ID、
  固定マス順、別節を自動適用する説明は書かない。
- **フレーバー:** 効果を言い換えず、その武器や人物の手触りを短い文章で伝える。

フレーバーの格もツリーの深さに合わせる。ルートと浅い節は動作や手触りを短く言い切り、中層のA3・B3は
戦い方や人物の声が見える一文にする。四枝の終端AA3・AB3・BA3・BB3は、前半で光景や覚悟を描き、後半を
決め台詞にする二行構成とする。表では文の境目へ`<br>`を置き、実UIでも同じ位置を優先改行として扱う。

アクティブの置換元、種別、枝、射程、RP費用、ラウンド／戦闘回数は共通UIのタグでも表示する。とくに
「○○を置換」は効果本文へ重ねない。表では比較できるよう費用と回数も表示文へ残すが、実UIではタグとの重複を
避けてよい。

### 0.3 状態と仮数値の共通基準

腕力・技術50前後を基準にすると、固定防御1は100%攻撃へ約2%、200%攻撃へ約1%しか影響しない。条件付きの
一節が成立しても結果がほぼ変わらない値は置かない。今回の初期目安は、固定防御の浅い増減6〜10、単体防壁15〜30、
一行動の割合補正15〜30%とする。防御は**hitごとの固定軽減**なので、多段への価値は単発より高い。

| 状態 | 表示上の共通効果 |
|---|---|
| 怯みN | 次の主軸が与えるダメージ・回復・防壁-N×15%。解決後に全消費。上限3 |
| 隙N | 次に受ける攻撃ダメージ+N×15%。被攻撃後に全消費。上限3 |
| 集中N | 次の主軸が与えるダメージ・回復・防壁+N×15%。解決後に全消費。上限3 |
| 裂傷N | ラウンド終了時に固定ダメージN×5を受け、その後1減る。上限6 |
| 観測N | Nラウンドの間、全味方の攻撃で軟優先される。ラウンド終了時に1減る |
| 移動不能N | 移動または位置交換を一回無効にして1減る |


### 0.4 応急手当型の副接続

この改稿では、各武器に副接続を置くが、リアクティブの数や発動eventを揃えない。副接続は、主軸の倍率を上げるだけでなく、被弾・対象指定・準備開始・移動・撃破などの出来事を、武器らしい別の出口へ変える節である。

- 取得中の武器や選択中の主軸を条件にしない。別武器の主軸でも、行動特性とeventが一致すれば発動できる。
- 同じ武器内でも、A→AA／A→AB／B→BA／B→BBの役割を一文で説明できるようにする。リアクティブが多いこと自体を価値にしない。
- 発動条件、RP費用、チェイン／ラウンド／戦闘上限、空きマス、対象生存などを明記する。不成立時にRPだけを失わせない。
- 同じ`damage_taken`を読む場合も出口を変える。戦槌は怯み付き反撃、射出器は援護照準、医療具は単体／全体回復、大盾は被害分散、双刃は裂傷付き反撃とする。

| 武器 | 副接続の中心 | 読む出来事 | 主軸と異なる出口 |
|---|---|---|---|
| 戦槌 | 打ち返し | 味方への被弾 | 攻撃者への反撃＋怯み |
| 格闘具 | 流し身 | 自分への単体攻撃 | 被害軽減＋後退 |
| 射出器 | 援護弾 | 味方への被弾 | 攻撃者への援護射撃＋観測 |
| 医療具 | 応急手当／連携治療 | 味方の危険域への被弾 | 単体回復／高コスト全体回復 |
| 大盾 | 痛みの肩代わり | 味方への単体ダメージ | 被害の一部を自分へ移す |
| 長槍 | 迎え槍 | 味方への被弾 | 反撃＋移動不能 |
| 鉤縄 | 引き戻し | 前列の味方への対象指定 | 退避＋被害軽減 |
| 双刃 | 返り刃 | 味方への被弾 | 反撃＋裂傷 |
| 号旗 | 遺志の号令 | 味方の撃破 | 全員への集中＋AP |
| 重弩 | 迎撃照準 | 敵の準備開始 | 先制射撃＋怯み |

この表は最低数のノルマではない。医療具のA→AAのように複数の反応を必要とするルートもあれば、重弩のB→BAのように一つの反応を軸にした方が完成するルートもある。

## 11. 十武器を横断する構成の種

「同一人物」は一つの主軸と他武器のターゲット／パッシブ／リアクティブを組み合わせる。
「分担」は複数人物が別々の主軸を持つ。主軸を二つ同時装着しない。

| 構成 | 担当 | 接続 | 何が起きるか |
|---|---|---|---|
| 構え狙撃 | 同一人物 | 長槍＋射出器ターゲット | `構えを刺す`と`準備を抜く`を並べ、未行動か準備中かを敵編成ごとに優先する |

| 代償の解決が無条件の完全上位になっていないか | 修正済み | 帰還には空きマスと2節、後退には撃破、返済免除にはRP2を要求する。医療具B→BAは全体防壁と再生で安定させる一方、B→BBは防壁を消費して回復するため次の被弾に弱く、重弩は被弾耐性を得ても対象死亡による不発を残す |
| 資源を作る節は消費先がなくても役立つか | 修正済み | 破片=防御+6/個、型=最大+24%、射順表=軟優先、血へ還す／返血=防壁をHPへ変換、鏡=被ダメージ-8%/個、二点固定=防壁/隙、予約刃・時砂=+5%/個、次弾=対応武器の強化として、深い消費節なしの出口を持たせた |
| 条件外に主軸が停止しないか | 修正済み | `指定射`、`無手`、`網場`、`千客万来`、`急かす`、`緊急蘇生`、`最後の号令`、`三時射`に親主軸または基礎攻撃へのfallbackを明記した |
| 発生源と消費主軸を同時に使えるか | 修正済み | 双刃の予約刃を「自分の非攻撃主軸」から「味方の非攻撃主軸」へ変更。主軸切替なしで`差し刃`と`千客万来`を使える |
| AP・RP・追加解決が自己増殖しないか | 修正済み | 号旗同士のAP受け渡しを禁止し、重弩の追加解決は次弾を生成せず、`未来撃ち`をラウンド1回にした |
| 初期ロードアウトの意味が曖昧でないか | 修正済み | 各人物は代表武器2本のR＋A1を初期保持する。Rはactive候補2つのうち1つだけを主軸にし、A1はpassiveとして両方有効にする |
| プレイヤー技能と敵技能が混ざらないか | 修正済み | player registryは10武器190節、敵は敵actorが使う定義だけの別registryとし、相互参照を検査する |
| 装備packと技能packが同じ解禁集合にならないか | 修正済み | `enabledWeaponIds`／`enabledSkillPackIds`と`enabledEquipmentPackIds`をmanifestで分離し、UIの統合表示だけaliasにする |
| 技能レベルや旧save互換が残っていないか | 修正済み | 節の前提は取得済みIDだけ、レベルmapと旧形式の移行は削除し、現行version不一致は読み込まない |
| 取得予約が新しい節構造でも成立するか | 修正済み | 一人一目標をrun stateへ保存し、SPが揃えば前提から順に解禁する。予約の差し替え・取消しも可能にする |

追加で、自動戦闘なのに手動選択を要求していた空きマス・列指定を固定規則へ置換し、廃止済みの速度を
号旗から除いた。格闘具の消えて育たない連携、双刃の同時利用できない予約刃、条件外に停止する主軸、
上限のなかった射出器の照合も修正した。

節数はアクティブ70、リアクティブ36、ターゲット9、パッシブ75の合計190。十武器すべて19節を維持する。

### 12.1 ルート要約 — 取得理由を一文で言えるか

各ルートは、能力・面白さ・主な強み・主な弱みを一文で説明できることを目標にする。A→AAは直球の完成形、A→ABは性質変化、B→BAは条件と連携、B→BBはルール改変として読む。ただし、リアクティブの数は武器ごとに異なる。

| 武器 | R | A→AA | A→AB | B→BA | B→BB |
|---|---|---|---|---|---|
| 戦槌 | 近い敵を重く叩く。単体には強いが近接限定。 | 単発火力と怯みを伸ばす正統派。集団と防壁に弱い。 | 単体打撃を列攻撃へ変える。雑魚に強いが単体火力は落ちる。 | 防壁・受け構えを壊し、次の味方へ火力を渡す。強化敵向け。 | 敵の強化を破片として蓄え、一撃へ圧縮する。準備型で敵依存。 |
| 格闘具 | 近距離で殴り続ける。前衛リスクあり。 | 多段化・防御無視で手数を極める。硬い単発防御に弱い。 | 受け流し・退避・防壁で殴り合う。攻撃力はやや落ちる。 | 同じ敵を追い続け、撃破で前後移動する。対象変更に弱い。 | 味方の主軸や強化を借りる。柔軟だが味方とRPに依存。 |
| 射出器 | 遠距離から対象を選んで撃つ。後衛から安定する。 | 単発・防御無視の狙撃。硬い敵に強いが単体限定。 | 連装と援護弾で手数と支援を両立。最大単発火力は落ちる。 | 観測した敵を味方全員で狙う。標的管理が面白いが観測依存。 | 敵の行動順を記録し、順番どおり撃つ。順を崩されると弱い。 |
| 医療具 | 味方に防壁を張る。安定するが直接回復しない。 | 単体回復と高コスト全体回復で継戦する。多人数被弾に強いが即死と戦闘後HPに弱い。 | 単体回復の発動条件を緩める。集中攻撃に強いが全体攻撃に弱い。 | 全体防壁と再生で隊を安定させる。防壁貫通に弱い。 | 防壁をHP回復へ変換する。雑魚に強く、ボスに弱いルール改変。 |
| 大盾 | 自分に防壁と誘引を張る。攻撃を集める。 | 被害分担と自己防御を極める。攻撃機会を失いやすい。 | 防壁を味方全体へ広げる。広域攻撃に強いが単体特化ではない。 | 受けた攻撃を守勢・回復・味方支援へ変換する。被弾が必要。 | 鏡で攻撃を無効化・回復する。大技に強いが多段攻撃に弱い。 |
| 長槍 | 遠距離の敵を直線で突く。位置取りが重要。 | 距離・防御無視・貫通を伸ばす。硬い後衛に強いが近距離に弱い。 | 多段・列攻撃・移動不能で敵を止める。状態異常耐性に弱い。 | 準備中の敵や移動する敵を迎撃する。条件外では平凡。 | 行動順を奪い、割り込みや手番交換を行う。強いが空振りの代償が大きい。 |
| 鉤縄 | 敵を引き、位置を変える。盤面操作が本体。 | 強制移動をダメージへ変える。動かせる敵に強く、固定敵に弱い。 | 味方を救助・退避させ、防壁を張る。攻撃力を犠牲にする。 | 移動した場所へ印を残し、敵味方を踏ませて効果を起こす。準備型。 | 行動者を記録し、位置を巻き戻し、隊列を入れ替える。強力だが不安定。 |
| 双刃 | 2hitで傷を刻む。手数と位置取りが重要。 | 前進・多段・後退で高火力と安全を両立。空きマスと防御に弱い。 | hitごとの対象変更と余ったhitの転送で集団を処理する。 | 裂傷を蓄積し、被弾時にも裂傷反撃する。長期戦向け。 | 味方の非攻撃行動を刃へ変換する。編成シナジーが強いが準備が必要。 |
| 号旗 | 味方へAPを渡し、自分の一拍を隊の行動へ変える。 | APと次行動強化を安定供給する。味方の行動価値に依存。 | 味方撃破から再編し、近接役を前へ出す。逆転力は高いが条件が重い。 | 準備を進め、APを前借りする。爆発力の代償として借金が残る。 | 時間・砂時計・最後の号令で戦闘ルールを変える。短期戦には薄い。 |
| 重弩 | 準備して大きな一発を撃つ。準備中が弱点。 | 単体高火力と防御無視。ボス向けだが遅く、妨害されやすい。 | 溜め攻撃を列攻撃・怯みへ変える。集団向けだが単体火力は落ちる。 | 敵の準備を迎撃し、着弾印や起爆へつなげる。敵が動かないと弱い。 | 次弾を蓄積して未来の射撃を前借りする。最大火力は高いが不発リスクが大きい。 |

この表で一文にできない節は、数値不足ではなくルートの出口不足として再設計する。

### 12.4 実装後に数値試験する残課題

- 腕力・技術50の100%／200%／400%攻撃へ、防御増減6・8・10・16を当て、浅い一節が結果を概ね10%以上動かしつつ、高係数単発を無効化しないか。
- 1／2／4／6hitの同じ合計基礎量へ防御を当て、hitごとの固定軽減と一行動合計の防御無視6・8・12・16を比較し、多段への対策と多段だけが得をする貫通の両方を避けられるか。
- 怯み・隙・集中を1〜3段、裂傷を1〜6段で比較し、状態を重ねる投資が強すぎず、1段でも戦闘ログ上の差が見えるか。
- 医療具のA→AA（単体＋全体回復）、A→AB（条件緩和）、B→BA（全体防壁）、B→BB（防壁変換）を、単体大攻撃・全体多段・防壁貫通・雑魚連戦・ボス戦で比較し、四ルートが互いの下位互換にならないか。
- A→AAの無条件パッシブを全取得した時、終端アクティブの実効値が他枝を消さないか。
- 単発・2hit・4hit・6hitへ同じ横断節を積み、1SPと経路SPを含む同投資で期待ダメージと状態付与回数が一つのhit帯へ偏らないか。
- 前列近接、後列近接、前列を攻撃する遠隔、前列越しに後列を狙う遠隔を同じ能力値で比較し、125%／40%／100%／75%が被弾リスクと対象価値に釣り合うか。
- ターゲットを借りる1SPが、後列の重要敵を狙える遠隔武器だけに偏らないか。
- `駆け込み`単体の前列残留が十分な代償で、`引き足`取得後の安全な往復が火力節一つ分に見合うか。
- `揃い足`の一時出撃が、号旗自身の攻撃一拍を捨てる価値に見合うか。
- 反応優先列がRPを使い切る順番を、戦闘予測とログから説明できるか。
- 3、6、10ラウンドの固定標本で、人物別RP消費率が通常60〜90%に入り、条件不成立による未使用が40%以上続かないか。
- 頻出反応へRP留保を0・1・2と設定した時、上位の緊急反応の発動率と通常反応の消費率が意図どおり交換されるか。
- `総入れ替え`や`時穿ち`が、予測と本番で同じevent順を返し、無限連鎖を作らないか。
- 3、6、10ラウンドの固定標本で、戦闘1回以外の各取得節が二度以上結果へ寄与するか。
- 全190節で、表示用効果文だけを読んだ取得判断と実装契約から得られる結果が一致するか。event名、固定順、置換元などは詳細表示またはUIタグだけへ出るか。
- 390px幅を含む実機相当表示で、効果文が一覧の比較を妨げない長さか。長い条件は詳細へ畳み、フレーバーは原則1〜2行で読めるか。
