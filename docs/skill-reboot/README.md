## 解決順の全技能監査（提案）

55個のパッシブを再監査し、同hit内で条件を奪い合う戦槌「砕けた鎧」「砕け音」だけをリアクティブへ変更した。両者はhit前の防壁・受け構え解除後と各hitの防御結果後に共通防御崩し窓を使い、優先列から一つだけ発動する。効果量だけを先行確定値から計算する近接+15%や単体+15%はパッシブに残す。二拍先はAP対象の確定後にRP1で+1し、借り札は借りを付けた対象へ高揚1を与える。借りは支払えるAPの分だけ返済し、残りを持ち越す。

[190技能の解決順監査](./12-resolution-order-audit.md)に、全節の入力と処理段階、対象・hit・防壁・移動・準備・状態・リアクティブ・ラウンド境界の順序を列挙した。カタログ0.0節と競合する個別技能を、基礎hit数→自己位置→基礎対象→攻撃前→最終hit/対象→hit前防御崩し→効果量→hit中防御崩し→攻撃後の一方向の順序へ修正した。攻撃後の移動で位置・射程や元の倍率は再計算しない。PR #288と予測UIは未同期。

## 旧v3の判断（2026-09-07、検討履歴）

以下は武器ツリー案より前の比較材料であり、現在の技能構造を指示しない。

| 論点 | 現在の方針 |
|---|---|
| 表示分類 | アクティブ／リアクティブ／パッシブ。「常設」は新しい表示名として使わない |
| パッシブの横取り | 悪とは見なさない。初回2SPの一律課金は未採用へ戻す |
| 深い育成 | 同じ倍率を買い続けるだけにしない。節目で用途や連携の仕方が変わる案を比較 |
| 新しい挙動 | 既存engineの語彙に制限しない。面白さを先に判断し、必要な拡張を後から特定 |
| 後半の強さ | 強くて意外なコンボ、通常の攻略法を塗り替えるパックを歓迎する |
| 終点への到達 | 初周で全終点が取れる必要はない。序盤の核は早く、深い終点は後の進行で到達してよい |
| SP | 通常2/ボス3の24SP案に固定しない。通常1/ボス2の13SP＋永続投資を含め比較 |
| 戦闘外効果 | 戦後回復・装備処理・戦利品・活動資金等も技能の対象に含める |
| 保持する根本 | 自動戦闘で操作が成立すること、結果を説明できること、決定論、有限に終了すること、精算を二重処理しないこと |

### 面白さの軸

最初は「敵を崩して味方が仕留める」「守った分を攻めへ回す」「弱体が別の役目を持つ」といった短い接続を発見する。後半は「次のラウンドを捨てて今動く」「状態異常を別の敵へ移す」「壊れる装備を燃料にする」「戦闘力を削って戦利品を増やす」など、準備する編成そのものを変える。

共有イベントでつながることは手段であり、面白さそのものではない。全技能が同じ出口へ流れるなら、接続が多くても戦い方は同じになる。各テーマの対象・時間・位置・資源の使い方を違わせる。

### 強いコンボとシステム破綻を分ける

- **許容・歓迎する:** 上手く仕込めば敵の初動前に勝つ、長い溜めを飛ばす、毒が敵全体へ広がる、防御を大火力へ変える、通常より多い報酬を得る。
- **成立条件を設計する:** 何を準備し何を諦めるか、どの敵や報酬で向き不向きが変わるか、初動が崩れたらどう立て直すか。
- **通常の挙動にしない:** AP往復だけで無限実行、敵を残すだけで報酬を無限生成、ロードによる二重精算、予測と本番の不一致。

一律のchain上限でコンボの長さを短くするのではなく、消費・借金・一戦内の在庫など、プレイヤーに分かる有限性を先に置く。防止のために有用なイベントを黙って捨てない。

### パッシブを取る面白さ

選択肢を「1SPで薄く広く」「何度も同じ技能へ振る」の二択に固定しない。

1. 新しい接続を増やす: 例、防壁が壊れることを攻撃の仕込みに変える。
2. 今の接続の用途を変える: 例、単体に溜める効果を、上位の節で他の敵へ渡せるようにする。
3. 今回の装備・敵へ合わせる: 高guard相手なら一撃に集め、多数相手なら分散させる。

浅広がよい遠征も、深狭がよい遠征もあってよい。無条件の万能加算だけを並べることと、浅い投資そのものを混同しない。全パッシブへ罰則を付ける必要もない。得られる利益と、そのSPで他に取れた技能を比べられるようにする。

### 新しい分類の境界

分類は技能の表示・自動実行方法を表す。習得ツリーはテーマ別に混在させる。

- アクティブ: 自分の行動枠を使う。条件と優先順位に従い、手番で実行する。
- リアクティブ: 戦闘中の出来事へ割り込む/反応する。反応の優先順位と利用可能な資源に従う。
- パッシブ: 自分の行動枠や反応の実行候補を増やさず、能力・計算規則・装備の扱い・精算条件などを変える。

実装がイベントを購読していることだけで、すべてをリアクティブとは呼ばない。戦後の回復量や報酬条件を変えるパッシブも成立する。反対に、無料で追加攻撃する技能を、RPを払わないという理由だけでパッシブへ隠さない。発動を管理する必要があるならリアクティブとして明示する。
