# スキル群再設計案（fun-first draft）

この文書は実装仕様ではなく、**「このスキル群なら何度も遊びたくなるか」**を決めるための設計案である。数値、schema、表示レイアウト、正確なイベント名は後で決める。先に、プレイヤーが戦闘結果を見て「その組み合わせは考えていなかった」「次は逆の使い方を試したい」と思える構造を固定する。

対象は、現行の ecology/content の技能・pack・技能ツリーを一度白紙に戻したものとする。現行の active / reactive / passive の分離はランタイム上の都合として残してもよいが、**プレイヤーが見る技能ツリーは種別ではなく、同じテーマと共有イベントでつなぐ**。

---

## 1. 先に決める体験

### 1.1 戦闘の中心

このゲームでは、戦闘中にプレイヤーが毎手入力するのではなく、編成・前後列・取得技能・装備を決めた結果を観察する。したがって、技能の面白さは「押したときの派手さ」だけでは足りない。

一つの技能は次の三段を持つ。

1. その技能だけでも成立する最低限の価値
2. 誰かが起こした共有イベントを読んだときの変換
3. 変換された結果を、別の技能がさらに読める出口

例えば「敵が準備を始めた」→「その敵に印を付ける」→「印を消費して大打撃」は、特定の技能ID同士の専用コンボではない。敵の準備を発生させたのが敵技能でも、味方の観測技能でもよく、印を消費するのがゴウでもツグミでもよい。**誰がイベントを起こしたかを固定しない**ことが、編成を変えたときの再発見につながる。

### 1.2 自動戦闘で残す意思決定

自動戦闘でも、次の判断は毎回残る。

- どのテーマへSPを投じるか
- どの枝を先に伸ばすか
- 前衛と後衛をどう置くか
- APを増やす枝へ行くか、RPを反応に残すか
- 先に印・熱・構えを作るか、条件がなくても動ける技能を取るか
- 受けた出来事を攻撃、防御、回復、移動のどこへ渡すか

反応技能が勝手に発火すること自体を面白さにするため、発火条件は画面で読める共有イベントに限る。条件が成立しない行動技能は、何もせずに止まらず、通常行動へ戻る。

### 1.3 現行から取り除くもの

- 人物IDや特定の技能IDの組み合わせだけを要求する専用コンボ
- 「強い数値の通常攻撃」と「少し弱い数値の通常攻撃」を名前だけ変えた技能
- 条件が成立するまで永久に待つ技能
- 過剰回復を資源として貯める仕組み
- 自傷→回復→自傷で戦闘を引き延ばせる仕組み
- 入口から終点まで一本の長い鎖を進むだけのツリー
- active / reactive / passive の境界をまたぐと説明が読めなくなる前提関係

技能の条件は、敵の状態、隊列、準備、直前に起きたイベント、味方の資源に置く。人物IDは、自然な得意不得意を作るための数値とタグに使う。

## 2. 全体をつなぐ共有語彙

新しい資源を大量に足すと、コンボの発見ではなく用語の暗記になる。常時管理する新しいスタックは原則として**熱**だけにし、残りは既存の AP / RP、HP、防壁、受け構え、状態、イベント履歴で表す。

| 共有語彙 | 種類 | 意味 |
|---|---|---|
| 兆し | イベント | 敵が準備を始めた、準備が進んだ、行動を宣言した |
| 印 | 敵に付く状態 | 「この敵へ何かを返す」目印。1〜複数段。誰が付けてもよい |
| 熱 | 行動者に付く短期スタック | 攻撃と危険を増幅する。上限を低くし、ラウンドまたは戦闘で管理する |
| 構え | 防御状態 | 一撃を受け止める回数。多段への弱さを残す |
| 守勢 | 防御状態 | 一撃ごとの被害を軽くする。構え・防壁と役割を分ける |
| 余波 | イベントの値 | 直前のダメージ、防いだ量、実効回復、移動、撃破などの結果 |
| 拍 | 既存資源・順番 | AP、RP、準備の進み、味方全員→敵全員の順序 |
| 位置 | 盤面 | 前後列、行、列、移動、入れ替え。イベントとして他系統が読む |
| 集中・鈍り | 既存の短期状態 | 表示名を統一し、集中は次の仕事を強め、鈍りは敵の出力を弱める。新しい資源として数えない |

印と熱以外は、新しい常時資源として数えない。余波は保存して貯めるものではなく、その chain の中だけで読める値にする。回復系統の出口は「実際にHPを戻した」ことを読む。回復の余りを貯めたり、HPを支払ってから回復して総量を増やしたりしない。

技能が読むイベントは次の集合を基本とする。

- 戦闘開始、ラウンド開始、ラウンド終了
- 対象選択、行動宣言
- 準備開始、準備進行、準備完了
- ダメージ提案、ダメージを受けた、ダメージを防いだ
- 実効回復、状態が付いた、状態が消えた
- 移動、入れ替え、資源を得た
- 過剰ダメージが出た、敵または味方が倒れた

overheal のような回復の余りは、この共有イベントへ戻さない。これにより、回復役は「HPを増やす装置」ではなく、傷を受けた後の隊の形を変える役になる。

## 3. 技能ツリーの共通構造

### 3.1 系統のレベル

各系統は、取得した技能への投資点数を**系統Lv**として持つ。レベルは技能の強さを段階的に上げる値ではなく、次の枝を読めるようにする門である。

- Lv1: 入口。単独で使い道がある
- Lv2: 基本の変換。共有イベントを一つ読む
- Lv3: 分岐。攻撃、防御、支援、位置など別の出口を選ぶ
- Lv5: 到達点。二つ以上のイベントを横断し、ビルドの性格を決める

各節の取得は原則1SP。Lv5の到達点だけ2SPとしてもよい。Lv2、Lv3、Lv5の前提を明示し、単に上から順に埋めるだけにしない。

### 3.2 見た目とランタイム

画面上は、テーマごとに一つの森を表示する。森の中では active / reactive / passive を混ぜてよい。

例えば、

火種（行動） → 熱を読む（反応） → 熱移し（行動） → 熱暴走（反応） → 灰熱（常設）

という流れを一つの目的として見せる。

ランタイムへ落とすときは種別を別ファイルへ分けてもよいが、前提の意味はテーマ側で保持する。種別をまたぐ前提を禁止すると、攻撃した結果を反応技能が読む、受けた結果を攻撃技能が読む、といったこのゲームの面白さがツリーから消える。

### 3.3 条件の書き方

条件は、次の順で強くする。

1. 位置・敵状態・HP割合など、常に読める盤面条件
2. 直前の共有イベント
3. ラウンド内の履歴
4. 系統Lvや熱・印の段数

発動しないときの行動を塞がない。行動技能は通常攻撃・防壁・対象を変えた支援へフォールバックし、反応技能はRPを使わず何もしない。反応の連鎖は、1イベントあたり、1ラウンド、1 chain、1戦闘のいずれかで必ず上限を持つ。

## 4. 8系統

各系統は9技能、計72技能を基準にする。数を増やすこと自体が目的ではない。各系統に、入口、イベントの発生源、変換器、単独の出口、横断的な到達点を一つずつ持たせる。

表の種別は実装上の候補である。

- A = APを使う行動
- R = RPを使う反応
- P = 常設または戦闘中の受動効果

### 4.1 観測と予兆

問いは「敵が次に何をするかを見て、先に有利へ変える」。

| 門 | 技能名 | 種別 | 効果案 |
|---|---|---|---|
| Lv1 | 兆し拾い | R | 敵が準備を始める、または攻撃を宣言したとき、その敵へ印を1つ付ける。誰の観測でも発動する |
| Lv2 | 狙いを読む | A | 準備中または行動宣言済みの敵を優先して攻撃する。後列にも届く |
| Lv2 | 先回り | R | 敵の対象が決まった直後、狙われた味方へ構えを1つ置く。身代わりではなく、狙いそのものを読む |
| Lv3 | 逆算 | R | 敵の準備が進んだとき、RP1で進みを1段戻すか、その敵へ印を追加する。どちらを採るかは装備または優先順位で決める |
| Lv3 | 余白計測 | P | ラウンド終了時にAPまたはRPが余っていた場合、次のラウンド最初の条件付き技能を強化する。資源を増やすのではなく、余った拍を次の判断へ持ち越す |
| Lv3 | 見切り | R | 兆しを読んだ敵の攻撃が届く直前、その一撃の提案ダメージを固定値だけ下げる。大技への割合軽減ではない |
| Lv5 | 予兆返し | R | 準備中の敵の攻撃を防ぐ、または対象が移動して空振りしたとき、攻撃者へ印を付け、次の味方の攻撃へ集中を渡す |
| Lv5 | 先手の設計 | A | 戦闘1回、敵が最初に準備を完了した瞬間に、その敵を優先して攻撃する。印がある場合は印を消費せず、次の技能へ残す |
| Lv5 | 終端予測 | P | ある敵の準備開始・進行・完了を同じ戦闘で観測したとき、その完了イベントを「次の攻撃が防壁を無視する」余波へ変える。特定の攻撃技能を要求しない |

兆しは新しい状態ではなくイベントなので、敵の準備を使わない戦闘でも「狙いを読む」は普通の遠隔攻撃へ戻る。観測系統は、攻撃・受け・隊列・拍動のどの出口にもつながる。

### 4.2 刻印と露出

問いは「敵へ残した印を、誰が、いつ、何に変えるか」。

| 門 | 技能名 | 種別 | 効果案 |
|---|---|---|---|
| Lv1 | 墨付け | A | 敵へ中程度の攻撃を行い、印を1つ付ける。対象がいなければ通常攻撃へ戻る |
| Lv2 | 傷を拾う | R | どの味方でも敵へ印を付けた直後、自分に集中を1つ得る。ラウンド1回 |
| Lv2 | 重ね印 | A | 印のある敵へ攻撃し、印を1つ追加する。単発の威力は墨付けより低く、段数を育てる手段 |
| Lv3 | 印渡し | R | 印が付いた敵が移動、準備完了、または別の敵を倒したとき、まだ印のない敵へ印を1つ移す |
| Lv3 | 深掘り | A | 印を1つ消費して、防壁・受けを一部無視する一撃。印がないときは通常攻撃へ戻る |
| Lv3 | 連環 | P | ラウンド最初の印付与が、隣接する別の敵にも薄い印を付ける。敵が1体なら単独の印を厚くする |
| Lv5 | 反転印 | R | 印が消費または自然消滅したとき、消費した本人へ構えを1つ置く。印を攻撃だけに閉じない |
| Lv5 | 破印 | A | 印をすべて消費し、段数に応じて一撃の倍率と対象数を変える。1段なら単体、複数段なら周囲へ余波を出す |
| Lv5 | 灰の証 | P | 印を消費した結果、過剰ダメージまたは撃破が出たとき、最も弱った別の敵へ印を1つ付ける。破印を持っていなくても発動する |

印を付ける技能は観測、移動、熱、連鎖からも生まれる。印を消費する出口は破印だけにせず、防御・資源・別対象への移動を残すことで、印を早く割るか育てるかが毎回変わる。

### 4.3 点火と過熱

問いは「攻撃の前借りを、どこまで危険にするか」。

熱はこの系統の中心になる唯一の新規スタック候補である。上限は3程度にし、熱が高いほど強くなるが、敵に印を付けられる、守りが薄くなる、条件付き技能が不安定になるなど、明確な危険を置く。

| 門 | 技能名 | 種別 | 効果案 |
|---|---|---|---|
| Lv1 | 火種 | A | 小さな攻撃を行い、自分に熱を1つ得る。攻撃しながら次の判断を準備する |
| Lv2 | 熱を読む | R | 味方が印付き、準備中、または防壁のある敵へ実効ダメージを与えたとき、熱を1つ得る。ラウンド1回 |
| Lv2 | 燃焼 | A | 熱を1つ消費し、攻撃へ追加ヒットを1回加える。熱がなければ通常攻撃へ戻る |
| Lv3 | 熱移し | A | 自分の熱を1つ消費し、最も傷ついた味方へ構えまたは集中を置く。攻撃資源を隊の資源へ変える |
| Lv3 | 蓄熱 | P | 自分が被弾または防御に成功したあと、熱を1つ得る。ラウンド1回。受け系統からも火が入る |
| Lv3 | 熱暴走 | R | 熱が上限に達した状態で味方が攻撃したとき、追加ダメージを出す代わりに自分へ印を1つ付ける。HPを支払わない |
| Lv5 | 消火 | A | 熱をすべて消費し、消費数に応じた防壁を味方へ置く。熱を抱え続けるか、次の一撃を安全へ変えるかを選ぶ |
| Lv5 | 炉心 | P | 熱が2以上ある間、次の攻撃の対象選択が「最も傷ついた敵」から「印または準備のある敵」へ寄る。数値だけでなく行動方針が変わる |
| Lv5 | 灰熱 | A | 熱をすべて消費して攻撃する。熱3なら行または列へ余波が広がり、残った敵へ印を1つ付ける |

自傷ダメージは採用しない。熱暴走の代償は印、守勢の喪失、次の被ダメージ増加など、HPを使わない形から選ぶ。これなら回復系統との無限循環が起きない。

### 4.4 連鎖と余波

問いは「直前に起きた出来事を、次の誰の仕事にするか」。

連鎖という資源を貯めるのではなく、同じ chain 内の直近イベントと、その余波の値を読む。プレイヤーが管理する常時スタックを増やさず、戦闘ログには「防いだ→印」「回復した→構え」のように因果を表示する。

| 門 | 技能名 | 種別 | 効果案 |
|---|---|---|---|
| Lv1 | 余波拾い | R | ダメージ、防御、実効回復、移動、準備完了、撃破のいずれかが起きた直後、RP1で次の技能へ直前イベントの対象を渡す |
| Lv2 | 追い打ち | R | 敵がHP閾値を下回る、または倒れた直後、最も弱った別の敵へ小さな攻撃を行う。自分が起こしたイベントに限らない |
| Lv2 | 横流し | A | 直前の余波がダメージなら別対象へ小ダメージ、防御なら味方へ構え、回復なら対象へ集中、移動なら印を渡す |
| Lv3 | 跳ね火 | A | 直前に味方が攻撃または移動していれば、元の対象に隣接する敵へ追加攻撃する。対象が1体なら元の敵へ追加の印 |
| Lv3 | 連鎖路 | P | 自分が起こしたイベントだけでなく、味方全員のイベントを次の反応技能が読めるようにする。人物や技能の所有者を条件にしない |
| Lv3 | 巻き込み | A | 同じchainで2種類以上のイベントが起きていれば、次の攻撃を行または列へ広げる。単独では普通の攻撃へ戻る |
| Lv5 | 収束 | A | 同一ラウンドにダメージ、防御、回復、移動のうち2種類以上が起きたとき、それらの余波を一撃へ集める。威力は合計値ではなく上限付き |
| Lv5 | 連鎖断ち | R | 敵が味方を倒す、または同じ敵が連続して攻撃した直後、その敵の次の追撃を止め、最も傷ついた味方へ構えを置く。守りにも進める |
| Lv5 | 大波 | P | 一つのchainで3種類目のイベントが起きたとき、最後のイベントに応じて攻撃、防御、回復、移動のいずれかへ小さな出口を出す。特定の技能IDを要求しない |

横流しと大波は実装が重い可能性があるため、最初は「イベント種別ごとに一つの固定出口」として作り、後で余波の値まで渡す。設計上は、どの系統から来たイベントでも読むことが重要である。

### 4.5 隊列と間合い

問いは「位置を変えること自体を、攻撃・防御・準備へ変える」。

| 門 | 技能名 | 種別 | 効果案 |
|---|---|---|---|
| Lv1 | すり足 | A | 自分と味方または前後列を入れ替える。移動先に応じて届く攻撃と狙われ方が変わる |
| Lv2 | 入れ替え | A | 最も傷ついた味方と自分の位置を交換する。移動しただけでも防御面の価値がある |
| Lv2 | 引き寄せ | A | 敵の前後を入れ替え、後列の敵を前へ出す。敵が1体ならその敵へ印を付ける |
| Lv3 | 横槍 | R | 味方が移動した直後、最前の敵または印付きの敵へ小攻撃を行う。移動者を限定しない |
| Lv3 | 交差防御 | P | 入れ替えが起きたとき、移動した本人と入れ替わった味方に構えを1つずつ置く。ラウンド1回 |
| Lv3 | 挟撃 | A | 同じ敵の前後または左右に味方の攻撃対象が揃っているとき、行または列へ攻撃し印を追加する |
| Lv5 | 列崩し | R | 敵の位置が変わった直後、その敵へ守勢低下または印を付ける。引き寄せを持っていなくても反応する |
| Lv5 | 退路 | R | 前列の味方が被弾したあと、対象を後列へ移し、自分または移動先へ構えを置く。ラウンド1回 |
| Lv5 | 陣替え | P | 同一ラウンドに味方が2回移動したとき、次の攻撃が列をまたいで届き、次の準備または反応へ小さな拍を渡す |

移動系統の技能は、移動回数を無限に増やすのではなく、ラウンド内の回数制限を持つ。ヒバナのAP2はこの系統と自然に相性がよいが、ゴウが退路を覚えたり、ナギが引き寄せで敵の形を変えたりできる。

### 4.6 受けと反転

問いは「受けた被害を、誰を守るか、何を返すかへ変える」。

| 門 | 技能名 | 種別 | 効果案 |
|---|---|---|---|
| Lv1 | 構え直し | A | 自分へ構えを1つ置き、少量の防壁を得る。単独で戦線を作れる |
| Lv2 | 受圧 | R | 構えまたは防壁でダメージを防いだ直後、攻撃者へ印を付けるか、自分へ熱を1つ得る |
| Lv2 | 身を寄せる | R | 味方が攻撃対象に選ばれたとき、RP1で被害の一部を自分へ移し、対象へ守勢を置く。完全な身代わりではない |
| Lv3 | 受け流し | R | 実際にダメージを防いだあと、最も弱った敵へ小攻撃またはその敵への印を選ぶ。防いだ量に上限を置く |
| Lv3 | 盾返し | A | 直前に自分が防いだ一撃の余波を使い、攻撃者へ反撃する。防いでいなければ通常攻撃へ戻る |
| Lv3 | 壁の余熱 | P | 防壁が消える、または構えが消費されたとき、次に行う支援・点火・隊列技能のいずれかを強化する |
| Lv5 | 連袂 | R | 身を寄せる、構え、防壁のいずれかで味方を守った直後、別の最も傷ついた味方へ構えを渡す。受け手は固定しない |
| Lv5 | 不屈 | R | HP30%以下で被弾したとき、戦闘1回だけ大きな防壁と守勢を得る。発動後に待つだけでは回復しない |
| Lv5 | 砦返し | P | 一ラウンドに複数回ダメージを防いだあと、次の攻撃へ防いだ回数に応じた追加対象または印を与える。累積量を無限に保存しない |

受け系統の終点は、受け続ければ勝てる防御ではなく、攻撃・印・熱・支援へ返す出口にする。ナギの高い受けは多段を止める方向へ、ゴウの高いHPは単発を受けて反転する方向へ自然に分かれる。

### 4.7 分配と再生

問いは「傷、構え、熱、拍を、誰へ渡すと隊全体が続くか」。

回復は実際に減ったHPだけを対象とする。回復の余り、自己HPを支払った見かけの回復、戦闘を待つだけの回復量は、資源やSPへ変換しない。

| 門 | 技能名 | 種別 | 効果案 |
|---|---|---|---|
| Lv1 | 手当て | R | 味方が被弾した直後、RP1でその被弾量の一部を対象へ返す。同じ被弾を二重に治さない |
| Lv2 | 配る | A | 最も傷ついた味方へ少量の防壁と守勢を置く。HPを戻せないときも仕事がある |
| Lv2 | 傷の分担 | R | 味方へのダメージ提案時、RP1で一部を自分または別の受け役へ移す。移した側に守勢を置く |
| Lv3 | 痛みの預け | R | 味方へ付いた印、鈍り、熱のいずれかを1段だけ自分へ移す。移した結果で自分が危険になる |
| Lv3 | 実効治療 | P | 実際にHPを戻した直後、回復を受けた味方へ集中または構えを1つ置く。過剰回復を読まない |
| Lv3 | 再点火 | R | HP閾値以下の味方が回復によって戦闘継続できたとき、その味方へAPまたはRPを1渡す。戦闘1回またはラウンド1回 |
| Lv5 | 命綱 | R | 味方が倒れるダメージを受けた直後、戦闘1回だけHP1で踏みとどまらせ、守勢を置く。回復量を資源にしない |
| Lv5 | 分け火 | A | 自分の熱を1つ消費し、傷ついた味方へ防壁を置き、その味方の次の攻撃へ集中を渡す。点火との横断口 |
| Lv5 | 灰の配給 | P | 一ラウンドに複数の味方へ実効回復を行ったとき、次に起きる防御、移動、攻撃のいずれかを一段だけ強化する。回復量を蓄積しない |

この系統はツグミの高い技術と自然に噛み合うが、ゲンゾウがRPを使って反応回復を担ってもよい。命綱は強いので発動回数を戦闘1回に固定する。

### 4.8 拍動と準備

問いは「AP、RP、準備の進みを、いつ誰へ渡すか」。

| 門 | 技能名 | 種別 | 効果案 |
|---|---|---|---|
| Lv1 | 一拍置く | A | 1段の準備を行い、完了時の次の攻撃または支援を一段強くする。準備中は通常攻撃へ戻る |
| Lv2 | 合図 | A | 最も条件が成立しやすい味方、または準備中の味方へAPを1渡す。対象の人物IDを固定しない |
| Lv2 | 割込み | R | 敵が行動を宣言した直後、RP1でダメージを下げるか、その行動を1段遅らせる。戦闘を止め続けない |
| Lv3 | 後押し | R | 味方の準備が進んだ、または完了した直後、RP1でその準備をさらに1段進めるか、次の対象へ集中を渡す |
| Lv3 | 遅延 | R | 敵の準備が進んだ直後、その敵へ鈍りを置き、完了を1段遅らせる。大技への答え |
| Lv3 | 交換手 | A | 自分のAP1をRP1へ、またはRP2をAP1へ変換する。ラウンド1回。資源総量は増えない |
| Lv5 | 追い越し | P | 味方全員が一度動いたあと、未使用APがある場合、次のラウンドの最初に条件付き技能を優先する。手数の無限増加ではなく順番を変える |
| Lv5 | 連奏 | R | 同じラウンドに異なる2種類の共有イベントが起きたとき、次の行動を準備完了扱いにするか、反応技能のRPコストを1だけ軽くする |
| Lv5 | 拍子木 | P | 同じchainで3種類のイベントが起きたとき、隊の最後に動いた人物へAPまたは最も傷ついた味方へ構えを1つ渡す。特定の技能IDを要求しない |

APを増やす技能には、ラウンド・chain・戦闘の上限を必ず付ける。拍動は「APが多いほど勝つ」系統ではなく、準備・反応・隊列の順序を組み替える系統にする。

## 5. 5人との関係

技能の所有者を固定せず、人物の数値と初期役割だけで自然な得意分野を作る。加入した人物がそのpackを独占しないという現行方針は維持する。

| 人物 | 現在の役割 | 自然な入口 | 逆張りの面白さ |
|---|---|---|---|
| ゴウ（warden） | HP・腕力が高い前衛。細かい被害に弱い | 点火、受け、刻印。熱を抱えて単発を反転する | 分配で自分の熱や傷を味方へ渡す。観測で敵の大技を読む |
| ツグミ（mender） | 技術が高い後衛。主火力と支援を兼ねる | 観測、刻印、分配。後列から印と実効回復を回す | 受けで防いだ余波を攻撃へ変える。隊列で前へ出て印を作る |
| ナギ（lancer） | 受けが高い前衛。多段を止める | 受け、観測、拍動。防いだ結果で次の対象を決める | 点火で防御を熱へ変え、列崩しで敵の形を崩す |
| ヒバナ（guardian） | AP2。位置を変えながら二度動く | 隊列、連鎖、点火。移動を攻撃の起点にする | 分配で二手を防御へ振り、拍動で味方の準備を前倒しする |
| ゲンゾウ（tactician） | RP4。自分から動くより割り込む | 拍動、観測、分配。兆しを読み、RPを出口へ渡す | 刻印や点火で反応の余波を攻撃へ変え、前衛として受ける |

例えばゴウが点火を持つことは自然だが、点火の「熱を読む」は誰でも取れる。ナギが防いだイベントで熱を得てもよいし、ツグミが印付きの敵へ攻撃して熱を得てもよい。技能の説明文にも「ゴウなら」「ツグミなら」と書かず、イベントの発生者・対象・隊列だけを書く。

## 6. Stage 0で先に成立させるもの

Stage 0はゴウとツグミの2人で、12戦を通して少なくとも3種類のビルドが成立する必要がある。最初から72技能を全部見せるのではなく、4系統の入口と前半を使えるようにする。

### 6.1 Stage 0の公開範囲

- 刻印、点火、受け、分配をスターター系統にする
- 各スターター系統は、入口からLv3までの5〜6節をStage 0で使える
- 観測、隊列、連鎖、拍動は根だけを表示するか、Stage 1以降のシルエットとして予告する
- Stage 0でも、4系統の技能は人物を限定せず両名が取得できる
- Stage 0の敵配置は、単体、前後列、防壁、多段、準備のうち最低3種類を出し、技能条件が実際に起きる

### 6.2 SP案

通常戦闘の勝利で2SP、ボスで3SPを渡す。12戦に通常戦闘とボスが含まれる場合、遠征内でおおむね25SP前後になる。

- 入口とLv2の取得を1SP
- Lv3の分岐を1SP
- Lv5の到達点を2SP
- 各戦闘後にすぐ取得できる
- SPは遠征ごとにリセットする
- 全系統を完成させるためではなく、2系統を深くするか、3〜4系統を浅く混ぜるための量にする

開始時に根を一つ無償で配る、または最初の戦闘後だけ追加1SPを渡す案は、Stage 0の最初から選択肢を見せるために検討する。通常2SP・ボス3SPという基本値は、紙上のコンボ確認後に変える。

### 6.3 Stage 0の3ビルド例

#### 火種を印へつなぐ「燃える傷」

- ゴウ: 火種 → 熱を読む → 燃焼 → 熱暴走
- ツグミ: 墨付け → 傷を拾う → 深掘り
- 盤面: ゴウが前列で熱を作り、ツグミが後列から印を付ける
- 予想外の結果: ツグミが付けた印でも、ゴウの熱暴走後に印が増え、ゴウの次の深掘りが大技になる
- 弱点: ゴウが印を抱えたまま被弾すると、熱暴走の代償が先に効く

これは「攻撃役と支援役の固定コンボ」ではない。2人のどちらが墨付けを取っても成立し、前後列を変えると熱を作る者と印を作る者が入れ替わる。

#### 防いで返す「受け火」

- ゴウ: 構え直し → 受圧 → 盾返し
- ツグミ: 手当て → 実効治療 → 配る
- 盤面: ゴウが単発大技を受け、ツグミが実際の被弾を戻して守勢を足す
- 予想外の結果: 受圧が敵へ印を付けたため、盾返しの対象選択が変わり、ツグミの次の墨付けが不要になる
- 弱点: 多段敵には構えが早く剥がれ、火力が伸びない

受けのイベントが攻撃・印・熱のどれへ出るかで、同じ前衛でも結果が変わる。ナギ加入後は防いだ回数が増え、受け火が「印を撒く」形へ再解釈される。

#### 傷を渡して二人で続ける「灰の手当て」

- ゴウ: 火種 → 熱移し → 構え直し → 身を寄せる
- ツグミ: 手当て → 配る → 実効治療
- 盤面: ゴウがツグミへの被害の一部を引き受け、ツグミは実効回復で次の拍を作る
- 予想外の結果: ゴウが熱移しで熱を味方へ渡すことで、ツグミの次の攻撃が集中付きになり、攻撃を急ぐルートへ移れる
- 弱点: 回復を待つだけでは資源が増えず、被弾イベントがなければ反応も起きない

回復が単なるHPの巻き戻しにならない。受け、熱、印、次の攻撃のどこへ渡すかで、守りのビルドが攻めへ変わる。

この3つに加えて、刻印と受けを浅く取る「印を育てて割る」型も成立させる。Stage 0でプレイヤーが「攻撃、反撃、支援」の三つを試せることを最初の面白さの合格条件とする。

## 7. Stage 1〜3での増やし方と再解釈

現行の人数加入順（2→3→4→5）を維持し、毎Stageで技能の語彙を増やす。新系統はそのStageで入口〜Lv2のcoreを解禁し、次Stage以降にLv3・Lv5を広げる。

| Stage | 加わる系統 | そのStageの問い | 過去の技能の再解釈 |
|---|---|---|---|
| Stage 0 | 刻印・点火・受け・分配 | 2人で、傷と攻撃を何へ渡すか | 印、熱、防御、実効回復を覚える |
| Stage 1 | 観測・隊列 | 敵の兆しと位置を読めるか | 準備中の敵へ印、移動後に熱、受けた位置を攻撃へ変える |
| Stage 2 | 連鎖 | 直前の出来事を別の役割へ渡せるか | 回復→構え、防御→印、移動→追撃、撃破→次の対象 |
| Stage 3 | 拍動 | AP/RP/準備を、どの順番へ振り替えるか | 2人で作った印・熱・受けを、5人の順番と反応で連鎖させる |

Stage 1ではナギが入るが、ナギ専用の受けpackは作らない。ナギの高い受けが受圧を多く起こし、観測の兆し拾いが敵へ印を付け、ゴウの灰熱が列へ広がる、というように、人物の数値が同じ技能の発生頻度を変える。

Stage 2ではヒバナの移動が横槍と余波拾いの起点になる。位置替え自体が得にならない場面では移動を控え、敵の前後を変えた結果を印・連鎖・受けへ回す場面で使う。

Stage 3ではゲンゾウのRP4が割込み、手当て、傷を拾う、横流しのどこへでも使える。RPが多い人物だから強いのではなく、同じイベントに複数の出口を用意し、どの出口を取得したかで役割が変わる。

### 7.1 後半の横断コンボ例

#### 兆し→受け→印→熱→列

1. 敵が準備を始める
2. 観測の兆し拾いで敵に印
3. 受けの先回りで狙われた味方に構え
4. 構えが一撃を止め、受圧で熱を得る
5. 熱3の灰熱が印付きの敵を列ごと攻撃
6. 刻印の灰の証が過剰ダメージを別の敵へ渡す

この流れは、ゴウが作ってもナギが作ってもよい。防御から攻撃への変換が、人物IDではなくイベントでつながる。

#### 移動→連鎖→実効回復→拍

1. ヒバナが前後を入れ替える
2. 隊列の横槍が敵へ小攻撃
3. 敵の反撃でツグミが手当て
4. 実効治療がツグミまたは対象へ集中
5. 連鎖の横流しが回復イベントを構えへ変換
6. 拍動の連奏が次の準備を完了扱いにする

回復から準備へ行く道は、回復技能IDと準備技能IDを直接結び付けない。実効回復という共有イベントを読むため、別の回復手段でも成立する。

#### 防御→資源交換→敵の準備遅延→止め

1. ゲンゾウが敵の攻撃宣言を割込みで遅らせる
2. ナギが防いで受圧
3. ゲンゾウがRPを残すか、交換手でAPへ変える
4. 敵の準備進行に遅延
5. 刻印の破印または点火の燃焼で止める
6. 敵が倒れれば連鎖の追い打ちが別の敵へ出る

敵が単発大技か、多段攻撃かで、割込み・受け・熱の価値が変わる。決定論のまま、敵の構成と前後列が毎回問いを変える。

## 8. 「思いもかけないコンボ」を維持する規則

### 8.1 すべての到達点に複数の発生源を置く

一つの到達点へ、最低2種類の共有イベントから到達できるようにする。

| 到達点 | 発生源の例 | 出口 |
|---|---|---|
| 印 | 敵の準備、移動、受け止め、通常攻撃 | 防壁無視、熱、追撃、対象移動 |
| 熱 | 攻撃、防御、印付きへの命中、被弾 | 追加ヒット、列攻撃、防壁 |
| 構え | 戦闘開始、回復、防いだ、移動 | 大技受け、次の反撃、列維持 |
| 追加の拍 | 撃破、実効回復、準備完了、防御 | 次の準備、割込み、別の味方の行動 |
| 追撃 | 過剰ダメージ、移動、撃破、印の消費 | 弱った敵、隣接敵、元の対象 |

### 8.2 出口を一つに固定しない

例えば印の消費は、常に破印の大ダメージになる必要はない。

- 印を消費して防御へ回す
- 印を移して次の敵へ回す
- 印を熱へ変える
- 印を消費した結果の余波を追撃へ回す

同じ盤面でも、取得技能と人物の配置で印の価値が変わる。

### 8.3 具体的な相手を名前で要求しない

技能の条件文は次のように書く。

- 「最も傷ついた敵」
- 「準備中の敵」
- 「印のない敵」
- 「最前の味方」
- 「直前のイベントの対象」
- 「このラウンドにまだ動いていない味方」

次のようには書かない。

- 「ゴウが墨付けした敵」
- 「技能Xの後に技能Y」
- 「pack_edgeを持つ人物」
- 「敵ID boss_03にだけ有効」

これにより、編成を変えても同じ木が違う役割を持つ。

### 8.4 決定論を隠さない

同じseed、同じ編成、同じ技能なら同じ結果になる。驚きは乱数からではなく、イベントが複数の系統へ渡ることから作る。

戦闘ログは、単なる数値列ではなく因果を一行で見せる。

- 「ナギが攻撃を防いだ → 敵に印」
- 「ツグミが実効回復した → ヒバナの次の準備が進む」
- 「ヒバナが移動した → 最前の敵へ横槍」
- 「ゴウが熱を3つ抱えた → 列攻撃、代わりに印1」
- 「印が消えた → 最も弱った敵へ余波」

プレイヤーがログを見て、技能の発火理由を追えることを面白さの条件にする。

## 9. 実装へ近づける順番

### Phase A — 紙上の面白さを確認

- 8系統72技能のカードを作る
- 1技能につき「単独の価値」「読むイベント」「出す出口」を一行で書く
- Stage 0の3ビルドを、単体・多段・準備敵の3種類で紙上再生する
- 連鎖が一つの専用レシピへ閉じていないか確認する
- 回復が過剰回復や自傷循環へ戻っていないか確認する

### Phase B — イベント語彙を固定

- 既存engineで使えるイベントと、追加が必要なイベントを一覧にする
- まずは印、熱、兆し、余波を最小語彙として試す
- 新しいイベントを追加する場合も、既存の「対象」「発生源」「イベント値」を再利用する
- 状態の表示名を、効果の役割が伝わる短い日本語へ統一する

### Phase C — Stage 0だけ実装

- 4スターター系統の入口〜Lv3を実装する
- 通常2SP、ボス3SPで12戦を回す
- 3ビルドが、2人のどちらに割り当てても成立するか確認する
- 自動選択の優先順位とフォールバックを確認する
- battle trace で「なぜ発火したか」を確認する

### Phase D — Stage 1〜3へ拡張

- 新系統はcoreだけを追加し、旧系統のfullを後で開ける
- 各Stageの敵の問いを、追加したイベントが実際に発生する構成にする
- 5人が揃った後も、特定人物専用の技能がなくて役割が分かれるか確認する
- 連鎖の長さ、反応回数、AP/RPの上限を実測して調整する

数値調整はPhase C以降に行う。先に倍率を決めて、面白くない構造を強くすることはしない。

## 10. Fun gate

実装を続ける前に、次の質問へ「はい」と答えられることを合格条件にする。

- Stage 0の2人で、攻撃、反撃、支援の3ビルドを作れるか
- 同じ技能をゴウとツグミへ移しても、数値と位置によって別の結果が出るか
- 一つのイベントに、最低2系統の反応先があるか
- 新しい技能を取ったとき、既存技能の使い道が一つ増えるか
- 12戦の途中で、次のSPを使う前に「この条件を起こしたい」と思えるか
- 敵が単体、多段、準備、後列、防壁のどれかを変えたとき、同じビルドに別の答えが出るか
- 反応が連鎖しても、プレイヤーがログから因果を追えるか
- 回復を待つだけ、自傷と回復を繰り返すだけ、APを無限に増やすだけの戦法が成立しないか
- 特定の技能IDを一つ抜くと、全体が壊れる固定レシピになっていないか

このゲートを通らない技能は、名前や数値を調整する前に、イベントの発生源か出口を作り直す。

## 付記：現行内容からの主な変更点

- packを「技能の箱」ではなく「共有イベントを読むテーマ」として再設計する
- active / reactive / passive をプレイヤー向けのツリーで統合する
- 現行の長い単線的な森を、各系統9節の入口・分岐・到達点へ組み直す
- Stage 0で4系統の前半を使えるようにし、2人でも3ビルドを成立させる
- Stage 1〜3で観測、隊列、連鎖、拍動を追加し、既存技能を再解釈する
- 通常戦闘2SP、ボス3SPを基準に、1遠征内で浅く広くか深く狭くかを選ばせる
- 回復の余り、自傷のHP支払い、特定IDペアをコンボの前提にしない
