# 人間テスト公開条件

更新日: 2026-08-31（UTC）

作者へ現行版の URL を渡す前に、未確認の経路を残さないための条件です。自動検査は面白さを判定しません。

## 1. 実装と契約

- ecology/ の変更が、対応する schema、content、UI、保存形式のどこに影響するか確認する。
- node ecology/check.mjs が成功する。
- bash analysis/check-all.sh が成功する。
- 変更した表示や保存 payload に、旧入口・旧版の表示が残っていない。

## 2. ブラウザ経路

公開先 E2E で、少なくとも次を確認する。

- ecology/ が開く。
- Campaign Stage を既定の入口として選べる。
- 8人から5人を選び、隊列、行動、反応、常設、装備を設定できる。
- 次の敵の狙いと戦闘条件を開始前に読める。
- 自動戦闘が決着し、リプレイとイベントログを確認できる。
- 戦闘中の再読み込みから復旧できる。
- 終了アンケートと D1 送信の成功・失敗を区別できる。

## 3. 版の確認

- 画面に EXP-18 R8 Campaign、content contract、build 印が出る。
- 公開先の core/build.mjs が、確認した build 印と一致する。
- 古い service worker や旧入口へ誘導されない。

## 4. 作者評価

作者は 1〜2 遠征だけ遊び、次を自由記述で残す。

- 選択が何を変えたか。
- 次に試したい変更が浮かんだか。
- もう一度開きたいか。
- 分からなかった語彙、過剰な判断、退屈した区間。

自動ゲートの PASS は作者評価の代わりになりません。

## 5. 公開後

- build 印、URL、検査結果、未確認事項を PR または作業記録へ残す。
- D1 に保存した場合は、必要に応じて read-only export で payload を確認する。
