# 人間テスト公開条件

更新日：2026-08-29

すべての実験で、作者へプレイURLを渡す前に満たす共通条件。個別実験票がより厳しい場合は個別条件を優先する。

## 原則

- 作者はE2Eテスターではない。未確認経路を作者のプレイで確認しない。
- 自動ゲートは面白さを判定せず、実験したい因果機構が盤面に存在することと、壊れた版を落とすことだけを確認する。
- 「コードがある」「単体テストが通る」「最初の画面が開く」は、公開可能の証拠ではない。
- 未確認項目が1件でもあればURLを渡さず停止し、未確認として報告する。

## 1. 要求トレーサビリティ

実験票の要求を1行ずつ表にし、各行に次を付ける。

| 要求 | 状態 | 証拠 |
|---|---|---|
| 実験票の原文または要求ID | PASS / FAIL / 未確認 | テスト名、出力、画面経路、ログ項目、コミット |

禁止：

- 複数要求を「概ね対応」でまとめる
- 未確認をPASSにする
- 作者のプレイで未確認を補う
- 実験票にない閾値変更を「調整」として黙って行う

## 2. 既存プレイテストUIの踏襲

独立試作でも次を標準装備する。

- 画面上で、選択可能な全要素の名前と効果を選択前に読める
- 操作不能な選択肢は理由が分かる
- 感情マーカーに任意メモを付けられる
- 終了アンケートに既定値を入れない
- 版、seed、build stampを画面または保存ログで確認できる
- 途中リロードから復旧できる
- ブラウザ標準のprompt/confirmへ主要操作を依存させない
- iPhone相当390×844で主要操作が画面外へ隠れない

既存機能を意図的に外す場合、実験票に理由と観測への影響を書く。

## 3. 本番E2E

公開先で、最長の正常経路を最初から最後まで1回通す。

必須：

1. 初期表示
2. 全主要操作
3. すべての中間画面
4. 分岐選択
5. 中盤でリロード
6. 勝利または敗北の終端
7. 終了アンケート送信
8. D1保存
9. export取得
10. 保存された版、seed、主要イベント、自由記述の照合

D1 exportの実行・取得手順は [docs/EXPORT.md](./EXPORT.md) を参照する。初回のSecret設定と、workflow起動が連携に現れない場合の安全な代替手順は [docs/D1_LOG_ACCESS.md](./D1_LOG_ACCESS.md) にまとめている。`echo_to_log=true` は自由記述を公開ジョブログへ出すため、必要な場合だけ使う。

複数分岐が実験の主題なら、主題に関係する両側を通す。

ブラウザ、認証、公開先接続などが使えない場合は停止する。作者へ代行を頼まない。

## 4. ログ完全性

仮説と失敗信号を判定できる粒度で、生イベントを人間テスト前に保存確認する。

最低限：

- 選択前状態
- 選択した行動
- 選択後状態
- ランダム提示内容
- 版、seed、時刻
- 感情マーカー種別と任意メモ
- アンケート数値と自由記述

結果票には、個人情報・端末IDを除き、作者の原文、正確な主要行動列、実験票からの逸脱を残す。要約だけへ置き換えない。

## 5. 公開判定

次のすべてがPASSのときだけ公開可能。

- 個別の自動ゲート
- 要求トレーサビリティ
- 既存UI踏襲
- 本番E2E
- リロード復旧
- D1保存とexport照合
- 全検査コマンドの終了コード0
- ルール版とbuild stamp更新

公開時に作者へ伝えるのは、URL、確認すべき版表示、最大プレイ量だけ。成功条件は教えない。

## 6. Luna試用とTerra置換

CONTROL 0.2をLunaの実行品質試用1回とする。ゲームが面白くないこと自体はLunaの失敗ではない。

次のいずれかがあれば、以降の実装担当をLunaからTerraへ置き換える。レビュー役を追加せず、常にSol＋実装担当の二者構成とする。

- 必須検査を未実施のまま作者へURLを渡す
- 実験票から無断で仕様・閾値を変える
- 上記の標準UI・ログ要件を落とす
- 結果票から作者の原文または主要行動が欠落する
- ゲートの合格主張と保存された証拠が矛盾する
- 作者が公開後に、公開条件の不足を2件以上発見する

接続障害などにより正しく停止し、未確認と報告した場合は失敗に数えない。
